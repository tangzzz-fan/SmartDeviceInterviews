# 评审意见 · 模拟面试第一轮

> 评审角色：面试官/陪练教练视角。对照 [03_规范答案.md](../03_规范答案.md) 与 [04_STAR表达法.md](../04_STAR表达法.md) 检查 [候选人_模拟作答_round1.md](./候选人_模拟作答_round1.md)。

## 总体评价

第一轮作答整体达到「资深候选人」水平：结构清晰、有实战细节、有量化数字、知道边界。主要短板是**个别知识点深度不够**和**细节真实性待替换**（【】占位 + 估算值）。

## 每题亮点与问题

### 1. 状态同步（良）
* 亮点：设备端缓冲 + App 端确认 + 对账去重，逻辑闭环。
* 问题：缺「确认报文的具体字段」细节（如 ack seq 放在哪个 characteristic）；面试官追问「设备缓冲满了怎么办」需要答案。

### 2. 断连恢复（良）
* 亮点：watchdog 假死检测 + 恢复现场 checklist，实战感强。
* 问题：退避参数缺少「为什么是这个值」的解释；没提状态恢复（restoreIdentifier）和「App 被杀后谁负责重连」。

### 3. OTA（优）
* 亮点：中断恢复是一等公民、双 bank 回滚、电量保护，覆盖完整。
* 问题：没提「协议版本协商」（新固件可能改协议导致兼容问题）；「99.x%」必须换成真实数字。

### 4. 联调排障（优）
* 亮点：四步分层隔离 + 真实 buffer 溢出案例，有证据意识。
* 问题：可以补一句「如果协议本身有缺陷，怎么推动双方改协议」。

### 5. 同步架构（优）
* 亮点：先落盘再上传、三路补偿、实时/批量分离，主架构完整。
* 问题：幂等键具体是什么（如 client_msg_id）；冲突规则说得太概括，追问会露怯。

### 6. 重连状态机（良）
* 亮点：纯逻辑状态机可单测 + 真实重连风暴教训。
* 问题：没有给出状态迁移表/图（面试官很可能让现场画）；可补充「syncing 超时回到 backoff 的处理」。

### 7. AI-native（良）
* 亮点：三个案例具体，且有「判断力兜底」的价值观表达。
* 问题：数字是估算，必须换成真实数据；可加一个「AI 建议出错被我发现」的反例，更可信。

### 8. 英文自我介绍（良）
* 亮点：结构完整（经历→技术→工程体系→AI→动机），时长合适。
* 问题：缺「为什么是我」的差异化钩子；可以加一句你对 AI 可穿戴方向的具体理解，让面试官记住你。

## 薄弱点 Top 5（D2-D5 重点补）

1. **协议细节**：确认报文字段、幂等键、缓冲溢出处理——面试官深挖点。
2. **状态恢复**：restoreIdentifier、App 被杀后的重连责任归属。
3. **OTA 兼容**：协议版本协商与固件兼容策略。
4. **真实数字**：所有「估算」与「xx」必须在真实经历里补上，否则追问即穿帮。
5. **现场画图**：状态机、同步链路、OTA 时序三张图要能徒手画。
