# JD 深度拆解与考点地图

## 一句话判断

这份 JD 的核心不是“会写 iOS App”，而是“能把 AI 可穿戴产品的 iOS 端从 0 到 1 扛起来，并和硬件、固件、后端、AI 团队一起把设备真正交付出去”。

## 显性要求

### 1. iOS 客户端核心架构

面试官会看：

- 你是否主导过模块设计
- 你是否理解版本规划与演进
- 你是否能在业务增长时保持代码可维护性

高频考点：

- 模块划分
- 状态管理
- 依赖治理
- 发布流程
- 崩溃与日志监控

### 2. BLE 通信

面试官会看：

- 你是否真正做过设备配对和连接管理
- 你是否理解连接生命周期，而不是只会 API 调用
- 你是否知道 BLE 在真实环境中的脏场景

高频考点：

- 扫描与过滤
- 建连与重连
- characteristic 订阅与写入
- 状态同步
- 数据包拆分与重组
- 超时与异常恢复

### 3. performance 与 infrastructure

面试官会看：

- 你是否能把“可运行”做成“可交付”
- 你是否关注稳定性、功耗、后台运行、同步一致性

高频考点：

- 启动优化
- 内存与卡顿
- 功耗治理
- 后台执行边界
- 本地缓存与数据同步
- 埋点、日志、监控

### 4. 软硬件联调

面试官会看：

- 你会不会甩锅
- 你能否定义接口与协议
- 出现问题时你如何切分责任与验证链路

高频考点：

- 协议定义
- 抓日志与复现
- 数据校验
- 联调分阶段策略
- 问题归因方法

### 5. 工程体系建设

面试官会看：

- 你是否只会写功能
- 你能否建立团队可复用的工程基础设施

高频考点：

- 自动化测试
- CI/CD
- 代码规范
- 发布流程
- 质量门禁

## 隐性要求

### 1. Founding 心态

隐含含义：

- 没有人把路铺好给你
- 需求、协议、流程都可能不完整
- 你要能补空白，而不是等待指令

面试中会体现为：

- 你如何做优先级判断
- 你如何在信息不全时推进
- 你是否能承担模糊性

### 2. 面向真实硬件产品，而不是纯软件

隐含含义：

- 真机环境复杂
- 问题经常不可稳定复现
- 设备、固件、App、服务端都可能出错

面试中会体现为：

- 你是否有系统思维
- 你是否能讲清楚链路，而不是孤立看 App

### 3. 跨时区协作

隐含含义：

- 需要高质量英文同步
- 需要写清楚问题、证据、假设、下一步

面试中会体现为：

- 英文表达是否清楚
- 你是否会结构化沟通

### 4. AI-native

隐含含义：

- 不只是“会用 ChatGPT”
- 而是把 AI 融入编码、调试、测试、文档和团队协作

面试中会体现为：

- 你有没有稳定工作流
- 你是否能说出 AI 提效的边界与风险

## 红线项

以下项如果回答空泛，风险很高：

1. `Core Bluetooth / BLE` 没做过却硬说做过
2. 只讲 UI 和业务逻辑，讲不出工程基础设施
3. 没有任何联调经验，但无法迁移说明
4. 只会背概念，讲不出真实故障案例
5. 英文协作表达非常弱，无法做基本技术同步

## 加分项背后的真实价值

### OTA

说明你参与过设备完整生命周期，而不是停留在普通数据同步层。

### 低功耗优化

说明你理解可穿戴设备的核心约束，不只关注功能。

### 离线同步

说明你知道设备类产品的使用场景并不总是在线、稳定、实时。

### C/C++ / 嵌入式 / 量产流程

说明你能更好地和硬件 / 固件团队建立共同语言。

## 面试官最可能追问的 10 个主题

1. 你做过最复杂的 iOS 模块是什么，为什么复杂？
2. 你做过哪些 BLE 连接或数据传输场景？
3. 连接失败、断连、超时、状态不一致时怎么处理？
4. 你如何和固件工程师一起定位问题？
5. 你做过哪些性能优化，如何量化结果？
6. 你如何设计日志、监控、报警和发布流程？
7. 你如何保证后台同步和数据一致性？
8. 你如何设计 OTA 的安全性和可靠性？
9. 你如何用 AI 提高开发和调试效率？
10. 为什么你适合 founding 阶段，而不是成熟大厂的分工模式？

## 准备重点排序

### 第一优先级

- BLE 全流程表达
- 联调方法论
- iOS 基础深水区
- 工程体系建设

### 第二优先级

- 性能 / 功耗 / 后台 / 同步
- OTA
- 英文协作

### 第三优先级

- 量产流程
- 传感器 / 音频 / 健康设备拓展知识

## 面试准备原则

不要把自己准备成“会背 iOS 面试题的人”，而要准备成“能把一个设备型产品交付出来的人”。
