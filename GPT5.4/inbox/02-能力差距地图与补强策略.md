# 能力差距地图与补强策略

## 使用说明

这份文档默认按以下画像制定：

- 你已有 iOS 基础
- 你能写 Swift / 使用常见 iOS SDK
- 真正需要强化的是 BLE、OTA、软硬件联调、founding ownership 和英文技术沟通

如果你的真实背景与以上不同，后续只需要调整优先级，不需要推翻这张图。

## 维度 1: iOS 基础功底

### 面试目标

做到“不是背题”，而是能解释机制与取舍。

### 面试官期待

- 理解 Swift 并发
- 理解 ARC / 内存管理
- 理解生命周期与后台任务边界
- 理解网络、存储、线程切换

### 常见短板

- 会写，但无法讲清原理
- 只会单点知识，不会结合实际场景

### 补强动作

1. 每个主题准备 1 个机制解释。
2. 每个主题准备 1 个真实案例。
3. 每个主题准备 1 个常见坑。

## 维度 2: BLE / Core Bluetooth

### 面试目标

能完整画出以下链路：

`扫描 -> 发现设备 -> 连接 -> 发现服务与特征 -> 订阅/写入 -> 状态同步 -> 异常恢复 -> 断开与重连`

### 面试官期待

- 不只是会 API
- 还知道 BLE 是弱连接、不稳定、受环境影响的

### 常见短板

- 只能讲 happy path
- 讲不出状态机
- 讲不出超时、断连、重复消息怎么处理

### 补强动作

1. 口述 3 次 BLE 全流程。
2. 单独准备 5 个异常场景：
   - 扫描不到设备
   - 已发现但连不上
   - 已连接但服务发现失败
   - 数据写入成功但设备状态没更新
   - 后台恢复后状态不一致
3. 每个异常都按 `现象 -> 假设 -> 证据 -> 修复 -> 回归验证` 结构表达。

## 维度 3: 软硬件联调

### 面试目标

能让面试官相信你不是“碰到硬件问题就等别人处理”的人。

### 面试官期待

- 你会定义边界
- 你会拉通证据
- 你知道怎么做分层定位

### 常见短板

- 只有感性描述，没有方法论
- 无法区分 App、BLE、协议、固件、服务端的问题

### 补强动作

1. 准备一个联调排障模板：
   - 现象
   - 复现条件
   - App 日志
   - BLE 抓包 / 协议日志
   - 固件反馈
   - 结论与下一步
2. 准备一段“如何和固件工程师对齐问题”的表达。
3. 准备一个跨团队推进案例。

## 维度 4: OTA

### 面试目标

即使没有完整做过，也能讲清核心链路和关键风险。

### 面试官期待

- 你知道 OTA 不是简单文件下载
- 你知道版本校验、断点恢复、失败回滚、安全性的重要性

### 常见短板

- 只知道升级，不知道失败策略

### 补强动作

1. 准备 OTA 最小流程图。
2. 准备 3 个风险点：
   - 升级中断
   - 版本不兼容
   - 升级后功能异常
3. 准备一段“没有亲手做过时如何诚实迁移表达”的话术。

## 维度 5: 性能 / 稳定性 / 后台 / 同步

### 面试目标

从“我做过优化”升级到“我知道怎么建立指标和治理闭环”。

### 面试官期待

- 有指标意识
- 有观测能力
- 有针对设备场景的稳定性思维

### 常见短板

- 只讲优化动作，不讲指标变化
- 只讲前台，不讲后台和同步一致性

### 补强动作

1. 为每个主题准备一个指标：
   - 启动时间
   - 崩溃率
   - 内存峰值
   - 电量消耗
   - 同步成功率
2. 为每个主题准备一段治理闭环：
   - 如何发现
   - 如何定位
   - 如何修复
   - 如何验证

## 维度 6: 工程体系

### 面试目标

让面试官看到你能建秩序，而不只是接需求。

### 面试官期待

- 模块化意识
- 自动化测试意识
- CI/CD 和发布意识
- 质量门禁意识

### 常见短板

- 讲不出为什么做这些建设
- 讲不出 trade-off

### 补强动作

1. 准备一个“如果我是 founding iOS engineer，我会先建什么”的清单。
2. 准备一个“早期不做什么”的清单，体现取舍能力。

## 维度 7: AI-native

### 面试目标

把 AI 从“工具使用”讲成“研发工作流增强”。

### 面试官期待

- 你会把 AI 融入编码、调试、测试、文档和协作
- 你知道哪些地方不能盲信 AI

### 常见短板

- 只会说“我用 ChatGPT 查资料”

### 补强动作

1. 准备 4 个真实工作流：
   - 用 AI 快速生成调试假设
   - 用 AI 起草测试用例
   - 用 AI 整理联调日志和问题单
   - 用 AI 辅助技术文档与英文同步
2. 准备一段“AI 的收益与边界”表达。

## 维度 8: 英文沟通

### 面试目标

达到“能清楚协作”而不是“像母语者一样华丽”。

### 面试官期待

- 能做英文自我介绍
- 能讲清技术方案
- 能同步风险和 blocker

### 常见短板

- 技术中文会讲，英文一紧张就碎掉

### 补强动作

1. 固定 3 段英文素材：
   - 自我介绍
   - 项目介绍
   - 风险同步
2. 每段练到 90 秒内说顺。

## 冲刺优先级矩阵

### 必须补到可面试

- BLE / Core Bluetooth
- 联调方法论
- iOS 基础深水区
- 工程体系与质量

### 尽量补到可加分

- OTA
- 功耗 / 同步 / 稳定性
- AI-native 工作流

### 有时间再扩展

- 量产流程
- C/C++
- 传感器 / 音频领域知识

## 最终目标

你不是要把所有短板都补成专家，而是要把所有关键点补到：

- 不会被一问就穿
- 能说出方法
- 能说出案例
- 能诚实说明边界
- 能让面试官相信你能快速补齐剩余部分
