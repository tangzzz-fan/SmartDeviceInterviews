# 模拟面试脚本与执行清单

状态：inbox 草稿，暂不落库。

## 目标

按真实轮次把材料跑穿。一次只答一题。空话被追问到机制、案例、指标为止。

## 双 Agent 对练

材料：

- 面试官：`Composer2/interviewer-agent.md`
- 候选人：`Composer2/senior-candidate-agent.md`
- 题库与故事：本目录 `03` `04` `05` `07` `08`

协议：

1. 对面试官说：按 Round N 开始，一次一问。
2. 你自己答，或让资深候选人按人设答。
3. 面试官只给评价 + 一个杀伤力追问。
4. 候选人用追问再答一版。
5. 你随时打断，把 `[人设案例]` 换成真实项目。

不要让两个 Agent 在同一条消息里互喷完整长文。保持一次一问。

## 模拟轮次设计

### Round 1：电话筛 / HR 初筛

1. 用 60 到 90 秒介绍自己，重点放最接近这份 JD 的经历。
2. 为什么对 Founding iOS Engineer 感兴趣？
3. 你能不能和硅谷团队日常英文协作？给一个例子。
4. 你没做过的加分项是什么？怎么补？

通过线：匹配度清楚、不装、有一个旗舰故事的标题。

### Round 2：技术一面

从下面抽 6 题，必须含 BLE：

1. Swift Concurrency 和 GCD 的关系。
2. ARC 下最常见的内存问题。
3. App 从后台恢复后设备状态不一致怎么办。
4. BLE 连接的完整流程。
5. 扫描不到设备怎么排。
6. 断连后如何恢复，如何保证幂等。
7. 启动优化怎么做，指标是什么。

通过线：能画状态机，能讲 Ready 不等于 `didConnect`。

### Round 3：深挖 / 系统设计 / 联调

1. 画 BLE 连接与恢复状态机。
2. 设计 OTA，重点讲 commit 点和失败路径。
3. 软硬件联调如何归因。
4. 如果你是 founding iOS engineer，先建什么。
5. 离线同步或低功耗，二选一深挖。

通过线：有白板、有失败路径、有观测点。

### Round 3b：加分项渗透（材料 `08`）

至少抽 4 题，覆盖两条 JD 加分：

1. 低功耗你真正关心哪些旋钮？SLA 和连接参数怎么换。
2. OTA 提交点在哪？掉电后什么还能启动。
3. 设备离线时如何不丢、上线后如何不乱序。
4. 传感器或音频数据面怎么设计，带宽怎么算。
5. 客户端和固件协议如何定义，为什么不要直接套 C struct。
6. EVT / DVT / PVT / 试产 / 量产，iOS 分别冻什么。

通过线：能画白板 5–8，能说清 iOS 边界 vs 固件边界，不会的项有缺口话术。

### Round 4：行为面 / Founder Mindset + English

中文：

1. 讲一个你主动推动而不是被安排的事情。
2. 讲一个跨团队分歧。
3. 讲一个信息不完整时的判断。

英文（抽 2 题）：

1. Please introduce yourself briefly.
2. Tell me about a challenging technical problem.
3. How do you work with cross-functional teams?
4. How do you use AI in your work?

通过线：有取舍、有证据、英文结构完整。

## 反问面试官的问题

1. iOS 客户端现在最大的交付风险是设备连接、OTA，还是工程节奏？
2. 协议的 owner 是谁？变更如何冻结？
3. 深圳固件和硅谷产品的日常重叠时间怎么安排？
4. founding 阶段对崩溃率、连接成功率、续航 SLA 有没有明确门槛？
5. 当前硬件处于 EVT / DVT / PVT 哪一段，客户端被要求冻什么？
6. 这个角色三个月后成功的样子是什么？

不要问能在 JD 上读到的问题。不要先问薪资和远程政策（放到流程后段）。
