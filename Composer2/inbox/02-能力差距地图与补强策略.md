# 能力差距地图与补强策略

状态：inbox 草稿，暂不落库。

## 使用说明

本文件有两层：

1. **人设默认画像**：资深候选人 Agent 答题时使用，标为 `[人设]`。
2. **你的自测表**：用 `[ ]` 勾选。Day 1 先填一遍，Day 7 再填一遍。

人设案例和指标都可以替换。没做过的项，用文末「诚实缺口话术」，不要硬装。

## 人设默认画像

`[人设]` 8 年+ iOS，近 3 年智能穿戴 / IoT。独立扛过 App 架构、Core Bluetooth、OTA、性能与发布。和深圳固件、海外产品做过联调与英文同步。AI 用于编码、日志归纳、测试用例和文档，关键判断自己验证。

默认强项：iOS 基础、BLE 生产级连接管理、联调归因、工程基建、英文技术同步。

默认边界：没有完整带过从 EVT 到量产的全流程；音频采集 / 健康数据不是主战场；C/C++ 能读协议和 JNI / 模块边界，不是固件开发者。

## 自测表

每个维度给自己打：`能连续讲` / `能讲骨架` / `只能背概念` / `没做过`。

### 维度 1：iOS 基础功底

面试目标：并发、内存、生命周期、后台、网络、存储能讲到机制，而不是 API 名字。

- [ ] Swift Concurrency 与 GCD 的关系、MainActor、取消
- [ ] 共享可变状态如何隔离（actor / 串行队列 / 单一状态机）
- [ ] ARC 所有权、闭包捕获、长生命周期订阅
- [ ] 后台恢复后不信任旧内存状态
- [ ] 存储：文件、数据库、Keychain 的职责边界

补强：对着 `03` 模块 1–3 每题练 60 秒结论 + 一条追问。

### 维度 2：BLE / Core Bluetooth

面试目标：能画出连接状态机，能讲脏场景。

- [ ] 扫描过滤、建连、服务发现、订阅、写入
- [ ] 断连分类与受控重连
- [ ] 命令队列、ack、幂等、reconciliation
- [ ] 前后台 / 蓝牙开关 / 系统抢占
- [ ] 大数据分包与流量控制

补强：把白板 1 画 10 遍，直到不看稿。

### 维度 3：软硬件联调

面试目标：分层可验证，不甩锅。

- [ ] 能按 App -> BLE -> 协议 -> 固件 -> 云 拆观测点
- [ ] 能对齐时间戳、设备版本、App 版本、复现路径
- [ ] 能写出一页问题单：现象 / 假设 / 证据 / 下一步
- [ ] 能讲一次「看起来是 App，实际是固件」或反过来的案例

补强：用 `04` 故事 3 练 5 分钟联调复盘。

### 维度 4：OTA

面试目标：把 OTA 当高风险链路，不是文件传输。

- [ ] 前置条件、包校验、分片、进度、重启、版本确认
- [ ] 中断、校验失败、升级后连不上、回滚或可恢复
- [ ] 安全：签名、型号匹配、防降级
- [ ] 可观测：每个阶段有日志和状态

补强：白板 2 + `03` Q11 + `08` B 节。没做过完整 OTA 时，用缺口话术 1。

### 维度 5：性能 / 稳定性 / 后台 / 同步

面试目标：指标驱动，不靠「感觉变快了」。

- [ ] 冷启动 / 首屏可交互如何拆
- [ ] 崩溃率、卡顿、连接成功率、同步成功率
- [ ] 低功耗：扫描窗口、连接间隔、通知频率
- [ ] 离线队列与冲突合并

补强：给每个指标准备「定义、采集、告警、治理专题」。功耗、离线同步、传感器数据面见 `08` A/C/D。

### 维度 6：工程体系

面试目标：founding 阶段先建秩序，不为了完整而完整。

- [ ] 模块边界和状态所有权
- [ ] 日志、符号表、崩溃聚合
- [ ] 关键链路测试，而不是追求覆盖率数字
- [ ] CI/CD 与发布门禁
- [ ] 版本规划：每周能出可测包

补强：`03` Q16，准备 90 秒 founding 基建优先级。

### 维度 7：AI-native

面试目标：有稳定工作流，也有不交给模型的红线。

- [ ] 方案比较、样板代码、测试用例、异常清单
- [ ] 用 AI 整理日志和假设，而不是让它定根因
- [ ] 文档和英文同步草稿
- [ ] 能说出一次 AI 给错过、自己拦下来的例子

补强：准备 1 个「加速了什么」+ 1 个「拒绝外包什么」。

### 维度 8：英文沟通

面试目标：结构化，不追求华丽。

- [ ] 90 秒英文自我介绍
- [ ] 3 分钟英文项目讲述
- [ ] 一封跨时区风险同步
- [ ] 会议里能打断并确认：problem / evidence / next step

补强：朗读 `05`，录音后删掉所有空话。

### 维度 9：加分项（功耗 / OTA / 同步 / 传感器 / 量产）

面试目标：能被追问到机制，不停留在名词。专篇 `08`。

- [ ] 功耗 SLA 与连接档
- [ ] OTA commit 与防砖
- [ ] 离线 seq / requestId
- [ ] 传感器带宽或音频链路边界
- [ ] 协议端序 / 版本 / 不直接套 C struct
- [ ] EVT 到量产翻译成 App 工作

补强：白板 5–8 各画一遍，`08` 每节一题含追问。

## 冲刺优先级矩阵

必须补到可面试：BLE 全流程、联调归因、iOS 深水区、工程基建、一个旗舰故事。

尽量补到可加分：`08` 的功耗、OTA commit、离线同步、英文风险同步。

有时间再扩展：`08` 的量产阶段语言、音频 / 传感器、C/C++ 协议细节。

## 诚实缺口话术

原则：先承认边界，再给可迁移证据，再给入职后 30 天怎么补。不编造项目。

### 1. 没做过完整设备 OTA

「我没有从 0 独立交付过完整量产 OTA。我做过的是固件包校验、分片传输和失败重试这一段，以及升级后重新握手、对版本。入职后我会先把失败路径和可观测性做成清单，和固件一起把中断、回滚、防砖策略冻住。」

### 2. 没参加过 EVT / DVT / PVT

「我没有以客户端 owner 身份完整走过 EVT 到量产。我参与过试产缺陷回流：协议字段不兼容、广播名变更、连接参数在不同固件下行为不一致。这些让我理解硬件阶段的核心是冻结接口和可回归的验证集，而不是继续堆功能。」

### 3. 没有音频 / 健康传感器主经验

「音频采集和健康数据不是我的主战场。可迁移的是：传感器数据的分包、时钟对齐、丢失重传，以及后台保活和功耗之间的取舍。如果这个产品音频链路是核心，我会先补编解码边界和系统音频会话冲突。」

### 4. 没有消费电子量产交付

「我没有带过百万级出货。接近的经验是小批量真机联调和灰度发布：按固件版本分流、看连接成功率和崩溃率、有问题能停。Founding 阶段我优先保证可观测和可回滚，而不是先谈规模。」

### 5. C/C++ / 嵌入式不深

「我不是固件工程师。我能读协议文档、看 hex、和固件对齐字节序与 ack 语义，必要时读他们关键状态机代码。边界我会说清楚：App 侧保证传输、重试、兼容；固件侧保证设备状态和硬件时序。」

## 最终目标

Day 7 结束时，P0 全部是「能连续讲」，P1 至少一半是「能讲骨架」，P2 有诚实话术，没有一项是「硬装做过」。
