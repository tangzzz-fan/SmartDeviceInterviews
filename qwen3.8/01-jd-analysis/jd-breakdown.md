# JD 拆解：Nirva Founding iOS Engineer

## 一、岗位定位解读

**这不是一个普通的高级 iOS 岗位，而是三个角色的叠加：**

1. **架构师**：从 0 到 1 定义客户端核心架构，没有历史包袱也没有现成方案可抄。
2. **软硬结合工程师**：BLE 通信 + OTA + 联调是日常，不是锦上添花而是核心交付。
3. **基建负责人**：CI/CD、监控、测试、发布流程全部要自己搭，工程体系建设是职责而非加分项。

**隐含信号：**
- "Founding" = 前 6-12 个月可能只有你一个人写 iOS，独立决策能力 > 团队协作话术。
- 三地协作（深圳硬件/嵌入式 + 硅谷软件产品 + 国内你）= 沟通效率和文档能力被放大。
- "AI 可穿戴产品从研发、测试到正式交付" = 面试会问完整生命周期，尤其是量产阶段的问题。
- "高度 AI-native" 单独列为要求 = 这家公司自己就在用 AI 重构研发流程，会深挖你的真实用法而非泛泛而谈。

## 五、必须主动展示的证据点

面试中不等被问，主动埋入以下内容：

1. **一个完整交付故事**：从需求到上线到线上运维，体现端到端 ownership。
2. **一个疑难 bug 定位故事**：最好是跨层问题（App ↔ 系统 ↔ 硬件/网络），体现定位方法论。
3. **一个从 0 搭建的东西**：模块、组件库、CI 流程、监控，任何"我建的"而非"我用的"。
4. **一个数据结果**：启动提速 X%、崩溃率降至 Y、连接成功率 Z%——数字是资深感的最短路径。
5. **对 Nirva 产品的思考**：提前研究 AI 可穿戴赛道，面试结尾提出 1-2 个有质量的产品/技术问题。

## 六、出题风格预判（startup + AI-native 公司）

- **少问八股，多问"你实际怎么做的"**：每个理论题都准备好落到自己的项目案例。
- **系统设计题概率极高**：BLE OTA、数据同步架构、App 整体架构三选至少一。
- **追问深**：答"用 GCD"会被追到"为什么不用 async/await、优先级怎么定、怎么避免优先级反转"。
- **文化面直接**：会问"为什么选 startup"、"你最快的一次交付"、"和硬件团队吵架怎么办"。
