# T2-01 教练密卷：模型资产与转换（仅教练分支/归档，学员禁阅）

> 本文件含弱/中/强三级提示、评分要点与参考答案。使用纪律：直接要答案 → 反问「训练分布和部署分布一样吗」。

## 一、概念题：提示梯与评分要点

### C1 模型资产流水线
- 弱提示：数据、训练、验证、打包、版本、回滚——缺哪环会在什么时候炸？
- 中提示：灰度/回滚需要什么前提（版本可溯源、标签表可回退）？
- 强提示：至少 6 节点：数据→训练/转换→端侧验证→打包→灰度→回滚；每节点要有产物与验收。
- 评分要点：真懂特征：节点 + 产物 + 验收三者齐；只有「训练→集成」两步 = 不过。
- 参考答案：数据（版本化）→ 训练/转换（指标）→ 端侧验证（真机/设备分布）→ 打包（.mlmodelc + 标签表）→ 灰度（按用户）→ 回滚（可逆 + 监控）。

### C2 Create ML 适合什么、不适合什么？
- 弱提示：Create ML 是「产品化训练器」——适合什么任务模板？研究级场景缺什么？
- 中提示：表格/图像分类/声纹这类固定任务 vs 自定义 loss/架构/数据管线，哪个适合？
- 强提示：适合：固定任务模板、快速原型、无自定义训练循环需求；不适合：研究级任意架构、频繁改 loss、深度定制数据增强。
- 评分要点：真懂特征：正反例各一 + 判断轴（模板 vs 自由度）。
- 参考答案：适合表格/图像/声纹等模板任务；不适合自定义网络与训练循环。

### C3 为什么「Python 里 acc=99%」不能直接写进发布说明？
- 弱提示：训练分布与设备分布差在哪？转换有损吗？度量环境一致吗？
- 中提示：三个不等：训练集 ≠ 真实设备数据；PyTorch 前向 ≠ CoreML 前向；实验室指标 ≠ 线上指标。
- 强提示：训练 acc 是「分布内 + 原框架 + 实验室」；发布需「设备分布 + CoreML 端侧回归 + 线上监控」。
- 评分要点：真懂特征：三个不等都能说；死记硬背典型：「Python 99% 说明模型好。」
- 参考答案：必须端侧回归（真实设备/数据）后才能引用；训练数字只能当筛选器。

### C4 量化前后盯哪三个指标？
- 弱提示：体积、延迟、任务指标——哪个是「必须盯」的底线？
- 中提示：延迟要分 compute unit 看；任务指标要分分布看。
- 强提示：三指标 = 体积（包）、延迟（分 compute unit、真机）、任务指标（Top1/F1 在验证集与设备样本上）。任一下降超阈值 → 放弃该量化档。
- 评分要点：真懂特征：三个指标 + 各自测量方式；只盯体积 = 半过。
- 参考答案：体积、真机延迟（分 unit）、任务指标（双分布）；三者都要量化对比。

### C5 标签表放哪？
- 弱提示：标签顺序是谁定的？模型输出 index 与标签表错位会怎样？
- 中提示：标签表在模型里、在代码里、在远端——各有什么版本同步问题？
- 强提示：与模型同包或哈希强校验；错位 = 静默错类（acc 看起来高但全错位）。远端标签表必须带版本协商。
- 评分要点：真懂特征：错位后果 + 版本同步方案。
- 参考答案：同包或强校验；远端标签表要版本 + 兼容策略。

### C6 拒绝 CoreML 的记账模板
- 弱提示：复用 T1 五维账 + 撤出条件；「继续走云」也要记账。
- 中提示：拒绝的理由要可验证（成本/迭代速度/团队能力），不是「麻烦」。
- 强提示：模板：问题/约束/候选（端 vs 云）/代价/撤出条件；结论可推翻。
- 评分要点：真懂特征：模板完整 + 撤出条件；「端侧太麻烦」= 不过。
- 参考答案：用统一记账模板，拒绝与引入同等严肃。

## 二、争议焦点参考立场

- D1 设备端训练：只适合个性化/隐私强需求；通用训练仍是云端/离线管线。
- D2 量化档位：先 fp16 再 int8，客户端有验收一票；掉点超阈值即否决。
- D3 热更新：差分下载值得的前提是模型大且更新频繁；小模型直接整包更简单。

## 三、代码题：评分要点与提示

### Q1 Create ML 表格分类器
- 评分要点：合成数据训练跑通；训练/验证指标打印。
- 参考答案要点：MLCreateML 表格分类器 API；`model.trainingMetrics`。

### Q2 导出与体积
- 评分要点：导出到临时目录成功；打印字节数与格式。
- 参考答案要点：`model.write(to:)` 后 `FileManager.attributesOfItem` 取 size。

### Q3 量化账本 CLI
- 评分要点：输入原体积/量化后/掉点；输出值得/不值得的阈值逻辑。
- 参考答案要点：`if drop > 0.02 or size_gain < 0.3: 不值得`。

### Q4 版本三元组
- 评分要点：打印「模型语义版本 + 预处理版本 + App 最低版本」并说明谁改谁换。
- 参考答案要点：三元组任一变化 → 触发端侧回归；预处理版本变化尤其危险。

## 四、使用纪律
- 判分只认证据：训练/验证指标、导出体积、账本阈值；「感觉更小」不算。
- 失真自查：不跑 Create ML 就说通了、量化只看体积 = 该题作废重跑。
