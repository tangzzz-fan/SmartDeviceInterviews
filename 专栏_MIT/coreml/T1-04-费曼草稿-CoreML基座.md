# T1-04 费曼草稿：CoreML 基座（示例）

> **示例文件**：本文件演示「脱稿重推 + 端侧 vs 云对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 模型 = 固化计算图 + 数据契约**：不是「智能对象」，是约定好输入输出形状的可执行图。一次 `prediction` 成功的底线是特征名、类型、形状对齐。
- **M2 特征类型决定集成方式**：Image 走 Vision 省事；MultiArray 自己管预处理。选错类型，后面全是补丁。
- **M3 源文件 ≠ 运行时产物**：`.mlmodel` 是源；设备上跑的是编译后的 `.mlmodelc`（或自动编译缓存）。
- **M4 端侧与云是产品决策**：延迟、隐私、成本、可更新性、硬件覆盖——五维账，不是技术炫技。
- **M5 失败是一等公民**：缺模型、形状不匹配、类型不对、计算单元不可用——都要可诊断，不能 silent fail。

## 二、端侧 vs 云对照

| 维度 | 端侧 CoreML | 云 API |
|------|------------|--------|
| 延迟 | 本地稳定，无网络抖动 | 依赖 RTT，弱网崩体验 |
| 隐私 | 数据不出设备 | 上传即暴露面 |
| 成本 | 按次边际≈0，体积占包 | 按调用计费 |
| 可更新性 | 跟版或自管热更 | 服务端随时换模 |
| 硬件覆盖 | 低端机/无 ANE 要降级 | 服务端算力统一 |

## 三、一个例子讲到底

相册分类：先问「必须离线吗」。必须 → 端侧；标签每天变 → 云或热更。业务层只认 `ClassificationResult` DTO，生成的 `XxxInput` 停在 Adapter 内侧——模型换版不炸 UI。

## 四、60 秒讲稿

「CoreML 不是把云模型塞进手机。它是一份数据契约加上一张可执行计算图：输入叫什么、什么类型、什么形状，输出怎么读，缺一项就失败。源文件是 `.mlmodel`，跑的是编译产物。端侧还是云，别问谁更潮，问延迟、隐私、成本、更新、硬件五本账。失败要可诊断——缺文件、形状错、算力不可用，都得看得见。学基座学的是契约与边界，不是背一个 `prediction` 调用。」

## 五、自检三问

1. 被问「`.mlmodel` 和 `.mlmodelc` 差在哪」能脱稿答——没被问倒。
2. 能讲给同事听：用了相册分类的五维账例子。
3. 诚实自查：C1 契约三件套是复攻后才稳的，属于「背过→推通」。
