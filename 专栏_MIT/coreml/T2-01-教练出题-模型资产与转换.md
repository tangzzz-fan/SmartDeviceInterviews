# T2 教练出题集：模型资产与转换

> 预期漏洞：以为 Create ML 万能；忽视量化掉点；分不清训练环境与部署环境。

## 一、共识五模型

| # | 模型 | 一句话骨架 |
|---|------|-----------|
| M1 | 资产流水线 | 数据→训练/转换→验证→打包→版本→回滚，缺一环就不是工程 |
| M2 | Create ML 是「产品化训练器」 | 适合表格/图像/声纹等固定任务；不是研究级任意架构乐园 |
| M3 | 转换有损 | PyTorch/TF → CoreML 可能改算子、改精度；必须端侧回归 |
| M4 | 量化是产品账 | 体积/延迟 vs 精度；没有「免费变快」 |
| M5 | 版本与 App 绑定 | 模型版本、标签表、预处理代码必须同版本发布或可协商 |

## 二、争议三焦点

**D1 该不该让 App 内置训练（Create ML on device）？**  
**D2 量化默认开到几 bit？谁有一票否决权（算法 vs 客户端）？**  
**D3 模型热更新是否值得做差分下载？**
