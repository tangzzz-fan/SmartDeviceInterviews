# T3-04 费曼草稿：Vision 与媒体管线（示例）

> **示例文件**：本文件演示「脱稿重推 + 端侧 vs 云对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 Vision 是编排层**：请求队列、裁剪、方向、缩放；CoreML 是其中一种 handler，不是「Vision = CoreML」。
- **M2 预处理即模型的一部分**：训练时做什么，推理就必须对齐，否则准头静默崩。
- **M3 方向是一等公民**：EXIF / `UIImage.orientation` 搞错 = 类别全错，通常不 crash。
- **M4 内建 vs 自定义**：系统模型省体积、省维护；自定义换控制权与领域标签。
- **M5 异步与生命周期**：VNRequest 完成回调不作主线程假设；UI 更新必须显式回主队列。

## 二、端侧 vs 云对照（媒体管线）

| 场景 | 更偏端侧 | 更偏云 | 备注 |
|------|---------|--------|------|
| 相册实时预览分类 | ✓ 稳定延迟 | | Vision 内建可先试 |
| 证件 OCR 高准 | 可端侧 | ✓ 复杂版式常上云 | 隐私要单独记账 |
| 批量归档打标 | 可夜间端侧 | ✓ 吞吐优先时 | 批 vs 单张产品取舍 |
| 训练对齐难的定制域 | 自定义 CoreML | 或云微调 | 预处理清单强制 |

## 三、一个例子讲到底

扫证件：先问隐私是否允许上传。不允许 → 端侧自定义或内建；允许且版式极复杂 → 云。无论哪条，orientation 与裁剪清单必须与训练一致；回调里 `DispatchQueue.main.async` 更新 UI——这不是细节，是崩溃与错标的分界。

## 四、60 秒讲稿

「Vision 管编排，CoreML 管推理。图像进模型之前，尺寸、归一化、色彩、裁剪、方向——全是模型的一部分，不是『可选项』。方向错了往往不崩，只是标签全错，最难查。系统内建模型省事，自定义换控制权。完成回调别假设在主线程。端侧还是云，先问隐私和延迟，再问准头谁家更稳。」

## 五、自检三问

1. 被问「orientation 错了会怎样」能答（静默准头崩，不是 crash）。
2. 能讲给同事听：扫证件三选一账（端侧/云/内建）。
3. 诚实自查：C1 分工是复攻后才分清的——以前总混着说。
