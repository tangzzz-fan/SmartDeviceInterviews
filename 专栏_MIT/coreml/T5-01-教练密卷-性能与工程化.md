# T5-01 教练密卷：性能与工程化（仅教练分支/归档，学员禁阅）

## 一、概念题：提示梯与评分要点

### C1 三种 computeUnits 适用场景
- 弱提示：`.cpuOnly` / `.cpuAndGPU` / `.all` 各自把推理放到哪？
- 中提示：CPU 内存友好但慢；GPU 快但拷贝开销；ANE 最快但受机型/算子支持限制。
- 强提示：默认 `.all`（ANE 优先，自动回退）；`.cpuOnly` 用于小模型/稳定内存/调试；`.cpuAndGPU` 用于 ANE 不支持或要控制功耗。选择要按真实机型度量。
- 评分要点：真懂特征：三种场景 + 回退机制；死记硬背典型：「.all 就是最快的。」
- 参考答案：.all 默认（ANE 优先回退 GPU/CPU）；cpuOnly 求稳求调试；cpuAndGPU 控功耗/兼容。数字为准。

### C2 最小可信延迟度量协议
- 弱提示：一次计时能信吗？编译/暖机污染怎么排除？
- 中提示：协议要素：环境（机型/OS/computeUnit/温度）、暖机 N 次、正式 M 次、统计口径。
- 强提示：协议 = 固定环境 + 暖机（排除首次编译）+ 正式 M 次（去首尾/取 min/median）+ 报告环境字段；结果必须可复现。
- 评分要点：真懂特征：环境/暖机/口径三要素；只有 `Date()` 掐表 = 半过。
- 参考答案：环境标注 + 暖机 + M 次统计（min/median）+ 可复现。

### C3 模拟器数字怎么用、怎么禁用
- 弱提示：模拟器有什么、没有什么（ANE/GPU 真机语义）？
- 中提示：模拟器数字能用来做什么（逻辑正确性/回归对比）？
- 强提示：模拟器可做功能回归与相对对比；绝对延迟/功耗/ANE 结论禁用；报告里必须标注环境。
- 评分要点：真懂特征：能用范围 + 禁用范围 + 标注义务。
- 参考答案：功能/相对对比可用；绝对性能禁用；报告强制标注环境。

### C4 后台推理的产品/系统限制
- 弱提示：iOS 后台执行的窗口是什么？长任务要用什么（BGTaskScheduler）？
- 中提示：后台跑推理会撞上什么（内存限制、被挂起、用户感知耗电）？
- 强提示：系统限制：后台窗口有限、内存受限、可能被杀；产品限制：耗电/隐私/用户预期。结论：能后台 ≠ 该后台。
- 评分要点：真懂特征：系统限制 + 产品判断两层。
- 参考答案：BGTaskScheduler 申请窗口；产品上评估必要性；默认前台。

### C5 内存峰值怎么测
- 弱提示：用什么工具/API 读内存（footprint）？峰值在哪个阶段出现（加载/预热/推理）？
- 中提示：`task_vm_info` / Instruments Allocations；多模型并发时峰值叠加。
- 强提示：测量：加载后/预热后/推理中分段采样；峰值关注点：多模型常驻、输入图像缓冲、输出大张量。
- 评分要点：真懂特征：分段测量 + 峰值归因。
- 参考答案：分段采样（加载/预热/推理）+ 归因（模型常驻/输入/输出）。

### C6 隐私威胁模型三段
- 弱提示：资产是什么（模型/输入数据/输出）？威胁是什么（泄露/篡改/滥用）？
- 中提示：缓解手段：端侧不传、沙盒、权限、审计日志。
- 强提示：三段：资产（输入数据/模型/中间结果）→ 威胁（截获/越权/日志泄露）→ 缓解（不出设备/最小权限/加密/审计）。
- 评分要点：真懂特征：三段完整 + 落到具体功能。
- 参考答案：资产→威胁→缓解，每个功能至少一条缓解措施。

## 二、争议焦点参考立场

- D1 `.all` 默认：是，但要按机型度量；ANE 不可用自动回退不 panic。
- D2 低端机小模型：值得的前提是用户分布里有明显低端段 + 质量可接受；否则一模型。
- D3 减体积 vs 减延迟：先看瓶颈（体积影响下载/启动，延迟影响体验）；量化账本决定。

- 参考答案要点：结构化打印模板。
