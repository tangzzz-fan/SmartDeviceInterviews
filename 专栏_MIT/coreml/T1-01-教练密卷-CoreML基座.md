# T1-01 教练密卷：CoreML 基座（仅教练分支/归档，学员禁阅）

> 本文件含弱/中/强三级提示、评分要点与参考答案。提示使用纪律（C1/C2）：卡住先给弱提示；直接要答案 → 反问「输入特征类型是什么」。

## 一、概念题：提示梯与评分要点

### C1 什么是 CoreML「数据契约」？
- 弱提示：一次 `prediction(from:)` 成功的必要条件有哪些？先列「模型侧」再列「调用方侧」。
- 中提示：特征名对不上、类型对不上、形状对不上，分别报什么错、能不能在编译期发现？
- 强提示：数据契约 = 输入特征名/类型（Image/MultiArray/Sequence/Dictionary）+ 形状（含 batch/flexible）+ 输出解读（标签→含义的映射）。契约失败大多在运行时暴露，所以要写成可诊断的适配层。
- 评分要点：死记硬背典型：「能调通 prediction 就行。」（无契约维度）真懂特征：能列出输入输出契约的完整要素，并说清哪类错误在运行时才暴露。
- 参考答案：契约 = 特征名 + 类型 + 形状 + 输出映射；CoreML 只保证类型/形状检查，业务语义（标签含义、预处理）必须应用层负责。

### C2 `.mlmodel` 与 `.mlmodelc` 差在哪？
- 弱提示：构建期与运行期各发生什么？App 里打包的是哪个？
- 中提示：`MLModel(contentsOf:)` 加载 `.mlmodel` 时系统会做什么？首次启动慢在哪？
- 强提示：`.mlmodel` 是源（含训练元数据/描述）；Xcode 构建期编译成 `.mlmodelc`（优化后的运行时包）；直接打包 `.mlmodel` 会首次加载时编译（慢、体积膨胀）；App 体积看 `.mlmodelc`。
- 评分要点：真懂特征：源 vs 运行时产物 + 首次启动影响；死记硬背典型：「两个一样，都能用。」
- 参考答案：构建期 Xcode 编译 `.mlmodel → .mlmodelc`；运行时加载 `.mlmodelc`；混用 `.mlmodel` 会触发首次编译，体积与启动双输。

### C3 端侧 vs 云：五维账
- 弱提示：五维是哪五维（延迟、隐私、成本、可更新、硬件覆盖）？每维端侧/云各写一档。
- 中提示：离线扫码识别植物——离线是硬需求吗？模型多久变一次？错误成本多高？
- 强提示：五维账要写「当前值 + 变化方向 + 阈值」；选型结论要有撤出条件（如模型迭代 > 每月 1 次且团队无端侧管线 → 撤端侧）。
- 评分要点：真懂特征：五维都有具体数字与阈值 + 撤出条件；只有「端侧更好」口号 = 不过。
- 参考答案：以离线植物识别为例：延迟（端 50ms vs 云 800ms）、隐私（图不出设备 vs 上云）、成本（端按次零边际 vs 云按量）、可更新（端需发版 vs 云秒更）、覆盖（端受机型 ANE 限制 vs 云全端）。结论：识别走端、疑难样本可降级云。

### C4 为什么「能 prediction」不等于「会 CoreML」？
- 弱提示：只会调 API，会在哪些工程场景翻车？先想「模型换版本」和「设备差异」。
- 中提示：输入来自相机方向错了、模型是 float16 而你的预处理算成 float32、低端机 ANE 不可用——这些都是「能 prediction」管不到的吗？
- 强提示：三场景：① 预处理与训练不一致（静默掉点）；② 模型/标签/预处理版本不同步（错类）；③ compute unit 与机型差异（性能翻车）。会 API ≠ 会资产与边界管理。
- 评分要点：真懂特征：至少三个具体翻车场景且能定位根因；死记硬背典型：「封装成 Service 就会了。」
- 参考答案：版本同步、预处理对齐、compute unit/机型差异、错误诊断——这四类都不在 `prediction` 调用里。

### C5 Vision 内建模型 vs 自定义 CoreML 怎么选？
- 弱提示：系统模型的好处（体积/维护/系统升级）与限制（不可定制）分别是什么？
- 中提示：质量不达标、要换骨干、要控制输出格式——哪些信号说明该自定义？
- 强提示：可操作标准：质量（内建 Top1 够不够）→ 控制权（要换模型/算子？）→ 体积（内建不占包）→ 系统版本（内建要求 iOS 版本）。先内建，不够再自定义。
- 评分要点：真懂特征：给出四维判断标准与例子；死记硬背典型：「自己训的更好。」
- 参考答案：默认先试 VNClassifyImageRequest 等内建；质量/控制权/体积/系统版本四维不足时再上自定义 CoreML。

### C6 错误怎么设计？
- 弱提示：把失败按「资源/契约/运行时」分层，每层各举一例。
- 中提示：缺模型文件能重试吗？形状不匹配重试有用吗？ANE 不可用重试有用吗？
- 强提示：资源缺失 → 提示用户/重新下载（可恢复）；契约失败 → 修代码/修数据（开发期错误）；运行时失败 → 降级云或提示（产品期错误）。分层决定重试策略。
- 评分要点：真懂特征：三层分类 + 每层对应动作；死记硬背典型：「全部 catch 后弹窗。」
- 参考答案：资源（缺失/损坏→重下）、契约（类型/形状→开发期修复）、运行时（ANE/内存→降级）。重试只对可恢复层有意义。

## 二、争议焦点参考立场

- D1 端侧 vs 云：画边界是核心能力；离线/隐私/稳定延迟归端侧，快速迭代/多模态归云，中间层做降级。
- D2 依赖生成类：应用层用 Domain DTO + 适配层，生成代码当 Adapter 内侧；直接泄漏 = 模型一换全炸。
- D3 模拟器数字：可回归不可定论；必须标注环境，产品结论以真机 ANE 为准。

## 三、代码题：评分要点与提示

### Q1 特征类型与契约
- 评分要点：至少两种 MLFeatureValue 构造并打印；写清调用方必须保证的契约项。
- 参考答案要点：`MLFeatureValue(multiArray:)`、`MLFeatureValue(string:)`；契约 = 名/型/形/语义。

### Q2 模型加载失败路径
- 评分要点：错误路径/空 URL 的可读错误捕获；打印分层后的错误类型。
- 参考答案要点：`do { _ = try MLModel(contentsOf: url) } catch { print(分层) }`。

### Q3 预测契约适配器
- 评分要点：生成类与 Domain DTO 之间适配层；模型换版只动适配层。
- 参考答案要点：`struct PredictionAdapter { func toDTO(_ output: XxxOutput) -> Domain }`。

### Q4 端侧 vs 云记账
- 评分要点：五维账 + 阈值 + 撤出条件。
- 参考答案要点：见 C3 模板。

## 四、使用纪律
- 判分只认证据：契约要素、分层错误、五维数字；「感觉端侧快」不算。
- 失真自查：把模拟器性能当 ANE 结论、错误不分层 = 该题作废重跑。
