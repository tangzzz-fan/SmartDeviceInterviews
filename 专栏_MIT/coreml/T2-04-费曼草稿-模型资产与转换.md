# T2-04 费曼草稿：模型资产与转换（示例）

> **示例文件**：本文件演示「脱稿重推 + 端侧 vs 云对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 资产流水线**：数据→训练/转换→验证→打包→版本→回滚。缺一环就不是工程，是演示。
- **M2 Create ML 是产品化训练器**：表格/图像/声纹等固定任务好用；不是任意架构研究乐园。
- **M3 转换有损**：PyTorch/TF → CoreML 可能改算子、改精度；Python 的 acc 不能直接写进商店。
- **M4 量化是产品账**：体积/延迟 vs 精度，没有「免费变快」。三指标都要盯。
- **M5 版本与 App 绑定**：模型版本、标签表、预处理代码必须同版本或可协商；错位 = 静默准头崩。

## 二、端侧 vs 云对照（资产视角）

| 维度 | 端侧资产策略 | 云模型策略 |
|------|-------------|-----------|
| 交付物 | `.mlmodelc` + 标签表 + 预处理同版 | API 契约 + 服务端版本 |
| 迭代速度 | 跟 App 发版或自管热更 | 服务端随时换 |
| 验证 | 必须设备端回归 | 可用服务端评测集 |
| 体积账 | 占包体，量化要算掉点 | 客户端几乎零体积 |
| 回滚 | App 回滚或模型侧回滚清单 | 配置开关即可 |

## 三、一个例子讲到底

表格分类器：Create ML 训完导出，体积 12MB→量化 4MB，验证掉点 1.2%——产品可接受才进包。标签表与预处理版本写进三元组清单；Python 99% 只进内部实验报告，不进商店文案。

## 四、60 秒讲稿

「模型资产不是『训完丢进 Bundle』。流水线要有验证、版本、回滚。Create ML 适合固定任务，不是万能训练器。从 Python 转到 CoreML，转换可能有损——端侧回归之前，训练准确率不能当发布结论。量化是体积和延迟跟精度换，没有免费午餐。模型、标签表、预处理必须同版本；错位比崩溃更可怕，因为准头会静默坏掉。」

## 五、自检三问

1. 被问「为什么 Python 99% 不能写进商店」能答（转换有损 + 端侧回归）。
2. 能讲给同事听：量化三指标 + 是否值得的阈值。
3. 诚实自查：C1 流水线缺回滚是首轮盲区，复攻后才补全。
