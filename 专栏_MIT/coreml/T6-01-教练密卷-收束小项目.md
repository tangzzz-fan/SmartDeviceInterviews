# T6-01 教练密卷：收束小项目（仅教练分支/归档，学员禁阅）

> 本文件含弱/中/强三级提示、评分要点与参考答案。使用纪律：直接要答案 → 反问「对拍测试在哪」。

## 一、概念题：提示梯与评分要点

### C1 收束报告必有的章节
- 弱提示：正确性、性能、资产、降级、回滚——哪些必须有？
- 中提示：报告是给谁看的（产品/算法/工程）？各自要什么？
- 强提示：必含：目标与边界、数据与预处理一致性证明、性能（环境标注）、体积、降级路径、回滚条件、上线决策与撤出条件。
- 评分要点：真懂特征：≥6 章节且每章有验收物；只有「跑通了」= 不过。
- 参考答案：目标/一致性/性能/体积/降级/回滚/决策七章。

### C2 如何证明预处理与训练一致
- 弱提示：训练侧预处理代码在哪？推理侧谁实现？怎么对拍？
- 中提示：同一张图走两端，输出/中间张量是否一致？
- 强提示：对拍：同一输入样本 → 训练管线 vs 端侧管线 → 比较输出（或中间层）；断言一致。
- 评分要点：真懂特征：对拍方法 + 断言标准。
- 参考答案：同一输入双管线对拍，输出（或特征）一致才放行。

### C3 降级路径设计
- 弱提示：降级触发条件（模型缺失/性能不达标/精度差）分别降去哪？
- 中提示：降级 = 云/内建/提示用户，优先级怎么排？
- 强提示：设计：检测条件 → 降级目标（内建 → 云 → 人工）→ 用户可见反馈 → 恢复路径。
- 评分要点：真懂特征：条件 + 目标 + 反馈 + 恢复四要素。
- 参考答案：条件驱动降级链，每级有反馈与恢复。

### C4 回滚触发条件
- 弱提示：哪些信号说明新模型该回滚（指标/崩溃/投诉）？
- 中提示：回滚要可自动还是手动？
- 强提示：触发：任务指标下降超阈值、崩溃率上升、线上投诉；回滚预案要提前写。
- 评分要点：真懂特征：明确阈值 + 预案。
- 参考答案：指标阈值 + 崩溃率 + 投诉三信号；预案提前写。

### C5 合格论证「拒绝 CoreML」
- 弱提示：拒绝的理由要可验证（成本/迭代/覆盖），不是「麻烦」。
- 中提示：用统一记账模板（问题/约束/候选/代价/撤出）。
- 强提示：合格论证 = 五维账 + 数据 + 撤出条件；结论可被推翻。
- 评分要点：真懂特征：模板 + 数据 + 可推翻。
- 参考答案：与引入同等严肃的记账与数据。

### C6 60 秒讲稿大纲
- 弱提示：讲给谁听？先结论还是先背景？
- 中提示：大纲：问题 → 方案 → 数据 → 边界 → 下一步。
- 强提示：大纲：一句话结论 → 为什么端侧 → 一个数据 → 边界与降级 → 下一步。
- 评分要点：真懂特征：五段式 + 可讲 60 秒。
- 参考答案：结论/理由/数据/边界/下一步。

## 二、争议焦点参考立场

- D1 Demo ≠ 上线：上线的验收是报告七章，不是视频。
- D2 强制真机 ANE：性能结论必须真机；功能闭环 CLI 可过，上线判定必须 ANE。
- D3 文档与代码：主交付 = 报告（决策依据），代码是证据；缺一不可。

## 三、代码题：评分要点与提示

### Q1 端到端
- 评分要点：训练 → 导出 → 加载 → 预测一条样本全链路跑通。
- 参考答案要点：Create ML 训练 + 导出 + `MLModel(contentsOf:)` + prediction。

### Q2 对拍一致性
- 评分要点：同一输入两次预测标签一致；输出打印。
- 参考答案要点：两次 prediction 比较 label。

### Q3 收束报告
- 评分要点：Markdown 报告到 stdout，含七章。
- 参考答案要点：结构化打印。

### Q4 上线检查清单
- 评分要点：打印通过/缺项清单。
- 参考答案要点：boolean 清单 + 缺项高亮。

## 四、使用纪律
- 判分只认证据：对拍输出、报告七章、检查清单；「Demo 跑通」不等于上线。
- 失真自查：没有性能环境标注、没有降级路径 = 收束不合格。
