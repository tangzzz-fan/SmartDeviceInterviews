# T4-04 费曼草稿：更新与多模态（示例）

> **示例文件**：本文件演示「脱稿重推 + 端侧 vs 云对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 可更新是特殊能力**：不是所有模型都能设备端微调；看训练声明与运行时权限，默认假设「不能」。
- **M2 个性化 ≠ 重新训练宇宙**：常见是最后几层、有限样本；期望降噪，失败会表现为不准/不稳/用户无感。
- **M3 语言内建优先**：NLTagger / SoundAnalysis 能解决的，先别上自定义 CoreML。
- **M4 可变形状是契约扩展**：flexible shape 要测最小/最大/长宽比边界；动态尺寸拖性能。
- **M5 更新也是发布**：数据、标签、回滚、隐私同意——与发版同等严肃。

## 二、端侧 vs 云对照（更新与模态）

| 能力 | 端侧路径 | 云路径 | 何时拒端侧 |
|------|---------|--------|-----------|
| 个性化 | 可更新模型 / 本地适配层 | 账户侧画像+服务模 | 无 updatable 声明 |
| NLP | NLTagger → 再考虑 CoreML | 大模型 API | 任务超内建能力且体积炸 |
| 热更新 | 差分包+版本协商 | 配置开关 | 审核/安全边界不清 |
| 多模态 | 双模型+自研融合 | 统一多模态 API | 端侧融合契约测不稳 |

## 三、一个例子讲到底

键盘快捷短语：先 NLTagger 分词足够 → 不上 Transformer。若要个性化，确认模型可更新、样本有同意、失败可回滚旧版+旧标签表。图+文搜索则先定契约字段（图向量、文向量、会话键），再谈融合——字段不齐的多模态是赌运气。

## 四、60 秒讲稿

「可更新不是 CoreML 标配，是训练时声明出来的特殊能力。个性化往往只动最后一层，别指望设备上重训宇宙。能 NLTagger 解决的别上自定义大模型。flexible shape 要测边界。模型一更新，标签表、预处理、隐私同意、回滚路径要一起走——这叫发布，不叫『换个文件』。端侧更新慢但隐私好；云更新快但数据出门——边界写进产品，不写进口号。」

## 五、自检三问

1. 被问「怎么判断能不能设备端更新」能答（声明 + 权限）。
2. 能讲给同事听：NLTagger 优先的选型标准。
3. 诚实自查：C1 把可更新当默认是首轮翻车点，复攻后钉死。
