# T1 教练出题集：CoreML 基座

> 原料 = 学员 Swift/Vision/Bundle 存量。人设见 [[01-学员人设卡.md]]；预期漏洞：把 CoreML 当云封装、特征类型盲区、编译产物分不清。
> 提示与评分在密卷；本题干版无答案。

## 一、共识：5 个核心心智模型

| # | 模型 | 一句话骨架 | 存量锚点 |
|---|------|-----------|---------|
| M1 | 模型 = 固化计算图 + 数据契约 | CoreML 模型不是「智能对象」，是「约定好输入输出形状的可执行图」 | Codable 契约、函数签名 |
| M2 | 特征类型决定集成方式 | Image / MultiArray / Sequence / Dictionary 决定预处理与 API 形状 | Vision vs 手写张量 |
| M3 | 源文件 ≠ 运行时产物 | `.mlmodel` 是源；设备上跑的是编译后的 `.mlmodelc`（或自动编译缓存） | Bundle 资源、构建阶段 |
| M4 | 端侧与云是产品决策 | 延迟、隐私、成本、可更新性、硬件覆盖——五维账，不是技术炫技 | URLSession 云调用对照 |
| M5 | 失败是一等公民 | 缺模型、形状不匹配、类型不对、计算单元不可用——都要可诊断 | `throws`、错误域 |

学员自检：合上表复述 M1–M5，各举一个自己项目里会踩的坑。

## 二、争议：3 个焦点

**D1 端侧推理会不会被云大模型淘汰？**
- 正：隐私、离线、稳定延迟、按次零边际成本仍不可替代。
- 反：模型迭代速度、多模态能力、团队熟悉度都在云侧；端侧维护成本高。
- 迁移者意义：学会画边界——哪些必须端侧，哪些必须云，哪些可降级。

**D2 业务代码该不该直接依赖自动生成的 `XxxInput` 类？**
- 正：类型安全、少样板。
- 反：模型一换类名全炸；应用层应依赖自己的 Domain DTO + 适配层。
- 迁移者意义：把生成代码当 Adapter 内侧，不要泄漏到 UI。

**D3 模拟器上的性能数字有没有发表价值？**
- 正：可回归、可对比逻辑正确性。
- 反：无 ANE，数字会误导产品决策。
- 迁移者意义：数字必须标注环境；产品结论以真机为准。

## 三、概念拷问题（6 道）

### C1 什么是 CoreML「数据契约」？

用自己的话定义：一次 `prediction` 成功的最小必要条件是什么？必须提到输入特征名/类型/形状与输出解读。

### C2 `.mlmodel` 与 `.mlmodelc` 差在哪？

说明构建期与运行期各自发生什么；App 体积与首次启动分别受谁影响。

### C3 端侧 vs 云：五维账

任选一个真实功能（如离线扫码识别植物），写五维对比表：延迟、隐私、成本、可更新、覆盖率。给出你的选型结论与撤出条件。

### C4 为什么「能 `prediction`」不等于「会 CoreML」？

列出至少三个「只会调 API」会在工程上翻车的场景。

### C5 Vision 内建模型与自定义 CoreML 模型怎么选？

给出可操作标准（质量、控制权、体积、系统版本）。

### C6 错误怎么设计？

设计一套面向产品的错误分层（资源缺失 / 契约失败 / 运行时失败），并说明哪些该重试、哪些该降级云、哪些该提示用户。

## 四、代码任务题（4 道）

落 `代码/T1/`，`swift Q*.swift` 跑通，输出贴回。

### Q1 特征类型与契约

构造至少两种 `MLFeatureValue`（如 MultiArray、字典/字符串），打印类型与描述；写清「若这是模型输入，调用方必须保证什么」。

### Q2 模型加载失败路径

演示：错误路径 / 空 URL 加载时如何捕获并打印可读错误（不要求真模型文件存在）。

### Q3 预测契约伪代码落地

用协议定义 `ImageClassifier`（输入图片元数据 + 输出标签），提供「假实现」与「CoreML 适配器骨架」两版，打印调用链。

### Q4 端侧 vs 云记账 CLI

输入一个场景名，打印五维账模板（可硬编码示例数据），强制输出「选型 + 撤出条件」。
