# MIT 三问攻坚：iOS 老手系统化 CoreML —— 学习计划

> 目标：学员（人设见 [[01-学员人设卡.md|01-学员人设卡]]）用 MIT 三问法把 CoreML 从「会调 `prediction`」升级为「**选对场景 → 管好资产 → 量性能 → 敢拒云**」：能在 Swift/Vision 语境下独立完成端侧推理闭环，并说清取舍。
> 方法基座：[[04-方法论基座-MIT三问与测试协议.md|方法论基座]]（自包含，与 Swift/Python/DP 线同一份方法论）。
> 分支：教练分支 `feat/mit-coreml-study`（对应 worktree `.worktrees/coreml-coach`）与学员分支 `feat/mit-coreml-study-student`（对应 worktree `.worktrees/coreml-student`），双 worktree 协议见第三节。

## 一、原料策略

本线无外部教材硬依赖：原料 = 学员 Swift/iOS 存量（Vision、URLSession、async/await、文件资产管理）+ 本机 macOS 上的 CoreML / Vision / CreateML / VisionKit + Python（torch / coremltools）+ C++（clang++ / CoreML ObjC++ 桥）。教练按既有知识重建模型骨架；云端大模型/训练框架只作为「对照边界」。

## 二、九主题与顺序

顺序逻辑：先建立端侧推理心智，再管模型资产，再接媒体管线，再谈更新与多模态，性能工程与收束项目收 Swift 主线；2026-08-17 补三个独立轮：T7 Python 模型创建与转换（coremltools）、T8 VisionKit 与系统视觉能力、T9 C++ + Python + CoreML 集成（真实混合栈）。

| 序 | 主题 | 拷问重点 | Swift 存量锚点 |
|---|------|---------|----------------|
| T1 | CoreML 基座 | MLModel / 特征类型 / 编译产物 / 端侧 vs 云边界 | Vision、Codable、文件 Bundle |
| T2 | 模型资产与转换 | Create ML / coremltools / 量化 / `.mlmodel`→`.mlmodelc` | 资源管理、体积/延迟权衡 |
| T3 | Vision 与媒体管线 | VNCoreMLRequest、预处理、方向、批处理 | Vision、CGImage、async |
| T4 | 更新与多模态 | 可更新模型、个性化、NLP/Sound、可变形状 | NLTagger、文件写入、权限 |
| T5 | 性能与工程化 | computeUnits、Neural Engine、 profiling、后台、隐私 | Instruments 心智、后台任务 |
| T6 | 收束小项目 | 端到端：造模→集成→度量→上线决策 | 完整 Swift 小工程 |
| T7 | Python 模型创建与转换（独立增量轮） | torch + coremltools 造模/转换、mlprogram 规范、量化、契约定义 | Python venv（torch/coremltools） |
| T8 | VisionKit 与系统视觉能力（独立增量轮） | ImageAnalyzer/Live Text/DataScanner、系统能力优先选型、隐私权限 | VisionKit/Vision（真机待验证） |
| T9 | C++ + Python + CoreML 集成（独立增量轮） | Python 造模→编译 .mlmodelc→C++（ObjC++ 桥）推理、混合栈分工 | clang++ / CoreML ObjC++ |

## 三、每主题执行流程（教练 + 学员双角色）

沿用四件套规范（[[04-方法论基座-MIT三问与测试协议.md|方法论基座]]），每主题产出：

1. **教练出题**（教练分支）：`T{n}-01-教练出题-<主题>.md` 与 `T{n}-01-教练密卷-<主题>.md`（提示梯 + 评分要点，**密卷进教练/归档**；本线采用「三处齐全」自律模式时学员侧也可见，先闭卷后对照）。
2. **学员作答**：闭卷作答 `T{n}-02`，代码实跑，输出贴回。
3. **批改判定**：过关 / 半过（拆判分点）/ 未过。
4. **费曼写回**：`T{n}-04`（含「端侧 vs 云」对照小节）。

**代码通道环境**：`swift 代码/T{n}/Q*.swift` 顶层脚本；CreateML / CoreML / Vision 在 macOS 上可跑。需要真机 Neural Engine 或相机的结论记「待真机验证」。

## 四、执行纪律（C1–C5）

| # | 纪律 | 在本线中的含义 |
|---|------|----------------|
| C1 | 先弱提示 | 卡住先只定位「输入/输出/compute unit」，不给整段样板 |
| C2 | 拒答代学 | 直接要模型文件/完整代码 → 拒给，反问「特征类型是什么」 |
| C3 | 双通道强制 | 口述过关后必须有可跑代码或可复现度量 |
| C4 | 台账如实 | 「待真机验证」必须如实；不准把 CLI 跑通冒充 ANE 结论 |
| C5 | 产出落本目录 | 全部产出落 `MIT-CoreML-Migration/` |

失败标准：全题全对（人设失效）；只会抄 `prediction(from:)` 讲不清特征类型；把云 API 延迟数字当成端侧结论。
