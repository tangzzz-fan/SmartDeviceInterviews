# T7-04 费曼草稿：Python 模型创建与转换（示例）

> **示例文件**：演示「脱稿重推 + 对照 + 60 秒讲稿」长什么样，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 Python 造模、CoreML 部署**：训练框架 → coremltools → `.mlmodel` → `.mlmodelc`；两端靠数据契约连接。
- **M2 coremltools 是转换器**：从 `torch.jit.trace` / SavedModel 转；trace 需要输入样例（记录数据流）。
- **M3 规范选型**：新项目默认 ML Program；老模型/老工具才 NeuralNetwork。
- **M4 量化是决策**：fp16 默认无损省一半；int8/palettization 有损换体积速度；三指标验收。
- **M5 契约由 Python 定义**：名/型/形/预处理/标签在转换时钉死，Swift/C++ 端按同一契约校验。

## 二、对照表

| 环节 | Python 端 | 端侧 |
|------|-----------|------|
| 契约 | convert 时声明 | 加载后按契约取数 |
| 精度 | 原框架前向 | CoreML 转换后前向（有损可能） |
| 版本 | 脚本 + 哈希 | 标签/预处理同版本 |

## 三、一个例子讲到底

torch 训一个 4→3 的微型 MLP，`torch.jit.trace` 后 `coremltools.convert`，同一输入 torch 与 CoreML 对拍误差 1e-6、Top1 一致；fp16 后体积减半、Top1 不变——量化账本成立。

## 四、60 秒讲稿

「CoreML 模型不是别人丢给你的黑盒，是可以用 Python 自己造出来的。核心一句话：训练框架负责学，coremltools 负责转，契约负责两端对齐。转换要 trace 不是读源码，所以要有输入样例；转换有损，所以必须端侧回归；量化先 fp16 再 int8，用体积、延迟、指标三本账说话。会造模之后，端侧推理才真正闭环。」
