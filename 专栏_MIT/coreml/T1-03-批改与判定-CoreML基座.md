# T1-03 批改与判定：CoreML 基座（示例）

> **示例文件**：本文件演示「教练按密卷判分」长什么样——基于一份模拟学员作答，用于格式与判定标准参考，**不是真实产物**。正式运行时请对你自己的真实作答另写一份批改。
> 判定依据：[[T1-01-教练密卷-CoreML基座.md|T1 密卷]]（提示梯 + 评分要点 + 参考答案）。

## 一、学员作答摘要（模拟）

- C1：把「数据契约」说成「有模型就能跑」，没提特征名/类型/形状与输出解读。
- C2：知道 `.mlmodel` 是源文件，但说「设备上也直接跑 `.mlmodel`」，编译产物没落清楚。
- C4：端侧 vs 云只写了「隐私更好」，缺延迟/成本/可更新性/硬件覆盖。
- Q1：打印了输入特征列表，但没对照输出类型；形状列空。
- Q3：Bundle 路径写对了，但缺模型不存在时的错误分支。

## 二、首轮判定

### 概念通道（6 题）

| 题 | 判定 | 判分点拆解 |
|----|------|-----------|
| C1 | 未过 | 最小必要条件缺「特征名/类型/形状」三件套 |
| C2 | 半过 | 源 vs 运行时方向对；运行时产物仍写成源文件 |
| C3 | 过关 | Image / MultiArray 选型标准可操作，举例正确 |
| C4 | 半过 | 只盯隐私一维；五维账缺四维 |
| C5 | 过关 | 失败四类（缺模型/形状/类型/计算单元）列出 |
| C6 | 半过 | 反对直接依赖生成类；Domain DTO 边界没画清 |

### 代码通道（4 题）

| 题 | 判定 | 判分点拆解 |
|----|------|-----------|
| Q1 | 半过 | 特征名有；类型/形状与输出解读不全 |
| Q2 | 过关 | 假想 `prediction` 契约与错误域打印完整 |
| Q3 | 半过 | Bundle 加载路径对；缺文件失败分支 |
| Q4 | 过关 | 端侧/云五维记账表可打印，含「待真机」标注 |

### 首轮总判定：**未过关**（概念 2过3半1未，代码 2过2半）
