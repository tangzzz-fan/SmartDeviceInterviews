# T2-04 费曼草稿：创建型模式（示例）

> **示例文件**：本文件演示「脱稿重推 + 语言内建对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 共享 ≠ 唯一**：`static let shared` 只保证唯一实例和线程安全初始化；可变状态全局共享、测试没法换、依赖藏着——这三条批评才是关键。
- **M2 创建与使用分离**：调用方只认协议。工厂回答「按条件选哪个实现」，DI 回答「谁持有依赖」，是两件事。
- **M3 Builder 是最后手段**：命名参数、默认值、可失败构造先顶上去；Builder 只剩「交叉校验 + 不可变产物」的场景。
- **M4 Prototype 是免费的**：struct 赋值语义上就是独立副本；class 才要手写深拷贝。
- **M5 生命周期决定创建方式**：进程级→单例/容器，作用域级→注入/@Environment，按需→工厂。

## 二、语言内建对照

| Swift 惯用写法 | 对应模式 | 注意 |
|---------------|---------|------|
| `static let shared` | Singleton | 只保证唯一，不保证不共享 |
| `static func make(type:)` | Factory Method / 静态工厂 | 看决定权在谁 |
| 命名参数 + `init?` | Builder 的吸收者 | 交叉校验时才回 Builder |
| struct 值语义 | Prototype | 赋值即原型复制 |
| `@Environment` / 构造注入 | DI | 生命周期作用域化 |

## 三、一个例子讲到底

项目里的 `UserManager.shared` 被六个页面直接拿。按 M5 拆：登录会话是进程级→单例可留但收敛写入口；搜索历史这类缓存改成注入到页面作用域。改完测试直接传假实例，不用重置全局状态。

## 四、60 秒讲稿

「创建型模式一句话：先回答谁拥有生命周期，再决定怎么创建。`static let` 保证唯一，但保证不了共享可变状态不乱；工厂是让调用方别认识具体类型；Swift 的命名参数已经把 Builder 大半工作吸收了；而 Prototype 在 Swift 里是免费的——struct 赋值就是拷贝。真正要练的不是会写这四种模式，是判断什么时候该用：单例是最后手段，注入是默认，工厂在类型多变时才有价值。」
