# T3-03 批改与判定：结构型模式（示例）

> **示例文件**：本文件演示「教练按密卷判分」长什么样——基于一份模拟学员作答，用于格式与判定标准参考，**不是真实产物**。
> 判定依据：[[T3-01-教练密卷-结构型模式.md|T3 密卷]]。

## 一、学员作答摘要（模拟）

- C1：把 Facade 当 Adapter 答（「都是封装」），没讲「翻译 vs 简化」的方向差异。
- C3：五个场景里缓存判成了 Decorator（实际是 Proxy——控访问）。
- C5：说「Swift 有 extension 就不需要 Adapter 了」，没区分免包装适配与仍需包装的场景。
- Q1：只写了 Facade，没写 Adapter 翻译层。
- Q3：Decorator 链跑通，但「顺序敏感反例」没写。

## 二、首轮判定

### 概念通道（6 题）

| 题 | 判定 | 判分点拆解 |
|----|------|-----------|
| C1 | 未过 | 方向（翻译 vs 简化）未讲；例子是包装不是适配 |
| C2 | 过关 | 递归包装结构写出，extension 静态 vs Decorator 动态讲清 |
| C3 | 半过 | 控访问 vs 加职责的轴讲了，但五场景判错两个 |
| C4 | 过关 | 组合/继承标准可操作，继承仍合理场景给出 |
| C5 | 半过 | 知道 extension 适配，但「仍需包装」的边界没讲 |
| C6 | 过关 | 三类间接层成本 + 判定标准（变化点/层数/实测） |

### 代码通道（4 题）

| 题 | 判定 | 判分点拆解 |
|----|------|-----------|
| Q1 | 半过 | Facade 有；Adapter 翻译层缺失 |
| Q2 | 过关 | 请求计数证明缓存生效；Proxy 归属与理由正确 |
| Q3 | 半过 | 叠加顺序证明有；顺序敏感反例缺失 |
| Q4 | 过关 | 两版对比量化真实，结论有账 |

### 首轮总判定：**未过关**（概念 3过2半1未，代码 2过2半）
