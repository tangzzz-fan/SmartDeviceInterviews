# T3-04 费曼草稿：结构型模式（示例）

> **示例文件**：本文件演示「脱稿重推 + 语言内建对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 Adapter 是翻译**：接口对不上时，包装一层把它翻译成目标协议。Swift 里 extension 经常免掉这层包装。
- **M2 Facade 是简化**：子系统太乱时给一个门面，调用方不碰内部。方向：Adapter 向内适配，Facade 向外简化。
- **M3 Decorator 是叠加**：同一协议 + 递归包装 + 附加职责，可组合可换顺序。extension 是静态补丁，做不到。
- **M4 Proxy 是替身**：控制访问——懒加载、缓存、权限、远程。结构和 Decorator 一样，Forces 不同。
- **M5 组合优先**：变化的是行为就组合，是身份才继承。

## 二、语言内建对照

| Swift 惯用写法 | 对应模式 | 注意 |
|---------------|---------|------|
| extension 适配第三方类型 | Adapter（免包装） | 需要状态时仍要包装 |
| 包装结构体/类 | Decorator | 职责可叠加，顺序敏感 |
| 懒加载属性 / 包装类型 | Proxy | 控访问，不是加职责 |
| 协议 + extension | 组合替代继承 | 身份场景仍要继承 |

## 三、一个例子讲到底

网络层：`SDKClient` 方法不友好，用 `SDKClientAdapter` 翻译成自己的 `HTTPClient` 协议；`APIClient` 做 Facade 统一 baseURL/鉴权/序列化；`UserCacheProxy` 包在 `UserLoader` 外面做缓存。三层各有各的账：Adapter 为换 SDK 付费，Facade 为调用方省心，Proxy 为懒加载付费——每层都有撤出条件。

## 四、60 秒讲稿

「结构型模式都是'包装'，但方向不同：Adapter 翻译接口，Facade 简化入口，Decorator 叠加职责，Proxy 控制访问。Swift 的 extension 已经把很多适配变免费了，所以第一问永远是'这层包装有没有真实的变化点'——没有变化点的包装就是负债。判断 Proxy 和 Decorator 别看长相，看约束：在访问上动手脚是 Proxy，在调用之外加东西是 Decorator。包装超过三层还没记账，基本就是滥用了。」
