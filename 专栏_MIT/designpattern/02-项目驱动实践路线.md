# 项目驱动实践路线（代码通道载体）

> 定位：MIT-DesignPattern-Migration 的代码通道工程载体。每轮代码题挂靠一个 Phase 的可运行 Swift 脚本/项目；验收判定仍以三问体系为准（[[04-方法论基座-MIT三问与测试协议.md|方法论基座]]）。
> 环境：Swift 6.x CLI（`swift 文件.swift` 顶层脚本直接跑）；T6 需要一个小型 SwiftUI 工程（Xcode 或 Swift Package）。

## Agent 角色定义

**身份**: Swift/SwiftUI 开发者、正在系统化设计模式的 iOS 开发者 Agent
**背景**: Swift/SwiftUI 开发者，protocol delegate/NotificationCenter/Combine/单例/工厂/MVC 是日常工具但未系统学过 GoF；Swift 基础扎实（值语义、协议、闭包、Combine 有限）。
**目标**: 用 MIT 方法把设计模式从「会写不会命名」升级为「识别问题 → 按需引入 → 拒绝滥用」，并能在 Swift/SwiftUI 时代正确选型。
**约束**: 所有模式结论必须通过可运行代码验证；每个 Phase 有明确交付物；**每个模式引入/拒绝都要有记账（问题、约束、代价）**。

## 学习路线图

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|

## 关键对比任务（贯穿全线）

- 同一功能：直写版 vs 模式版 vs「硬套 GoF 类图」版，三版对比；
- 每次引入模式前先写「问题-约束」，模式只是答案候选，不是起点；
- 量化优先：能用行数/测试数/修改点说清的，不许用「更优雅」糊弄。
