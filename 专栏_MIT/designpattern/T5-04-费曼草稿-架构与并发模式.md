# T5-04 费曼草稿：架构与并发模式（示例）

> **示例文件**：本文件演示「脱稿重推 + 语言内建对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 模式 vs 架构**：模式是局部解法（看 Forces 匹配），架构是整体形状（看变更隔离）。MVVM/Coordinator 是架构风格，不是 GoF。
- **M2 MVVM = 状态与视图解耦**：ViewModel 放状态和可测逻辑，不碰 View；状态选型看作用域（@State 私有 / @Observable 共享 / 函数纯计算）。
- **M3 导航是编排**：NavigationStack 把路径变数据（可恢复、可编程）；跨模块/混编/深层流程才需要导航层（Coordinator 退化成导航服务）。
- **M4 DI 显式化**：手动注入默认，@Environment 是 SwiftUI 官方通道，容器是规模到了的升级；全局单例是最差默认。
- **M5 actor 是隔离域**：串行 + 可重入 + Sendable 边界。可重入意味着 await 挂起时状态可能被别人改——check-then-act 要当心。

## 二、语言内建对照

| Swift 惯用写法 | 对应概念 | 注意 |
|---------------|---------|------|
| SwiftUI View（body 是函数） | MVVM 的 View 层 | ViewModel 不碰 View |
| NavigationStack path | 导航数据化 | 跨模块编排仍需导航层 |
| @Environment | 依赖注入 | 按视图树传递 |
| actor | 隔离域 | 可重入 ≠ 锁 |
| @Observable | 状态共享 | 读时依赖收集 |

## 三、一个例子讲到底

搜索页：ViewModel 管 query/结果/错误（可脱离 View 测试），@Environment 注入 Logger 和 Cache，缓存用 actor 收状态。导航从「手动 push」改成 path 数据化——深链和状态恢复白拿。遇到跨模块跳转（搜索→详情→支付）时再评估要不要导航服务层。

## 四、60 秒讲稿

「架构和模式是两回事：模式是局部解法，架构是整体形状。SwiftUI 时代，MVVM 让 View 变成函数、ViewModel 承载可测逻辑；导航从手动 push 变成数据 path；依赖从全局单例变成 @Environment 注入；并发从锁变成 actor。actor 不是锁的语法糖——它串行、可重入，await 挂起时别人可能改了状态。学这轮不是记住四个名词，是每个设计决策都能回答：这是局部问题还是整体形状？依赖谁持有？状态该不该共享？」

## 五、自检三问
