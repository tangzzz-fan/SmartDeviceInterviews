# 学员学法与攻坚 SOP：我会怎么学

> 视角：学员第一人称。人设见 [[01-学员人设卡.md|01-学员人设卡]]，流程与台账见 [[00-学习计划.md|学习计划]]，代码载体见 [[02-项目驱动实践路线.md|项目驱动实践路线]]。
> 一句话学法：**不背模式名字，只认问题与约束**——先识别 Forces，再对号解法；Swift 存量是挂钩，语言内建是校验，代码实跑是证据。

## 一、学习姿态（三条总纲）

1. **问题先行**：每个模式先问「它解决什么问题、在什么约束下成立、代价是什么」，禁止先背名字再找例子。
2. **存量挂靠 + 语言校验**：Swift 的 protocol delegate/闭包/单例是天然挂钩；语言内建（协议、闭包、Combine、@Observable）会改写 GoF 实现——先写直觉版，再对模型版，差异处才是学习区。
3. **引入必记账**：每个模式引入/拒绝都写「问题-约束-代价」三行账；没有账的模式决定一律视为「拍脑袋」。

## 二、每主题七步循环 SOP

| 步 | 动作 | 产出 | 自查红线 |
|---|------|------|---------|
| 1 | 盘点存量：该主题在 Swift 里我已经怎么写了 | Swift 版「问题-解法」清单 | 不许跳过存量直接背 GoF |
| 2 | 自推五模型，再对教练版 | 自推版 + 差异标注 | 先对答案再复述 = 无效 |
| 3 | 闭卷作答概念题，逐题自评 | 作答稿（思考过程 + 自评三档） | 自评诚实，「纯猜」不许写成「半懂」 |
| 4 | 卡住逐级要提示 | 提示使用记录（级别、是否点醒） | 跳级 = 纪律违规 |
| 5 | 代码硬验证（每个模式最小实现 + 对拍） | `代码/T{n}/` 跑通实现 + 输出 | 输出不贴回 = 视为未跑 |
| 6 | 引入记账 + 台账复攻 | 每题的「问题-约束-代价」账 + 台账行 | 未过不许前进；无账不许写结论 |
| 7 | 费曼讲回（含语言内建对照） | 费曼草稿 | 被问倒 = 退回第 3 步 |

## 三、各主题我怎么学（预判 + 破法）

### T1 模式基座：先把「词汇」变成「问题词典」

- **我会怎么学**：拿自己 Swift 项目的代码当语料——把 protocol delegate、NotificationCenter、闭包、static let 单例、static func 工厂逐个翻译成「问题-约束-解法」三元组，再对照 GoF 词汇。先不碰类图，先学 Forces。
- **预判卡点**：把模式当处方背（说不出为什么）；把「实现长相」当「模式身份」（同一个长相在不同 Forces 下是不同模式）。
- **破法**：模式识别器 CLI 当第二个教练——输入代码，强制自己输出三元组，答不出「约束」就不许写模式名。

### T2 创建型：值语义会把「复制」变免费

- **我会怎么学**：把 `static let` 单例、`static func` 工厂、手写深拷贝逐一对照 Singleton 批评、Factory/Builder、Prototype=拷贝。重点不是会写，是**判断什么时候不该用单例**。
- **预判卡点**：Singleton 万能化；把 Prototype 还按 class 深拷贝写，忘了 struct 拷贝白送。
- **破法**：重构一个真实单例为显式注入，量化测试改进。

### T3 结构型：组合 vs 继承是主战场

- **我会怎么学**：Swift 的 extension 适配/类型包装经验挂靠 Adapter/Decorator/Proxy；重点练「协议组合」和「继承」的判断标准。
- **预判卡点**：Decorator 和 Proxy 分不清（都是包装，约束不同）；Facade 和 Adapter 混为一谈。
- **破法**：网络层封装实战，把「统一入口」「隔离 SDK」「加缓存」三种意图分别落成 Facade/Adapter/Proxy。

### T4 行为型：我的 Swift 主场，但要防「套公式」

- **我会怎么学**：protocol delegate/NotificationCenter/Combine/闭包全是我写熟的——重点是反着来：每个 Swift 写法先说出模式名，再判断该用协议、闭包还是 Combine。
- **预判卡点**：Observer 用 Combine 写就以为懂了（没讲清订阅寿命）；Command 用闭包写就以为等价（没讲清撤销/队列语义）。
- **破法**：事件/命令总线实验，做「闭包版 vs 协议版 vs Combine 版」三版对拍。

### T5 架构与并发：模式进入工程层

- **我会怎么学**：MVC 存量挂靠 MVVM；导航栈经验对照 Coordinator 与 NavigationStack；GCD 经验对照 Actor。重点：**模式 vs 架构的分工**。
- **预判卡点**：把 MVVM/Coordinator 当 GoF 背；在 SwiftUI 里硬套 UIKit 时代导航。
- **破法**：SwiftUI 小工程实战，先朴素写，再按需引入，每引入一个架构件都记账。

### T6 收束：用「重构对拍」证明方法学会了

- **我会怎么学**：拿一个真实小项目写两版——直觉版 vs 按需引入版，量化差异（行数、可测性、修改成本），得出「哪些模式值得、哪些是负债」的结论。
- **预判卡点**：为了凑「用了模式」而强行引入；或者反过来，什么都拒绝。
- **破法**：对拍数据说话，不接受「感觉更优雅」。

## 四、反模式自查清单（每次学习后过一遍）

- [ ] 我是不是先背了模式名、再回头找「问题」？（识别失序 = 无效）
- [ ] 概念题过了，我是不是省掉了代码题？（C3 红线）
- [ ] 每个模式决定有没有写「问题-约束-代价」三行账？
- [ ] 代码是抄的旧实现还是自己跑通的？每行我能讲吗？
- [ ] 我是不是在用继承照搬本该协议组合的场景？
- [ ] 台账里有没有把「半懂」写成「过关」？（C4 红线）
