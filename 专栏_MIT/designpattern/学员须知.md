# 学员须知（三处齐全版）

> 设计模式线采用「三处齐全」：参考解法、示例批改、示例费曼在 **main / 教练侧 / 学员侧** 三处都可见（方便随时查格式与标准）。这意味着防假学习从「物理不可见」改为「自律」：**先闭卷作答，再对照参考，如实记录差距**。

## 你在这里能做什么

1. **看题干**：`T{n}-01-教练出题-<主题>.md`（共识五模型 + 争议三焦点 + 拷问题干）。
2. **盘点存量 + 自推五模型**：先写「Swift 里我已经怎么解决这类问题」，再自推 M1–M5，对教练版标注差异。
3. **闭卷作答**：写 `T{n}-02-学员作答-<主题>.md`——每题先写思考过程再给结论，附自评三档。
4. **代码实跑**：实现放 `代码/T{n}/`（参考解法也在同目录，标「参考解法」），先自己写，`swift 代码/T{n}/Q*.swift` 实跑，输出贴回作答稿。
5. **对照自批**：作答完成后，对照 `T{n}-01-教练密卷`（提示梯+评分要点+参考答案）与 `T{n}-03-批改与判定`（示例）自批，把差距如实记进作答稿。
6. **费曼写回**：参考 `T{n}-04-费曼草稿`（示例）的格式，写自己的 `T{n}-04`。
7. **提交即留档**：`git add -A && git commit`，台账在 `00-学习计划.md` 第五节。

## 纪律红线（违反 = 该轮作废重跑）

- **先闭卷后对照**：作答完成之前不许打开同目录的参考解法 / 密卷 / 批改 / 费曼；对照过的题要如实标注「对照过」；
- 自评必须诚实：「纯猜」不许写成「半懂」；只说出模式名字、讲不清「问题/约束」的如实标半懂；
- 代码没跑起来 = 没验证；直接抄参考解法不跑 = 该题作废；
- 模式引入/拒绝没有「问题-约束-代价」记账，不许写结论。

## 流程速记

```
闭卷作答 + 代码实跑 + 提交
  → 对照密卷/示例批改自批（过/半过/未过，拆判分点）
  → 复攻（逐级提示）→ 写自己的费曼稿 → 提交
```
