# T6 教练出题集：收束重构

> 学员人设：已完成 T1–T5（见 [[01-学员人设卡.md]]）；本主题是整线收束——不是学新模式，而是证明「识别 → 记账 → 决策」已成肌肉记忆。预期暴露点：为凑模式而引入、没有测试就重构、量化靠「感觉更优雅」。
> 挂靠：T1 三元组与滥用判定、T2 创建型、T3 结构型、T4 行为型、T5 架构与并发。
> 使用纪律：学员卡住按「弱→中→强」逐级给提示，禁止跳级；直接要答案 → 拒答并反问「你的对拍测试在哪」（C1/C2）。提示与评分要点在密卷（仅教练分支），本文件是题干版。

## 一、共识：5 个核心心智模型

| # | 模型 | 一句话骨架 | 前序锚点 |
|---|------|-----------|---------|
| M1 | 重构的验收标准是「行为不变、结构改善」 | 对拍测试：同一输入序列，重构前后输出一致；没有对拍的重构是赌博 | T1–T5 的「实跑即证据」纪律 |
| M2 | 引入模式的正确顺序：问题 → 约束 → 候选 → 记账 → 决策 | 禁止先选模式再造问题；候选模式只是答案集，不是起点 | T1 三元组、M5 负债决策 |
| M3 | 量化是防自我欺骗的唯一手段 | 行数、修改点、测试数、耦合度要有数字；「更优雅」不是证据 | T1 Q4 引入记账、T3/T4 对拍 |
| M4 | 模式是可逆决策 | 引入时写撤出条件；重构债要还；没有撤出条件的引入是赌博 | T1 M5、各轮记账纪律 |
| M5 | 收束目标 = 肌肉记忆 | 把 T1–T5 浓缩成一条自动执行的决策链：识别问题 → 记账 → 选承载 → 量化验证 | 六轮闭环后的能力验收 |

学员自检要求：本主题不需要复述模型，需要「用」——每个决定都要能指向前序轮次的某个模型。

## 二、争议：专家吵得最凶的 3 个焦点

**D1 重构该不该「顺手」引入模式？**
- 正方：改到哪算到哪，顺手重构效率高，不留技术债。
- 反方：顺手 = 没有记账、没有对拍、没有撤出条件；重构和功能变更混在一个提交里，出问题无法回退。
- 对迁移者的意义：本线纪律 = 重构必须独立提交、先对拍、后记账；「顺手」是反模式。

**D2 什么时候重构不值得做？**
- 正方：代码能用、没有新需求驱动、风险大于收益 → 不重构；重构是投资，要有回报。
- 反方：坏味道不除会持续吸血，越晚越贵。
- 对迁移者的意义：给「不重构」也要记账（收益/风险/时机），拒绝要有理由。

**D3 模式学习者的毕业标准是什么？**
- 正方：能认出模式、能实现模式。
- 反方：会认会写只是入门；毕业 = 能判断「该不该引入」，并能为「不引入」给出有据的理由。
- 对迁移者的意义：本线按「拒绝能力」验收——能论证拒绝的模式学习者，才算会用。

## 三、概念拷问题（6 道，口述通道）

判定标准：能讲出「为什么」并迁移到新场景 = 过；只能复述定义 = 不过。**每题都要有「问题-约束」维度，只背名字不算回答。**

### C1 重构的安全网是什么？没有测试的重构怎么进行？

问题：说出「行为不变」的验证手段（对拍测试/特征测试）；如果项目没有测试，重构前你至少要做哪两件事（可观察的行为基线 + 小步提交）？为什么「先补测试再重构」不是教条而是风控？

### C2 引入模式的完整决策路径？

问题：从「发现坏味道」到「引入/拒绝模式」，走完整路径：问题 → 约束 → 候选模式 → 语言内建承载 → 记账（代价/撤出条件）→ 决策。用你自己 T6 项目里的一处真实改动演示。

### C3 量化的维度有哪些？哪些不能量化但必须记录？

问题：列出可量化维度（行数、文件/类型数、修改点、测试数、圈复杂度）与不可量化但必须记录的内容（可读性、团队认知成本、长期演进风险）；为什么「不可量化」不等于「可以不记录」？

### C4 模式的可逆性：什么情况下会撤？

问题：说出三个「引入后应该撤掉模式」的信号（约束变了、内建覆盖了、账算不平）；撤出成本怎么提前控制（独立提交、撤出条件写进记账）？

### C5 毕业标准自评：一段「模式满满的代码」值不值？

问题：给你一段「三个模式叠在一个类里」的代码，怎么判断它值不值？列出你的判定清单（每个模式的问题-约束是否真实、账是否算平、能否指出撤出条件）。

### C6 把 T1–T5 串成一条线（反思题）

问题：用不超过 5 句话，把 T1（三元组/滥用判定）→ T2（创建型）→ T3（结构型）→ T4（行为型）→ T5（架构与并发）串成一条「遇到问题怎么走」的决策链；指出哪一环是你最弱的，为什么。

## 四、代码任务题（4 道，代码通道，挂 Phase 6 载体）

判定标准：本机 `swift` CLI 跑通 + 对拍输出一致 + 学员逐行能讲 = 过。代码落 `代码/T6/`，输出贴回作答稿。

### Q1 选项目 + 写直觉版（载体 6.1）

任务：自选一个真实小项目（约 200–400 行），或使用默认项目：**任务清单 CLI**（增删改查 + 标签搜索 + 文件存储，约 250 行）。先写「直觉版」——用你最自然的方式写，不刻意套任何模式。提交前记录：你现在识别到哪些坏味道（至少 3 个）。

### Q2 对拍测试（载体 6.1）

任务：为直觉版写对拍基线：一组固定输入序列（增/删/改/搜/存/读），记录输出。重构后同一序列必须输出一致——这是「行为不变」的唯一证据。打印两组输出做 diff 证明。

### Q3 按需引入（载体 6.1）

任务：对 Q1 的坏味道逐个走「问题 → 约束 → 候选 → 记账 → 决策」，**只引入 2–3 个模式**（如存储后端用 Adapter/协议、搜索策略用 Strategy、命令操作用 Command 撤销、状态用 MVVM 化），每个引入都有记账与撤出条件。量化重构前后差异（行数/类型数/修改点/测试数）。

### Q4 收尾报告（载体 6.1）

任务：写 `T6-04-费曼草稿-收束重构.md` 收尾：哪些模式值得（数据）、哪些是负债（数据）、哪个撤出条件已触发、整线六轮你最该带走的三个结论。报告里必须能指向前序轮次的模型（如「这个决定来自 T1 M5」）。

## 五、验收规则

- 概念通道：6 题全过（允许批改后复攻）；代码通道：4 题全跑通 + 对拍一致。
- 任一通道未过 → 主题不记过关，缺口进台账（C3/C4）。
- 只引入模式不记账 = 该决定作废；对拍不一致 = 重构失败重跑。
