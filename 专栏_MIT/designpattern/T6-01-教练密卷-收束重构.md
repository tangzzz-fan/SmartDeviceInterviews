# T6-01 教练密卷：收束重构（仅教练分支，学员禁阅）

> 本文件含弱/中/强三级提示、评分要点与参考答案，只存在于教练分支 `feat/mit-dp-study`（dp-coach worktree）。题干同步到学员分支时严禁带入本文件。
> 提示使用纪律（C1/C2）：学员卡住先给弱提示；学员立刻想到答案说明提示太强，降级重出；直接要答案 → 拒给，反问「你的对拍测试在哪」。

## 一、概念题：提示梯与评分要点

### C1 重构的安全网是什么？没有测试的重构怎么进行？
- 弱提示：怎么证明「行为没变」？——同一输入，输出一致。这叫什么？
- 中提示：没有测试时，先建立「可观察行为基线」（录一组输入输出），再小步提交（每次重构一个提交，可回退）。
- 强提示：对拍测试 = 特征测试（记录当前行为，不管对不对，先锁住）；没有它，重构后「看起来一样但悄悄变了」无法发现。先补测试是风控不是教条。
- 评分要点：
  - 死记硬背典型：「重构前必须写单元测试。」（无基线思路）
  - 真懂特征：能说出特征测试/对拍基线 + 小步提交，解释为什么这是风控。
- 参考答案：安全网 = 对拍基线（同一输入序列输出一致）+ 小步提交；没有测试也能重构，但要先锁行为、每步可回退。

### C2 引入模式的完整决策路径？
- 弱提示：起点是「问题/坏味道」，不是「模式名」。候选模式排在记账前面还是后面？
- 中提示：路径：坏味道 → 问题/约束 → 候选（含内建承载）→ 记账（代价/撤出条件）→ 决策（引入/拒绝）。
- 强提示：演示：T6 项目里「存储直接写文件」→ 问题：换后端要改调用点；约束：CLI 无 UI、文件后端够用；候选：Adapter 协议；记账：多 1 协议 + 1 实现，换后端收益不确定 → 决策：可引入（收益明确）或拒绝（无换后端需求）。
- 评分要点：
  - 死记硬背典型：直接报「用 Adapter」，无过程。
  - 真懂特征：完整路径 + 真实改动 + 记账，且允许「拒绝」结论。
- 参考答案：路径完整即可；重点是把「候选」与「决策」分开——候选不承担正确性，记账才承担。

### C3 量化的维度有哪些？哪些不能量化但必须记录？
- 弱提示：可量化：行数、类型数、修改点、测试数、圈复杂度；不可量化：可读性、认知成本、演进风险。
- 中提示：为什么「不可量化」也要记？——因为决策理由里往往藏着不可量化的判断，不记录就成了「感觉」。
- 强提示：量化给数字，不可量化的给「判断 + 依据」；两者都进记账。缺数字 = 缺证据；只有数字 = 缺判断。
- 评分要点：
  - 死记硬背典型：「重构让代码更好了。」（无数字无依据）
  - 真懂特征：两类维度都列，能说清各自的作用。
- 参考答案：可量化维度给证据，不可量化内容（可读性/认知/演进）给判断依据；两者缺一不可。

### C4 模式的可逆性：什么情况下会撤？
- 弱提示：什么信号说明「当初的账算错了」？——约束变了、内建覆盖了、收益没兑现。
- 中提示：撤出成本怎么提前控制？——独立提交（可整体回退）、撤出条件写进记账。
- 强提示：三个撤出信号：约束变化（不再有该 Forces）、语言/框架内建覆盖（Combine/值语义等）、账算不平（间接层成本 > 收益）。引入时写「什么情况我会撤」。
- 评分要点：
  - 死记硬背典型：「模式引入后就一直用。」（无可逆意识）
  - 真懂特征：三个信号 + 撤出成本控制手段。
- 参考答案：约束变化 / 内建覆盖 / 账算不平 → 撤；控制手段 = 独立提交 + 记账里写明撤出条件。

### C5 毕业标准自评：一段「模式满满的代码」值不值？
- 弱提示：判定从哪开始？——每个模式先问「它的问题-约束真实吗」。
- 中提示：再问：账算平了吗？撤出条件是什么？叠了三个模式，每个都有独立理由吗？
- 强提示：判定清单：①每个模式有真实问题/约束；②每个账算平（收益 > 间接层）；③每个有撤出条件；④层数可数（3 层以上无记账 = 滥用）。
- 评分要点：
  - 死记硬背典型：「模式多 = 设计好。」（无判定）
  - 真懂特征：按清单逐条判定，敢于说「这代码是负债」。
- 参考答案：判定清单四问；模式叠加不必然好，能指出「哪个该撤」才算会。

### C6 把 T1–T5 串成一条线（反思题）
- 弱提示：遇到新代码/新需求，第一步看什么？——问题与变化点。
- 中提示：串起来：识别（T1 三元组）→ 创建/结构/行为分类（T2/T3/T4）→ 架构承载（T5）→ 记账决策（T1 M5）。
- 强提示：完整决策链：这是什么问题（变化点）→ 属于创建/结构/行为/架构哪层 → 候选模式 + 语言内建承载 → 记账（代价/撤出）→ 引入或拒绝 → 量化验证。最弱环自评要具体。
- 评分要点：
  - 死记硬背典型：复述六个主题名，串不起来。
  - 真懂特征：5 句话成链 + 诚实的弱环自评。
- 参考答案：成链即可；弱环自评要具体到「我在记账环节容易偷懒」这类真实判断。

## 二、争议焦点参考立场

- **D1 顺手重构**：本线纪律 = 重构独立提交、先对拍后记账；「顺手」= 无对拍无记账，是反模式。
- **D2 什么时候不重构**：能用、无需求驱动、风险大于收益 → 不重构也要记账；拒绝要有理由。
- **D3 毕业标准**：会认会写只是入门；毕业 = 能为「不引入」给出有据理由（拒绝能力）。

## 三、代码题：评分要点与提示

### Q1 选项目 + 写直觉版
- 评分要点：项目真实可跑（或默认任务清单 CLI）；直觉版完成；坏味道至少 3 个且都是「问题/约束」描述而非「这不好」。
- 参考答案要点：默认项目坏味道示例：存储硬编码文件（换后端要改调用点）、搜索逻辑写死（算法难换）、命令操作无撤销（行为不可回放）、状态散落（难测）。

### Q2 对拍测试
- 评分要点：固定输入序列 + 重构前后输出一致（diff 证据）；序列覆盖增删改搜存读。
- 参考答案要点：写一个 `runScenario()` 打印全部操作结果；重构前后各跑一次，输出文件 diff 为空即通过。

### Q3 按需引入
- 评分要点：只引入 2–3 个模式；每个引入有「问题 → 约束 → 候选 → 记账 → 决策」完整记录；量化真实（行数/类型数/修改点/测试数）；至少一个「拒绝」决定有理由。
- 参考答案要点：存储 → Adapter 协议（若换后端需求真实）；命令 → Command + 撤销栈（若撤销需求真实）；搜索 → Strategy（若算法多变）；其余坏味道记账后拒绝（约束不满足）。

### Q4 收尾报告
- 评分要点：数据说话（哪些值得/哪些负债）；撤出条件是否触发；整线三个结论具体；能指向前序模型（如「来自 T1 M5」）。
- 参考答案要点：报告结构：值得（数据）/ 负债（数据）/ 撤出触发 / 三个结论（如：先对拍再重构、记账防自我欺骗、拒绝也要理由）。

## 四、使用纪律

- 判分只认证据：对拍 diff、量化数字、记账记录缺一不可；「感觉更优雅」一律不算证据。
- 失真自查：只引入不记账、对拍不一致仍声称成功、收尾报告无数据 = 收束失败需重跑。
