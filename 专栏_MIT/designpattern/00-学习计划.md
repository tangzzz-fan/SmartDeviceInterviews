# MIT 三问攻坚：iOS 老手系统化设计模式 —— 学习计划

> 目标：学员（人设见 [[01-学员人设卡.md|01-学员人设卡]]）用 MIT 三问法把设计模式从「背名字」升级为「**识别问题 → 按需引入 → 拒绝滥用**」：能在 Swift/SwiftUI 语境下认出模式、说清取舍，并落地到 SwiftUI/Concurrency 工程。
> 方法基座：[[04-方法论基座-MIT三问与测试协议.md|方法论基座]]（自包含，与 Swift/Python 线同一份方法论）。
> 分支：教练分支 `feat/mit-dp-study`（对应 worktree `.worktrees/dp-coach`）与学员分支 `feat/mit-dp-study-student`（对应 worktree `.worktrees/dp-student`），双 worktree 协议见第三节。

## 一、原料策略

本线无外部教材依赖：设计模式是「既有工程词汇的再组织」，学员的 Swift/iOS 存量（protocol delegate、NotificationCenter、Combine、@Observable、static let、static func、@Environment、NavigationStack、actor）本身就是原料。教练按既有知识重建模型骨架，每轮模型与考点的 Swift 存量锚点见各 `T{n}-01` 文件头。

## 二、六主题与顺序

顺序逻辑：先学会「模式是什么、怎么读」，再进具体模式，最后收束到真实项目——T1 基座 → T2 创建型 → T3 结构型 → T4 行为型 → T5 架构与并发模式 → T6 收束重构。

| 序 | 主题 | 拷问重点 | Swift 存量锚点 |
|---|------|---------|------------|
| T1 | 模式基座 | 模式=问题-约束-解法三元组、GoF 四要素、语言内建优先、组合优于继承、滥用判定 | protocol delegate/闭包/Combine/@Observable 本来就是模式词汇 |
| T2 | 创建型模式 | Singleton / Factory / Builder / Prototype 的取舍；Swift 值语义下 Prototype=拷贝；Singleton 现代批评 | static func 工厂、static let 共享、值语义 |
| T3 | 结构型模式 | Adapter / Facade / Decorator / Proxy；协议组合 vs 继承 | extension 适配、类型包装、网络层封装 |
| T4 | 行为型模式 | Strategy / Observer / Command / Template Method；闭包与协议改写 | protocol delegate / NotificationCenter / Combine / @Observable / 闭包 |
| T5 | 架构与并发模式 | MVVM+状态管理、Coordinator、依赖注入、Actor 化；模式进入工程层 | UIKit MVC、@Environment、actor |
| T6 | 收束重构 | 真实小项目「先直觉写 → 按需引入 → 量化差异」 | 一个完整 Swift 项目 |

## 三、每主题执行流程（教练 + 学员双角色）

沿用四件套规范（[[04-方法论基座-MIT三问与测试协议.md|方法论基座]]），每主题产出：

1. **教练出题**（教练分支）：`T{n}-01-教练出题-<主题>.md`（题干：共识五模型 + 争议三焦点 + 概念六题 + 代码四题，含脚手架）与 `T{n}-01-教练密卷-<主题>.md`（弱/中/强提示 + 评分要点 + 参考答案，**仅教练分支/归档**）。
2. **学员作答**（学员分支）：闭卷作答 `T{n}-02-学员作答-<主题>.md`，每题自评三档；代码实跑，输出贴回作答稿。
3. **批改判定**：按密卷判 过关 / 半过（拆判分点）/ 未过；概念看推理链、代码看实跑输出。
4. **费曼写回**：`T{n}-04-费曼草稿-<主题>.md`（含语言内建对照小节），被问倒退回复攻。

**代码通道环境**：本线代码题用 Swift 脚本（`swift 代码/T{n}/Q*.swift` 顶层脚本直接跑）；T6 收束一个小型 SwiftUI 或 Swift CLI 项目。CLI 可验证的结论一律实跑；UI 类结论记「待真机验证」，不冒充。

## 四、执行纪律（照搬测试协议 C1–C5）

| # | 纪律 | 在本线中的含义 |
|---|------|----------------|
| C1 | 先弱提示 | 卡住先只定位「问题/约束」不给方向；立刻想到答案说明提示太强，降级重出 |
| C2 | 拒答代学 | 直接要答案 → 拒给，反问「你先识别出的问题是什么、约束是什么」 |
| C3 | 双通道强制 | 概念口述过关后必须追加代码任务，只有口述不算过关 |
| C4 | 台账如实 | 未过不得写「过关」，半过必须拆判分点；「模式引入记账」必须有真实数字或理由 |
| C5 | 产出落本目录 | 全部产出落 `MIT-DesignPattern-Migration/` 内，不直写外部 |

失败标准（失真即重跑）：学员全题全对（人设失效）；把 GoF 名字当答案背却讲不清问题/约束（模式识别失守）；代码全靠抄也能判过（C3 失守）。

## 六、执行节奏

- 每主题一轮闭环（出题 → 作答 → 批改 → 费曼），跑完记台账再开下一主题；未过缺口先复攻再前进。
- 前序主题的遗留观察项在后续主题点名回收（格式见 Swift 线 T5-03 第四节）。
- 模式线特有的节奏纪律：每轮代码题都要求「记账」——引入/拒绝模式都要有可复现的理由，不许凭感觉。
