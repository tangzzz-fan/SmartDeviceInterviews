## 一、概念题：提示梯与评分要点

### C1 Strategy 与「直接传闭包」的取舍？
- 弱提示：闭包能表达「一段行为」。什么场景闭包表达力不够？——需要多个相关行为、需要命名、需要被测试单独引用、需要状态。
- 中提示：一个「策略」如果是「一组相关操作」（validate + transform + retry），闭包参数要传几个？协议对象呢？
- 强提示：判断轴：单一行为 → 闭包；行为族 / 可命名 / 可复用 / 有状态 / 要身份 → 协议或策略对象。闭包是默认，协议是升级。
- 评分要点：
  - 死记硬背典型：「Strategy 必须用协议。」（没考虑闭包内建）
  - 真懂特征：能给判断轴，举真实例子，承认多数场景闭包就够。
- 参考答案：闭包承载单一行为（便宜、类型安全）；协议承载行为族/状态/可命名测试。先闭包，需要时升级。

### C2 Observer 的订阅寿命问题？
- 弱提示：NotificationCenter 忘 removeObserver 会怎样（野指针/崩溃）？Combine 忘存 cancellable 会怎样（立刻取消）？方向相反说明什么？
- 中提示：通知是「注册后一直活着直到移除」；Combine 是「不持有就释放即取消」。义务从「记得移除」变成「记得持有」。
- 强提示：`@Observable` 用依赖跟踪：视图在 body 里读到哪个属性就依赖哪个，状态变了只更新依赖者——把「订阅关系」从手动注册变成编译/运行期自动收集。
- 评分要点：
  - 死记硬背典型：「Combine 比通知好。」（没讲寿命义务转移）
  - 真懂特征：能对照两种「忘记」的后果，讲清义务从移除变持有，以及 @Observable 的自动依赖收集。
- 参考答案：通知忘移除 = 崩溃/泄漏；Combine 忘存 cancellable = 立即取消收不到事件；义务方向相反（移除 vs 持有）。@Observable 把注册改成自动依赖收集。

### C3 Command 的撤销怎么实现？闭包版缺什么？
- 弱提示：撤销需要什么——记住「上一个操作」以及「怎么把它退回去」。闭包能记住操作，能记住逆操作吗？
- 中提示：命令对象版有 `execute()` 和 `undo()` 两个方法、有身份（可入栈）；闭包只有一个动作，逆操作要另存。
- 强提示：撤销 = 栈 + 逆操作；闭包版要么另存逆闭包（成对管理，容易错），要么没有通用撤销。闭包回调是 Command 的轻量形态（动作即值，但无栈）。
- 评分要点：
  - 死记硬背典型：「用闭包写 Command 就行了。」（没讲撤销/队列/记录语义）
  - 真懂特征：讲清闭包缺「身份 + 逆操作 + 可入栈」，命令对象补什么。
- 参考答案：闭包是轻量 Command（执行即发生，无撤销）；命令对象有身份与 `undo()`，配栈实现撤销/重做/宏记录。

### C4 Template Method 与 Strategy 的分工？
- 弱提示：Template Method 的「骨架」在谁手里？Strategy 的「算法」在谁手里？
- 中提示：Template Method = 固定流程 + 覆写点（骨架在基类）；Strategy = 整个算法替换（骨架在策略里）。
- 强提示：分工：流程骨架固定、只替换某一步 → Template Method（继承/协议默认实现）；整段算法可换 → Strategy（组合/注入）。例：数据加载流程骨架固定 → Template；折扣算法整体可换 → Strategy。
- 评分要点：
  - 死记硬背典型：「Template Method 是继承，Strategy 是组合。」（只记实现，未讲分工）
  - 真懂特征：从「骨架位置」讲分工，举例正确。
- 参考答案：骨架固定、步骤可覆写 = Template Method；算法整体可替换 = Strategy。判断看「变的是某一步还是整段」。

### C5 delegate 的 Strategy / Observer 双重身份？
- 弱提示：delegate 方法有两种形态：返回一个值（决策）vs 通知你事件发生了（回调）。分别像哪个模式？
- 中提示：`shouldDoSomething`（决策）= Strategy；`didSomething`（事件通知）= Observer。
- 强提示：Swift 一个 delegate 协议同时装两种方法，所以它是混血；Swift 里拆法：决策类 → 协议或闭包属性；事件类 → 闭包回调或 Combine/AsyncSequence。
- 评分要点：
  - 死记硬背典型：「delegate 是 Observer。」（只记一面）
  - 真懂特征：能拆出 should/did 两面并分别对号 Strategy/Observer，给出 Swift 拆分方案。
- 参考答案：`shouldX`（决策）= Strategy；`didX`（事件）= Observer；delegate 是两者的混血。Swift 按方法形态拆分承载。

### C6 行为型选择轴：给一个真实变化点走完整决策路径？
- 弱提示：先把「变化点」写出来——是算法、状态、行为序列还是单步？
- 中提示：按 M5 轴对号：算法变 → Strategy；状态变 → Observer；行为要回放/撤销 → Command；步骤固定 → Template Method。然后问语言内建承载是什么。
- 强提示：完整路径 = 变化点 → 候选模式 → 内建承载（闭包/Combine/协议默认实现）→ 记账（问题-约束-代价）→ 决策。
- 评分要点：
  - 死记硬背典型：直接报模式名，无决策过程。
  - 真懂特征：走完整路径，至少一次「内建承载已覆盖 → 不引入模式」的结论。
- 参考答案：决策路径示例：支付折扣算法会变 → Strategy；登录状态多播 → Observer（Combine/@Observable）；用户操作要撤销 → Command；加载流程固定 → Template Method；单一小行为 → 闭包直写。

## 二、争议焦点参考立场

- **D1 Combine 与 Observer**：机制内建（@Published/sink）但义务没消失（寿命/取消/背压）；「用 Combine 就不用学 Observer」= 半过。
- **D2 闭包 vs 协议**：单一行为闭包优先；行为族/状态/身份用协议；站死一方都算半过。
- **D3 Template Method**：业务流程用协议默认实现；UIKit 生命周期等身份绑定场景继承合理；看骨架是否与类型身份绑定。

## 三、代码题：评分要点与提示

### Q1 Observer 三版对拍
- 评分要点：三版都可运行；寿命管理对照清楚（移除 vs 持有 vs 自动）；测试替换点说明白；打印证据。
- 参考答案要点：NotificationCenter 版要 `removeObserver`；Combine 版要 `store(in:)`（不存即取消）；手写协议版要显式 add/remove。`@Observable` 版自动依赖。

### Q2 Command 撤销栈
- 评分要点：命令栈 undo 可运行（execute 后 undo 恢复）；闭包版对比说明「为什么做不了通用撤销」（缺身份/逆操作）；打印证据。
- 参考答案要点：`protocol Command { func execute(); func undo() }` + `[Command]` 栈；闭包版需成对保存逆闭包，易错且无法通用。

### Q3 Strategy 重构
- 评分要点：策略表（协议 + 字典/数组）运行通过；新增策略不改调用方（打印证明）；if/else 版对照。
- 参考答案要点：`protocol DiscountStrategy` + `[String: DiscountStrategy]` 注册表；调用方查表调用。

### Q4 Template Method 对拍
- 评分要点：两版都可运行；修改点数量对比真实；可测试性结论明确。
- 参考答案要点：继承版加新流程要新建子类/改基类；协议默认实现版把步骤注入为协议实现，可独立测试；骨架函数（默认实现）只写一遍。

## 四、使用纪律

- 判分只认证据：概念看「变化点 → 模式 → 内建承载」推理链，代码看实跑输出与记账。
- 失真自查：用 Combine 写了 Observer 却讲不清寿命 = 半懂当过关，需重跑；只背模式名不讲 Forces = 识别失守。
