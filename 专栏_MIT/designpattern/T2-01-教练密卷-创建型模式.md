## 一、概念题：提示梯与评分要点

### C1 Singleton 的现代批评是什么？`static let shared` 解决了什么、没解决什么？
- 弱提示：先分清两件事——「只有一个实例」和「所有代码都能拿到它」。哪件事是共享，哪件事是唯一？
- 中提示：测试一个依赖 `CacheManager.shared` 的类，你打算怎么替换缓存？如果不替换，测试之间会互相污染吗？
- 强提示：`static let` 保证线程安全的唯一实例（编译器管）；不保证「这个实例没有共享可变状态」（开发者管）。批评三连：全局可变状态、测试不可替换、依赖隐式化。
- 评分要点：
  - 死记硬背典型：「单例是反模式。」（没拆开唯一实例与共享状态）
  - 真懂特征：能拆开「唯一」与「共享」；能说出测试污染机制；能给真实反例。
- 参考答案：`static let shared` 只解决「唯一 + 线程安全初始化」；可变状态仍全局共享、测试无法替换、依赖不进构造签名。反例：内存缓存不该是进程级单例，应注入到使用方作用域。

### C2 Factory Method / Abstract Factory / 静态工厂的区别？
- 弱提示：三个问题分别问：谁决定类型？决定一个还是一族？要不要子类参与？
- 中提示：`+paymentWithType:` 的调用方是谁、选择逻辑在哪、有没有子类？分别对应哪个？
- 强提示：静态工厂 = 一个类方法按参数返回；Factory Method = 由子类覆写决定（Swift 里常退化成协议默认实现）；Abstract Factory = 一族对象的创建接口。Swift 的 `static func make(type:)` 是静态工厂（选择逻辑在工厂里，不在子类）。
- 评分要点：
  - 死记硬背典型：「工厂就是 new 一个对象。」（不分三种）
  - 真懂特征：能区分三种的「决定权在哪」，能对号 Swift 写法。
- 参考答案：静态工厂（单方法按条件返回，Swift 最常用）；Factory Method（子类/协议实现决定，创建步骤延迟）；Abstract Factory（一族对象，接口家族）。Swift `static func make(type:)` = 静态工厂。

### C3 Builder 在 Swift 里什么时候仍值得用？
- 弱提示：Swift 构造一个对象有哪些内建手段？先列全，再说 Builder 还能补什么。
- 中提示：必选参数漏传、参数间有校验约束、产物要不可变——哪件事命名参数做不到？
- 强提示：命名参数/默认值吸收「可选参数」；可失败构造吸收「单条校验」；Builder 仍值得的两个必要条件：多个必选参数 + 参数间交叉校验 + 产物不可变（或组装顺序敏感）。
- 评分要点：
  - 死记硬背典型：「配置多就用 Builder。」（没先列语言内建）
  - 真懂特征：能说出语言内建吸收了什么、Builder 补的是什么，并给必要条件。
- 参考答案：Swift 内建吸收大部分（命名参数、默认值、`init?`、静态工厂）；Builder 只剩「交叉校验 + 不可变产物 + 顺序敏感组装」这类场景，且 Java 式 Builder 通常可以用「校验工厂」替代。

### C4 Prototype 在 Swift 里为什么「免费」？
- 弱提示：struct 赋值发生了什么？拷贝语义是「复制内容」还是「共享引用」？
- 中提示：struct 里的 Array 成员呢——CoW 下赋值廉价，但语义上是不是「独立副本」？
- 强提示：值语义 = 赋值即原型复制（语义保证独立）；CoW 只是实现优化，不改变语义。失效场景：引用类型成员（拷贝的是引用）、class 本身、需要「深拷贝树」时。
- 评分要点：
  - 死记硬背典型：「struct 复制快。」（把 CoW 当 Prototype 的理由，讲不清语义）
  - 真懂特征：从「赋值语义」而非性能讲 Prototype；能指出引用成员失效场景。
- 参考答案：Prototype 的模式意图（复制既有对象）在值语义下由语言默认实现；struct 赋值语义上就是独立副本。class 场景退回到手写深拷贝：浅拷贝只拷引用字段，深拷贝要递归复制。

### C5 「谁拥有生命周期」怎么决定创建方式？
- 弱提示：一个依赖的生命周期有哪几档？进程 / 作用域 / 每次调用？
- 中提示：进程级 → 单例/容器；作用域级 → 注入/Environment；按需 → 工厂。为什么作用域级用单例是错的？
- 强提示：判断轴 = 生命周期 + 是否需要替换（测试）。例子：全局挂一堆 `static let` 单例 → SwiftUI 里用 `@Environment` 或显式注入按 scene 作用域传递。
- 评分要点：
  - 死记硬背典型：「单例方便所以用单例。」（无生命周期维度）
  - 真懂特征：能按生命周期选创建方式，并说出作用域错配的后果（测试污染、并发共享）。
- 参考答案：生命周期决定创建方式——进程级资源用单例/容器；页面/模块作用域用注入或 `@Environment`；临时对象用工厂/直接 init。错配 = 不该共享的被共享。

### C6 为什么说「可替换性」是创建型模式的隐性收益？
- 弱提示：测试要替换的是什么——具体实现？还是创建它的代码？
- 中提示：如果创建逻辑散落在业务代码里（`if type == .x { return X() }`），测试怎么注入假实现？
- 强提示：创建与使用分离后，使用方依赖协议，测试可注入 mock；这是 Factory/DI 的隐性收益，也是「为什么单例难测」的反面。
- 评分要点：
  - 死记硬背典型：「工厂让代码解耦。」（无测试视角）
  - 真懂特征：能用「测试替换点」解释创建型模式的收益，给具体场景。
- 参考答案：创建型模式的隐性收益是「替换点」：使用方只依赖协议，测试可以注入假实现；单例没有替换点，所以难测。

## 二、争议焦点参考立场

- **D1 Singleton 禁用论**：合理立场是「无状态单例可用，有状态共享要论证」——唯一实例 ≠ 全局可变；适用边界（日志/系统服务）与替代方案（注入/Environment/actor）都要能说。
- **D2 DI vs Factory**：DI 管「谁持有依赖」，Factory 管「按条件选实现」；两者是装配层的两种工具，不是替代关系。
- **D3 Builder 存废**：先列语言内建（命名参数/默认值/可失败构造），Builder 只在交叉校验 + 不可变产物场景胜出；站死「必须用」或「绝不用」都算半过。

## 三、代码题：评分要点与提示

### Q1 Singleton 重构
- 评分要点：重构后行为一致（同 key 读写结果相同）；可变状态不再全局（注入实例或 actor 隔离）；能演示测试替换（注入假实例）；讲清「唯一」与「共享」的分离。
- 参考答案要点：`final class CacheManager { init(storage: ...) }` + 由使用方持有/注入；并发场景用 `actor CacheManager`；测试传独立实例即可隔离。

### Q2 工厂收敛
- 评分要点：调用方只依赖协议；新类型只需在工厂加一行（或注册表）；打印证明选择逻辑收敛；if/else 仍可接受时能说明理由（记账）。
- 参考答案要点：`protocol Payment { func pay() }` + `enum PaymentFactory { static func make(type:) -> Payment }`；调用方 `let p = PaymentFactory.make(type:)`。

### Q3 Builder vs 命名参数
- 评分要点：两版都可编译运行；必选参数在命名参数版是否编译期强制；校验位置讲清；结论与账一致。
- 参考答案要点：命名参数版必选参数天然编译期强制；Builder 版多一层且不增加安全性时 → 拒绝 Builder；若有交叉校验 → 用校验工厂而非 Builder。

### Q4 Prototype 深拷贝对拍
- 评分要点：打印证明浅拷贝共享、深拷贝独立；说明 struct 为什么在这个场景失效（class 成员）；手写深拷贝思路清楚。
- 参考答案要点：class 含引用成员 → 拷贝构造只拷引用（浅）；深拷贝需递归复制成员；class 的深拷贝要「显式声明可拷贝」，Swift 值语义是「默认可拷贝」。
