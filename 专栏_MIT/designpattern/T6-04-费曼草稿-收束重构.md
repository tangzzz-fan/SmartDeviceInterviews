# T6-04 费曼草稿：收束重构（示例）

> **示例文件**：本文件演示「整线收束的费曼/毕业报告」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 行为不变、结构改善**：重构的证据是对拍 diff——同一输入序列，前后输出一致。没有对拍的重构是赌博。
- **M2 顺序：问题 → 约束 → 候选 → 记账 → 决策**：禁止先选模式再造问题。
- **M3 量化防自我欺骗**：行数、修改点、测试数是证据；「更优雅」不是。
- **M4 模式可逆**：每个引入写撤出条件；独立提交让撤出便宜。
- **M5 收束 = 肌肉记忆**：识别 → 记账 → 决策 → 量化验证，一条链自动跑。

## 二、整线收束对照（我拿走的）

| 轮 | 一句话收获 |
|----|-----------|
| T1 | 先问问题与约束，再对模式名 |
| T2 | `static let` 只保证唯一；生命周期决定创建方式 |
| T3 | 包装要有真实变化点；Proxy 控访问、Decorator 加职责 |
| T4 | 每个订阅能回答「谁持有、活多久」 |
| T5 | 架构是整体形状；actor 可重入不是锁 |
| T6 | 没有对拍与记账的引入 = 赌博 |

## 三、收尾报告（模拟数据）

- **值得引入**：存储 Adapter（换后端需求真实，改动点从 12 处收敛到 1 处）；命令撤销栈（撤销需求真实，新增 18 行换 undo 能力）。
- **负债**：搜索 Strategy（只有一种策略，间接层 3 个类型换 0 收益）——已按撤出条件移除。
- **撤出触发**：Q4 曾因「为凑模式」引入的观察者总线，量化后账算不平，复攻中撤掉。
- **三个结论**：① 先对拍再重构（来自 T6 M1）；② 记账防自我欺骗（来自 T1 M5）；③ 拒绝也要有理由（来自 T1 M5 / T6 争议 D3）。

## 四、60 秒讲稿

「六轮下来我学到的最重要一件事：设计模式不是知识，是决策。识别问题、记账、选承载、量化验证——这条链我以后写任何新代码都会跑一遍。Swift 把很多模式变便宜了，但便宜不是免费；没有变化点的抽象就是负债。毕业标准不是能背出 23 个名字，是能在代码里指出：这个模式解决什么、代价是什么、什么时候撤。能做到这三点，MIT 方法才算真的学会了。」
