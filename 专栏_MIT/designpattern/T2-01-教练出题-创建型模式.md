# T2 教练出题集：创建型模式

> 学员人设：Swift/SwiftUI 开发者（见 [[01-学员人设卡.md]]）；预期在「Singleton 万能化、把共享实例当单例、Prototype 仍按 class 深拷贝写、创建逻辑用 if/else 堆」上暴露漏洞。
> 挂靠：`static let` 单例、`static func` 工厂、值语义、`actor`、`@Environment` 依赖注入。
> 使用纪律：学员卡住按「弱→中→强」逐级给提示，禁止跳级；直接要答案 → 拒答并反问「这个问题里谁是创建者、谁拥有生命周期」（C1/C2）。提示与评分要点在密卷（仅教练分支），本文件是题干版。

## 一、共识：5 个核心心智模型

| # | 模型 | 一句话骨架 | Swift 存量锚点 |
|---|------|-----------|------------|
| M1 | Singleton 是「全局共享」的一种选择，不是默认 | 共享状态与唯一实例是两件事；`static let shared` 只保证唯一实例，不保证无共享可变状态；现代批评：全局可变、测试难、隐式依赖 | `static let shared` 人人会用，人人没想过替代 |
| M2 | Factory 是「创建逻辑与使用逻辑分离」 | 调用方只认协议不认具体类型；Factory Method（子类决定）vs Abstract Factory（一族对象）vs 静态工厂（最轻） | `static func make(type:)` |
| M3 | Builder 是「参数太多的构造」的解法 | Swift 命名参数 + 默认值已吸收大部分；Builder 只剩「必选参数校验 + 不可变产物」时才有价值 | struct 的 init 长参数列表、配置类型 |
| M4 | Prototype = 复制既有对象 | Swift 值语义让 struct 拷贝免费（拷贝即原型复制）；class 才需要手写深拷贝 | class 的手写深拷贝 |
| M5 | 创建型模式都要回答「谁拥有生命周期」 | 单例=进程级、注入=作用域级、工厂=按需；选错 = 测试与并发灾难 | 项目里 `static let` 单例到处飞，没人记账 |

学员自检要求：合上表复述 M1–M5，并各举一个自己项目里的创建场景。

## 二、争议：专家吵得最凶的 3 个焦点

**D1 Singleton 该不该被「禁用」？**
- 正方最强论据：全局可变状态是测试与并发的头号敌人；现代 Swift 里 `@Environment`、actor、显式注入都能替代，Singleton 是「偷懒的依赖」。
- 反方最强论据：真正进程级的资源（日志、数据库连接、系统服务）本来就是单例；为反对而反对会造出「到处传参」的噪音。
- 对迁移者的意义：考点不是「用不用」，而是「能否说出适用边界」——唯一实例 ≠ 全局可变，无状态单例 ≠ 有状态单例。

**D2 依赖注入是否「取代」了创建型模式？**
- 正方：DI 让创建逻辑集中在装配层，Factory 的「创建与使用分离」目标被 DI 容器直接实现。
- 反方：DI 解决的是「谁持有依赖」，Factory 解决的是「按条件创建哪个实现」——两者回答不同问题，工厂仍是 DI 的装配手段之一。
- 对迁移者的意义：区分「生命周期管理」（DI）与「选择实现」（Factory），别把两件事混成一个。

**D3 Swift 里 Builder 还有存在价值吗？**
- 正方：复杂配置（必选 + 可选 + 校验 + 不可变）用命名参数表达力不够，Builder 能强制编译期校验。
- 反方：Swift 的命名参数、默认值、`static func` 工厂、`init?` 可失败构造已覆盖 95% 场景；Builder 是 Java 时代的遗产。
- 对迁移者的意义：先列语言内建手段，Builder 是最后的选择，不是默认。

## 三、概念拷问题（6 道，口述通道）

判定标准：能讲出「为什么」并迁移到新场景 = 过；只能复述定义 = 不过。**每题都要有「问题-约束」维度，只背名字不算回答。**

### C1 Singleton 的现代批评是什么？`static let shared` 解决了什么、没解决什么？

问题：说出 Singleton 作为「全局共享」的完整代价（至少三点：可变状态、测试、隐式依赖），然后解释 `static let shared` 到底保证了什么、不保证什么。给一个「看似单例、其实不该是单例」的真实例子。

### C2 Factory Method / Abstract Factory / 静态工厂的区别？

问题：分别说出三种「工厂」解决的问题差异（谁决定类型 / 决定一族还是单个 / 有没有子类参与），然后判定 Swift 的 `static func make(type:)` 属于哪一种、为什么。

### C3 Builder 在 Swift 里什么时候仍值得用？

问题：列出 Swift 语言内建手段（命名参数、默认值、可失败构造、静态工厂）各自吸收了 Builder 的哪部分工作；然后给出「Builder 仍值得用」的两个必要条件（必选参数校验、不可变产物）并举例。

### C4 Prototype 在 Swift 里为什么「免费」？

问题：从值语义出发解释为什么 struct 拷贝天然实现 Prototype；然后说出什么时候「免费」失效（引用类型成员、需要深拷贝、class 场景），并对比 class 场景的手写深拷贝。

### C5 「谁拥有生命周期」怎么决定创建方式？

问题：给出判断轴（进程级 / 作用域级 / 按需创建），并各配一个创建方式（Singleton / 注入 / Factory）；举一个「static let 单例」在 SwiftUI 里应该改成 `@Environment` 或显式注入的例子，说明改动收益。

### C6 为什么说「可替换性」是创建型模式的隐性收益？

问题：从测试角度解释：创建逻辑与使用逻辑分离后，测试能替换什么、不能替换什么；给一个「工厂让测试变容易」的具体场景。

## 四、代码任务题（4 道，代码通道，挂 Phase 2 载体）

判定标准：本机 `swift` CLI 跑通 + 输出符合预期 + 学员逐行能讲 = 过。代码落 `代码/T2/`，输出贴回作答稿。

### Q1 Singleton 重构（载体 2.1）

任务：写一个 Swift 风格的「static let 有状态单例」（如内存缓存 + 可变字典），然后重构为显式注入（构造传入）+ 隔离（actor 或值类型），打印证明：重构前后行为一致、并发安全边界清晰、测试可以直接替换实例。

脚手架：
```swift
final class CacheManager {
    static let shared = CacheManager()
    private var storage: [String: String] = [:]   // 全局可变状态
    func get(_ key: String) -> String? { storage[key] }
    func set(_ key: String, _ v: String) { storage[key] = v }
}
```

### Q2 工厂收敛（载体 2.1）

任务：把一段 if/else 创建逻辑（按类型返回不同实现）收敛为静态工厂 + 协议，打印证明调用方只依赖协议、新类型只需在工厂加一行。

### Q3 Builder vs 命名参数（载体 2.1）

任务：同一个「复杂配置对象」（3 个必选 + 3 个可选 + 1 条校验规则），写两版：命名参数版 vs Builder 版。对比：可读性、必选参数是否编译期强制、校验在哪发生。给出你的结论（哪版更适合这个场景）。

### Q4 Prototype 深拷贝对拍（载体 2.1，T1 Q3 深化）

任务：class 场景的 Prototype：一个 class 含引用类型成员，写手写深拷贝（`copy()` 方法，注释说明为什么不能靠 struct），打印证明「浅拷贝共享、深拷贝独立」；并说明为什么这个场景不能靠 struct 白拿。
