# T4-04 费曼草稿：行为型模式（示例）

> **示例文件**：本文件演示「脱稿重推 + 语言内建对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 Strategy 是算法可替换**：变化点是算法。Swift 里先问闭包够不够，行为族/要命名/要测试再上协议。
- **M2 Observer 是多播 + 寿命义务**：一对多、解耦。义务从「记得移除」（通知）变成「记得持有」（Combine）；@Observable 把注册变成自动依赖收集。
- **M3 Command 是行为对象化**：闭包是轻量版（执行即发生）；要撤销/排队/记录就得有身份 + 逆操作 + 栈的命令对象。
- **M4 Template Method 是骨架固定**：变的是某一步。流程骨架用协议默认实现，生命周期钩子类场景继承仍合理。
- **M5 变化点决定模式**：算法变→Strategy，状态变→Observer，行为要回放→Command，步骤固定→Template Method。

## 二、语言内建对照

| Swift 惯用写法 | 对应模式 | 注意 |
|---------------|---------|------|
| protocol delegate（should/did） | Strategy + Observer | 拆两面 |
| 闭包参数 | Command / Strategy | 无撤销栈 |
| NotificationCenter | Observer | 忘移除 = 崩溃 |
| Combine / @Observable | Observer | 不存即取消；自动依赖 |
| 协议默认实现 | Template Method | 生命周期钩子仍用继承 |

## 三、一个例子讲到底

登录模块：`LoginDelegate` 里混着「要不要自动登录」（决策）和「登录完成」（事件）。拆成：自动登录策略用闭包属性注入；登录事件用 Combine 的 `@Published` 广播，页面 `store(in:)` 持有。改完每个订阅都能回答「谁持有、活多久」。

## 四、60 秒讲稿

「行为型模式的选择轴是变化点：算法变用 Strategy，状态变用 Observer，行为要回放用 Command，步骤固定用 Template Method。Swift 里闭包和 Combine 把很多实现变便宜了，但便宜不是免费——闭包命令没有撤销栈，Combine 订阅不存就取消，通知忘移除就崩溃。真正要练的不是会写，是每写一个订阅都能回答：谁持有它、它活多久、谁负责了结。」

## 五、自检三问

1. 被问「Combine 是不是就不用学 Observer 了」能答（不是，寿命/背压仍是义务）。
2. 能讲给同事听：用了登录模块例子。
3. 诚实自查：C2 的「不存即取消」是我从「知道要 store」升级到「理解机制」的，属于复攻收获。
