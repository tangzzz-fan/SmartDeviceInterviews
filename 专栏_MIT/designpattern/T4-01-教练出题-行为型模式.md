# T4 教练出题集：行为型模式

> 学员人设：Swift/SwiftUI 开发者（见 [[01-学员人设卡.md]]）；本主题是学员的 Swift 主场（protocol delegate/NotificationCenter/Combine/闭包写得多），预期在「用 Combine 写 Observer 就以为懂了（没管订阅寿命）、闭包版 Command 以为等价（没讲撤销语义）、delegate 双重身份说不清」上暴露漏洞。
> 挂靠：protocol delegate、NotificationCenter、Combine、@Observable、闭包；语言内建协议、闭包、AsyncSequence。
> 使用纪律：学员卡住按「弱→中→强」逐级给提示，禁止跳级；直接要答案 → 拒答并反问「这个行为的变化点在哪」（C1/C2）。提示与评分要点在密卷（仅教练分支），本文件是题干版。

## 一、共识：5 个核心心智模型

| # | 模型 | 一句话骨架 | Swift 存量锚点 |
|---|------|-----------|------------|
| M1 | Strategy 是「算法可替换」 | 变化点 = 算法/行为；Swift 里函数参数或协议都行；protocol delegate 的「策略面」就是 Strategy | protocol 回调、闭包参数 |
| M2 | Observer 是「状态变化多播」 | 一对多、解耦；订阅寿命必须显式管理；NotificationCenter/Combine/@Observable 都是承载 | NotificationCenter、Combine、@Observable |
| M3 | Command 是「行为对象化」 | 可排队/撤销/记录；闭包是轻量版，撤销栈要显式对象 | 闭包属性、UIAction |
| M4 | Template Method 是「骨架固定、步骤可覆写」 | 继承 + 子类覆写；协议默认实现 + 组合注入替代 | 协议默认实现、生命周期钩子 |
| M5 | 行为型选择轴：变化点决定模式 | 算法变 → Strategy；状态变 → Observer；行为要回放/撤销 → Command；步骤固定只替换某步 → Template Method | 先问「什么在变」，再选模式 |

学员自检要求：合上表复述 M1–M5，并各举一个自己项目里的行为场景。

## 二、争议：专家吵得最凶的 3 个焦点

**D1 Combine 是否让 Observer 模式「消失」？**
- 正方：`@Published` + `sink` 内建了订阅/发布，手写 Observer 是重复造轮子。
- 反方：Combine 只是 Observer 的一种承载；理解「订阅寿命、背压、取消」才能用好它——机制内建不等于心智内建。
- 对迁移者的意义：考点是「内建机制解决了什么、还剩什么义务」（寿命、多播、背压仍是开发者的）。

**D2 行为参数化：闭包还是协议？**
- 正方：Swift 闭包是「函数即值」，Strategy/Command 的轻量版闭包就够了，协议对象是样板。
- 反方：需要多个相关操作、需要可命名/可复用/可测试、需要身份（如撤销栈入栈）时，协议/对象仍有价值。
- 对迁移者的意义：判断轴 = 单一行为 vs 行为族 + 是否需要状态/身份；先列闭包，需要时升级协议。

**D3 Template Method 在 Swift 里该用继承还是协议默认实现？**
- 正方：协议默认实现 + 组合注入，避免继承树；Swift 官方倾向组合。
- 反方：生命周期类钩子（`viewDidLoad`、`onAppear`）本身就是继承/回调约定，硬改组合反而绕。
- 对迁移者的意义：看「骨架是否与类型身份绑定」（UIKit 生命周期 = 继承；业务流程 = 协议默认实现）。

## 三、概念拷问题（6 道，口述通道）

判定标准：能讲出「为什么」并迁移到新场景 = 过；只能复述定义 = 不过。**每题都要有「问题-约束」维度，只背名字不算回答。**

### C1 Strategy 与「直接传闭包」的取舍？

问题：什么时候「函数参数 / 闭包」就够（Strategy 的轻量版），什么时候需要协议 / 策略对象？给出判断轴（单一行为 vs 行为族、是否需要可命名/可测试/有状态），并用你的一个例子说明。

### C2 Observer 的订阅寿命问题？

问题：NotificationCenter 的 `addObserver` 忘移除 vs Combine 的 `sink` 返回值不存——两个「忘记」的后果分别是什么、机制差异在哪？`@Observable` 的依赖跟踪是怎么解决「谁该更新」的？

### C3 Command 的撤销怎么实现？闭包版缺什么？

问题：用闭包实现「一个操作」很便宜；但要支持撤销（undo 栈）时，闭包版缺了什么？命令对象版怎么补（逆操作 / 状态快照 / 入栈）？闭包回调与命令对象什么关系？

### C4 Template Method 与 Strategy 的分工？

问题：两者都是「固定流程 + 变化点」，区别在哪（骨架与步骤的位置、继承 vs 组合）？给一个「该用 Template Method 却被写成 Strategy」或反过来的例子。

### C5 delegate 的 Strategy / Observer 双重身份？

问题：delegate 什么时候像 Strategy（把决策交给调用方）、什么时候像 Observer（回调通知事件）？Swift 里为什么一个机制身兼两职？Swift 里你会怎么拆（协议回调 vs 闭包 vs Combine）？

### C6 行为型选择轴：给一个真实变化点走完整决策路径？

问题：从你项目里选一个「行为会变」的场景，按 M5 的轴走一遍：变化点是什么 → 候选模式是什么 → 语言内建承载是什么 → 最终选择与记账。

## 四、代码任务题（4 道，代码通道，挂 Phase 4 载体）

判定标准：本机 `swift` CLI 跑通 + 输出符合预期 + 学员逐行能讲 = 过。代码落 `代码/T4/`，输出贴回作答稿。

### Q1 Observer 三版对拍（载体 4.1）

任务：同一个「登录状态变化」通知场景，写三版：NotificationCenter 版、Combine `@Published` + `sink` 版、手写观察者协议版。对照：订阅寿命管理、移除/取消义务、测试替换点。打印证据。

### Q2 Command 撤销栈（载体 4.1）

任务：实现一个带 undo 的编辑器命令：`protocol Command { func execute(); func undo() }` + 命令栈；再写「闭包版」做对比，说明闭包版为什么做不了通用撤销。

### Q3 Strategy 重构（载体 4.1）

任务：把一段 if/else 算法分支（如不同支付方式的折扣计算）收敛为策略表（协议 + 数组/字典），打印证明「新增策略不改调用方」。

### Q4 Template Method 对拍（载体 4.1）

任务：同一个「数据加载流程」（校验 → 拉取 → 缓存 → 回调），写两版：继承版（基类 + 子类覆写）vs 协议默认实现版（骨架函数 + 注入步骤）。对比修改点数量与可测试性。
