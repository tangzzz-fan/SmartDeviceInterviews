# T5 费曼草稿：我用自己的话讲一遍性能这件事

> 全过后费曼写回（流程第四节）。视角：学员第一人称，讲给一个跟我一样的 OC/UIKit 性能老手听。这是五主题的收束篇——每个模型都尽量勾连回 T1–T4 亲手验过的证据。
> 判定背书见 [[T5-03-批改与判定-性能优化整合.md|T5 批改]]；代码证据在 `代码/T5/`（Swift 6.3.3 实跑，Q4 过 Swift 6 typecheck）。

## 一、一句话版本

**性能方法论一步没变——度量先于优化、分层定位、同口径复测；变的是指标对象：帧成本拆成「重算×diff×渲染」、Identity 是 diff 的身份证（M2），失效的爆炸半径由依赖粒度决定（M3），并发世界的两笔新账是 hop 与排队（M4），泄漏换了形态没消失（M5）。老手艺全带得走，旧直觉有一半会骗你。**

## 二、五个骨架，逐个讲

### 1. 度量先于优化：方法论是存量，指标清单是新账（M1）

这是唯一一条我闭眼能讲的——Time Profiler、Allocations、卡顿打点、先拿数据再动刀。本轮学到的不是新方法，是**新指标清单**：body 重算次数、diff 规模、hop 次数、取消延迟、失效通知次数。
但 M1 在本轮反咬了我两口，都是真学费：
- Q2 我第一版**结论先行**——预设「actor 比锁慢几十倍」，数据出来差距在完全错的地方（actor vs NSLock 仅 ~1.3x，真正数千倍的差距在 hop 次数上）。度量派老手在新世界翻的车，恰恰是「带着旧预设去看新数据」。
- Q2/Q3 都跑在 swift CLI 解释器里，绝对值被解释开销污染——**基准结论必须连同测量环境一起声明**，否则就是把噪声当结论。Instruments 类真机数据我老老实实全记了「待真机验证」，五主题守下来的 C4 纪律在这里是护身符。

### 2. 帧成本三段 + Identity 是身份证（M2）

一帧的预算（16.6ms）花在三段：body 重算 → diff → 渲染。治理手段对位：**LazyVStack 治渲染段**（懒在渲染与布局，不在失效——可视区内的行照样重算）、**equatable 治 diff 段**（输入相等短路掉子树的重算+深入 diff）、**body 瘦身治重算段**（前提是 body 里没塞格式化/排序这种重活——「body 便宜」在这些场景是骗人的）。
Identity 是 diff 的身份证，这是 reuseIdentifier 的声明式转世。Q1 模拟器把三档现场全打出来了：
- 稳定 id 头部插入：新增 1、复用 1000，代价 1；
- 下标当 id：1000 行全判内容变更——**第一现场是「张冠李戴」不是重建**，挂在行上的局部状态还会跟着身份错配（这是我预期被数据修正的一课）；
- 每次渲染换 UUID：内容一字未动也 1000 删 1000 建——身份变 = 推倒重建。
List 的复用「形似而层不同」：行视图是值不需要复用，复用发生在底层 cell 承载层。

### 3. 失效的爆炸半径：从对象级广播到属性级追踪（M3）

T4 Q2 量过 objectWillChange 的对象级广播，本轮 Q4 段三把两代底座的账并排算清了：两属性各改 3 次，只关心 a 的依赖方——ObservableObject 陪跑 **6 次**失效（改 b 也广播），@Observable 只失效 **3 次**（改 b 无感）。爆炸半径从「对象」缩到「属性」。
有个勾连我自己觉得妙：KVO 本来就是属性级 did 语义——**@Observable 是回到属性级，@Published 的对象级广播才是这条路上的反常一站**。旧直觉这次没骗我，反而帮我看清了「新 vs 旧」叙事的偏差。
选型规则（D2 收口）：机制上 @Observable 赢；工程上按部署版本（iOS 17+）与管道需求定——要防抖/节流管道还得回 Combine（@Observable 无内建 publisher）。渲染层真机失效次数欠着，台账有记。

### 4. 并发世界的两笔新账：hop 与排队（M4）

线程被收走了，换来两笔新账。
**hop 账**：一次 actor 调用 = 离开当前上下文 + 调度到目标执行器 + 排队（actor 忙时）。单次不可怕，可怕的是 N×hop——Q2 实锤：同样 20000 次写入，逐次 await 6346ms、批量一次 0.67ms，**差出 9529 倍**。批量化不是微优化，是数量级决策。收敛三板斧：批量化、热路径移进隔离域、nonisolated 豁免只读。表述边界我自己划：9529 倍是解释器里的相对关系，编译产物真机倍数记待真机验证。
**取消账**：cancel 只翻标志位，不杀正在跑的代码——Q3 三级梯度：每圈检查 10.3ms 停、批检 1145ms 停、不检查 28.5 秒（≈ 剩余半程照跑完）。密度原则有了可操作版：**取消延迟上限 ≈ 单批跑完的时间**，批大小就是延迟预算的旋钮；检查点不是免费的（每圈查全程慢 ~23%），按停止时延预算选密度。`.task` 把「任务该活多久」答给了视图寿命，手动 Task 自己答——寿命义务从 T4 C1 的凭证一路跟到这里。

### 5. 泄漏换脸：值语义是红利，不是免死金牌（M5）

总量变少、形态变刁。值语义+ARC 收走了「共享可变忘了释放」这类堆压力，但循环引用这个根一天不下岗。新栈三场景与排查手段：
1. **闭包捕获环**——老账新还，[weak self] + deinit 打点（老手艺直接迁移）；
2. **凭证长寿**——T4 C1 翻面：「不存即取消」反过来是「存进永不 deinit 的持有者 = 订阅永生」；
3. **Task 泄漏**——Task 闭包强引 self、self 强引 Task，形状和 UIViewController 持 block 一模一样。
同时破除一条新迷信：「struct 一定省内存」——T1 Q2 验过，嵌套引用类型成员时拷贝不深，struct 数组里装 class 拷的还是指针。

## 三、争议题我的立场（讲给同行听）

- **D1 规则先行 vs 度量先行**：不站边，站**分层**——规则清单当「嫌疑人名录」（LazyVStack、稳定 id、少 GeometryReader），度量数据当「判决书」。Q1 就是活例子：清单会说「下标当 id 导致重建」，实测才知道第一现场是张冠李戴。没有清单的度量瞎，没有度量的清单是玄学。
- **D2 @Observable 默认底座？**：有实验背书的答案（见 M3）——部署目标 ≥ iOS 17 且不需要内建 publisher 管道的新模块，@Observable 直接上；存量 ObservableObject 不为换而换，失效次数实测超标再动刀。
- **D3 Combine 调试成本算不算隐性性能债**：算，进选型账本第二栏。T4 三轴判定管能力账，本轮补维护账。工程结论：管道装配时顺手埋 print()/时间戳/计数——调试成本前置到装配期，这是声明式付的税里可以报销的部分（T4 Q1 要是没打点，retry 语义我到今天还在猜）。

## 四、迁移对比小节（UIKit 性能调优 ↔ 新栈性能，固定骨架）

| 维度 | OC + UIKit（旧世界） | Swift/SwiftUI/Concurrency（新世界） | 迁移要点 |
|------|---------------------|-----------------------------------|---------|
| 方法论 | Instruments + 打点，先数据后动刀 | 完全不变 | 方法论是存量资产，全盘带走 |
| 指标对象 | 帧率、cell 复用率、离屏渲染、主线程耗时 | body 重算次数、diff 规模、hop 次数、失效通知次数 | 新指标清单要重学，工具（Time Profiler/Allocations）继续用 |
| 列表性能 | reuseIdentifier 手发身份证 | Identity 框架推断，显式 id 可覆盖 | 身份证稳定是两代共同铁律；下标当 id/UUID 当 id 是新栈特有的翻车姿势 |
| 复用机制 | cell 复用（你写） | 行视图是值不复用，底层 cell 承载层复用（框架管） | 「形似而层不同」——别拿 dequeueReusableCell 心智找 SwiftUI 对应 |
| 状态失效 | 手动 reload/setNeedsLayout，指哪打哪 | objectWillChange 对象级广播 → @Observable 属性级追踪 | 失效粒度是选型账；KVO 的属性级直觉在 @Observable 上复活 |
| 并发成本 | 线程数、锁等待、QoS | hop、排队、检查点密度 | 「别阻塞主线程」升级为「别用 N×hop 和长占用污染隔离域」 |
| 取消语义 | GCD 无原生取消（NSOperation 有） | 标志位 + 检查点协作，结构化传播 | 取消延迟由检查点密度决定；.task 把寿命答给视图 |
| 泄漏形态 | 循环引用、delegate 忘 weak、block 持 self | 同款 + Task 持有环 + 订阅凭证长寿 | deinit 打点老手艺复用；多查「该死的任务和订阅死了吗」 |
| 基准测试 | 多轮、控变量、看稳态 | 同款 + 测量环境声明（解释器 vs 编译产物） | 结论先行是新世界的新型翻车姿势——先读数据再下笔 |
