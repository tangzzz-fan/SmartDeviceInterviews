## 二、复攻记录

**C2 复攻**（Q1 数据回填 + 教练追问「你手写的 debounce 跟 Combine 的语义差在哪」）：

> 补答：手写 debounce 终版是推模型：reader 任务消费源流写「最新值+时间戳」，emitter 按 10ms 时钟轮询「静默够不够一个窗口」——新值来了时间戳重置（续期），跟 Combine 的「最后一次收到值 + 窗口到期」是同一语义的轮询实现（检查粒度 10ms ≪ 窗口 80ms）。我最初押的「单次超时即判静默」是错的：那是 throttle 的亲戚不是 debounce。retry 更朴素：循环试 n 次、catch 记最后一个错、**最后一次仍失败要抛出去**——第一版只 break 不 throw，失败被吞成静默成功，对拍才暴露。merge 归属我不再押：AsyncAlgorithms 有（CLI 无外部包，记待真包验证）；combineLatest 同记。share 维持挂账：多播重设计我给不出方案，诚实不变。

判定：debounce 续期语义与轮询实现讲透、retry 失败路径边界亲历、拉/推模型的结构取舍（撞墙④）自己复盘出、押错的 merge 改为「待真包验证」不硬撑 → **C2 复攻过关**。

**C4 复攻**（Q2 数据回填 + 教练追问「onChange 回调里你读到的到底是新值还是旧值」）：

> 补答：旧值——这是 Q2 撞墙⑤探针（/tmp/obs_probe.swift）定位的：withObservationTracking 的 onChange 在 **willSet 时刻同步触发**，此刻读属性拿到的还是旧值；所以回调内只能标脏+重挂，新值由「重挂后的 access 读」落账，最后一笔靠 finish() 冲刷——不冲刷它永远悬着（旧世界 cancellable 不会替你翻的新账）。9:3 的账现在能算全：旧版 objectWillChange 是写前广播，query 3 次 + noise 3 次 + **results 自己写入 3 次**都算广播 = 9；新版属性级只追踪读过的 query = 3。private(set) 那道墙我守对了：观察回调在类外 append 被拦，正解不是放宽保护，是把管道行为收进 VM 的 recordResult()——接口不放宽，保护语义保留。

判定：willSet 语义有探针实证、落账点两处讲清、9:3 的账逐项算全、private(set) 的处置是「收进去」不是「放开」 → **C4 复攻过关**。T4 遗留的 @Observable 对比在 T5 量过爆炸半径、本轮补上「管道搬家」的工程实体，两代底座的账结清。

**C6 复攻**（Q4 数据回填 + 教练追问「你首轮说 AsyncPublisher 订阅是 cancellable 语义——跑出来还是这样吗」）：

> 补答：前提先翻了：`AsyncPublisher(stream).sink` 根本编译不过——AsyncPublisher 是 Publisher→AsyncSequence 方向的桥，跟 .values 同向，**反向桥（async→Combine）标准库没有现成件**。我手搭了一座：Task 泵流把 AsyncStream 的件倒进 PassthroughSubject，sink 照常订阅；泵 Task 的取消归 disconnect 手动管，sink 凭证归 cancellable——旧世界的义务没免，还多了一份泵 Task 的。寿命归属修正版：values 归消费循环（结构化）；手搭反向桥归 cancellable+泵 Task（双份旧世界义务）。缓冲不对称是这轮最值钱的对照：热 subject 先发后挂丢 3 收 1，AsyncStream 先发后接丢 0——**丢件归责先查桥有没有缓冲，再查谁先就位**。

判定：反向桥真相有编译错误实证、手搭桥寿命双义务讲清、缓冲不对称用反例对照量出、首轮现推被证伪后主动修正不护短 → **C6 复攻过关**。

**代码通道复攻确认**：Q1–Q4 的撞墙记录（4+5+7+3 处）全部写入 `代码/T6/` 对应文件头注释；教练独立复跑四题输出一致（Q1 对拍序列一致、Q2 的 9:3 与行为等价成立、Q3 双侧判定与反例计数成立、Q4 双桥 0 丢件与缓冲不对称成立）→ **Q1–Q4 复攻过关**。
