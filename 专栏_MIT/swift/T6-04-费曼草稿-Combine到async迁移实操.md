# T6 费曼草稿：我用自己的话讲一遍「把半生不熟的 Combine 换成 async」

> 全过后费曼写回（流程第四节）。视角：学员第一人称，讲给一个跟我处境一样的人听——纯 Swift 写过完整项目、Combine 用过但不多、正要迁 SwiftUI + Concurrency。这轮不是学 Combine，是**存量替换工程**：把我自己写过的东西换成新形态，还不许弄丢行为。
> 判定背书见 [[T6-03-批改与判定-Combine到async迁移实操.md|T6 批改]]；代码证据在 `代码/T6/`（Swift 6.3.3 实跑，四题全过、19 处撞墙全留档）。

## 一、一句话版本

**迁移换的不是语法是交付模型：推换成拉（M1）、账本上缺的项要自己手写（M2）、寿命义务从记忆力移交结构（M3）、重构不是逐行翻译而是给管道搬家（M4）、按屏切分让桥当边界（M5）。工程直觉全带得走，但每一条「我以为有现成件」的地方都埋着学费。**

## 二、五个骨架，逐个讲

### 1. 推 vs 拉：同一条流的两种交付模型（M1）

我用 sink 用了那么久，从没想过上游在按 demand 发货——Combine 是**推**：生产侧控制节奏，订阅方被动收。`for await` 是**拉**：消费侧控制节奏，没货就挂起等。选型规则一句话：**多播共享、生产侧带节奏的留 Combine；单消费链、消费侧要控制节奏的迁 async**。
本轮这条规则第一次上了手术台：Q1 我手写 debounce 先押「拉模型竞速」（nextOrTimeout），结果超时侧一取消挂起的 iterator.next()，整条 AsyncStream 直接终止——拉模型里「等」和「取消」是同一根神经。终版改推模型：reader 任务写共享状态、emitter 任务按 10ms 时钟轮询静默期。**手写算子选结构比选语法更要命**，这是本轮第一笔学费。

### 2. 操作符账本：能映射的免费，缺项的要手写（M2）

map/filter 两边同构，迁移零风险——但迁移成本从来不在这些行上。账本的贵处在两栏：
- **变形栏**：debounce。标准库没有（我一直以为 for-await 上能直接 `.debounce`，盲区当场被抓）。手写 = 记最新值 + 时间戳，新值来了重置静默计时（续期），静默满窗口才发——和 Combine 的 `due:` 语义是同一条，只是我用轮询实现。我最初押的「单次超时即发」是 throttle 的亲戚，不是 debounce。
- **缺项栏**：retry。async 里就是朴素循环——试 n 次、catch 记错、**最后一次仍失败必须抛**。第一版只 break 不 throw，失败被吞成「静默成功」，对拍时被 Combine 版的抛错抓个正着。教训钉死：**手写算子先写失败路径**。
「估迁移工时按账本的缺项栏估，不按行数估」——这句话现在是我自己的了。merge/combineLatest 在 AsyncAlgorithms 里，CLI 装不了外部包，记待真包验证；share 的多播重设计我给不出方案，诚实挂账不变。

### 3. 寿命移交：从「记得存」到「结构自带」（M3）

旧世界我写过一百遍 `Set<AnyCancellable>`——忘存即取消的坑也踩过。新世界对应表：视图凭证 → `.task`，VM 长订阅 → 作用域 Task，一屏多订 → TaskGroup。义务从记忆力移交结构。
Q3 把这笔账量成了硬数据：两形态对拍「活 0.2s → 销毁 → 再等 0.15s」，旧形态 deinit 即停收（死后账 0 新增），新形态 dismiss = Task 取消 = onTermination（死后生产侧仍发 7 件、消费侧收 0 件——**被丢的件才是取消传导的证据**）。
反例是本主题的灵魂：把 Task 存进永生单例，计数 5→10 还在涨——**要跨作用域活着的订阅，结构化并发里没有它的位置**。要么显式长寿命 Task 手动管取消（旧义务请回来），要么留 Combine 不迁。我项目里那个全局总线就是这个形状，迁的时候别硬塞。
这题我还交了本轮最贵的一笔学费：首跑的「死后冻结」判定是**假证**——占位计数器恒零，✅ 平凡成立。判定要双侧（死前有收、死后停收），证据要真实——**会做实验不够，还得会审计自己的实验**。

### 4. @Observable 重构：赚粒度、赔管道（M4）

重构清单我背熟了：@Published → 普通属性，private(set) 保留，@Observable 一加，白赚属性级。真跑才知道贵在哪——**管道断了**。@Observable 没有 $ 投影、没有发布点（读时追踪天生不知道「谁要听」），挂在 $query 上的 debounce 管道必须搬家。
Q2 的量账比 T5 更狠：同样「改 query 3 次 + 改无关属性 3 次」，旧版 objectWillChange 广播 **9 次**（连 results 自己的写入都算广播——@Published 的账比想的更肥），新版属性级只失效 **3 次**，results 行为等价。赚的部分实锤。
搬家的手感是本轮现学的：withObservationTracking 的 onChange 在 **willSet 时刻同步触发、读到的是旧值**（探针定位），所以回调里只标脏+重挂，新值由「重挂后的 access 读」落账，最后一笔靠 finish() 冲刷——不冲刷它永远悬着。private(set) 被观察回调碰到时，正解不是放宽保护，是管道行为收进 VM 方法。**接口不放宽，是重构的底线**。

### 5. 按屏切、桥是边界（M5）

主场题，讲的全是我的旧伤疤钉成的规则：切分单位 = 一屏 + 状态闭环（按文件切会把状态劈在两个世界）；第一屏选叶子屏（可独立替换、一键回退）；桥开屏边界（新嵌旧 UIHostingController、旧嵌新 UIViewRepresentable）；流向单向（新吃旧服务可以，旧吃新状态不行）；顺序下游先行，每迁一屏桥向内移一格。
Q4 把「混合共存」从口述变成了跑着的程序：桥 A（subject → .values → for await）和桥 B（AsyncStream → 手搭桥 → sink）同场 0 丢件，防线是先挂消费者再开生产者（T5 的学费没白交）。两个新发现：
- **反向桥没有现成件**：`AsyncPublisher(stream).sink` 编译不过——它是 Publisher→AsyncSequence 方向的桥，和 .values 同向。async→Combine 要手搭（Task 泵流 + subject 转发），泵 Task 又是一份手动取消的旧义务。「缺项自建」从账本上的一行变成了手上的活。
- **缓冲不对称**：热 subject 先发后挂丢 3 收 1；AsyncStream 先发后接丢 0（unbounded 缓冲存住早到的件）。**丢件归责先查桥有没有缓冲，再查谁先就位**。
桥不删——迁完它就是新旧世界的长期接口。这条我读着顺，现在跑着信。

## 三、学费清单（本轮 19 处撞墙里的五笔大账）

1. 拉模型竞速碰取消 → 推模型+时钟（Q1 ④）
2. 手写算子先写失败路径（Q1 ②）
3. 判定要双侧、证据要真实——审计自己的 ✅（Q3 ④⑥⑦）
4. onChange 是 willSet 语义、落账点在重挂后的读（Q2 ⑤）
5. 反向桥无现成件、丢件先查缓冲（Q4 ③②）
