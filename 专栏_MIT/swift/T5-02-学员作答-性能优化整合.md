# T5 学员作答：性能优化整合

> 学员背景自述：终于轮到我主场了——卡顿、内存、列表滚动是我十年 OC 的真金白银。但读完出题集我冷静了半秒：主场是「方法论主场」，指标对象全换了（body 重算、actor hop、依赖粒度），人设卡那句「新指标陌生、需要现场学」我作答时不偷看。策略：旧手艺能挂靠的先挂靠，挂靠不上的如实说没底，代码题让 CLI 替我说话。

## 一、共识复述：M1–M5 用自己的话

**M1 度量先于优化**：这条我闭眼能背——Time Profiler、Allocations、卡顿打点，先拿数据再动刀，优化后同口径复测。原料说「方法论不变、指标对象换了」，我接受前半句，后半句的「新指标清单」具体长什么样（body 重算次数？hop 次数？）我只有名词没有手感。
**自评：有把握**（方法论是存量，新指标清单待 Q2/Q3 回填）。

**M2 帧成本三段 + Identity 是身份证**：body 重算 → diff → 渲染，这个三段式我第一次见，但「Identity 是 diff 的身份证」我秒懂——这不就是 reuseIdentifier 吗，身份证稳定才谈得上复用。挂上锚点后我信方向，但「身份变了整棵子树推倒重建、状态一起丢」这个后果的实感我没有——T2 撞过 Identity 印象分，这轮要亲手验（Q1）。
**自评：半懂半猜**（锚点挂靠成功，机制细节等 Q1）。

**M3 失效爆炸半径**：T4 Q2 我亲手量过 objectWillChange 的对象级广播——任一属性变、全体陪跑。@Observable 属性级依赖收集我有方向（T4 C6 复攻讲的），但「爆炸半径缩到属性」具体省多少失效次数，没实验数据，只有机制推演。
**自评：半懂半猜**（T4 存量扛一半，量化对比等 Q4 段三）。

**M4 协作线程池 + hop 有价 + 取消靠检查点**：线程池 ≈ 核数这条对 GCD 线程爆炸有对照（T3 讲过），我信。「hop 是一次真实调度、有开销」——方向我懂，但一次 hop 到底等于一次锁的几倍、什么量级，完全没有数。取消是标志位+检查点协作，T3 Q2 的可取消 Gallery 我写过，检查点该插多密我全凭手感。优先级反转我知道 GCD 靠优先级继承治，actor 世界的新形态只能现推。
**自评：半懂半猜**（三个子项全在「方向对、没数字」的状态，等 Q2/Q3）。

**M5 值语义红利 + 泄漏换脸**：「泄漏没绝迹」我举双手——十年里见过太多「用了 ARC 就不会泄漏」的同事翻车。闭包捕获环是老账；Task 泄漏、凭证长寿这两个新形态我能从 T4 C1 顺着推，但没亲眼见过现场。「struct 一定省内存是迷信」这句我读的时候愣了下——T1 Q2 嵌套引用类型拷贝不深，确实，这条旧直觉会骗人。
**自评：有把握**（主场直觉 + T1/T4 存量可推，Task 泄漏现场感欠）。

## 二、概念拷问题作答

### C1 性能方法论：「列表滚动掉帧」工单

主场题，直接按肌肉记忆走：先复现（稳定路径、机型、数据量固定），再分层——掉帧是**哪一段**超了 16.6ms 的预算。旧世界我会先 Time Profiler 看主线程堆栈（是布局/绘制还是业务逻辑占的），再看离屏渲染、cell 高度计算这些老嫌疑人。
新世界变化我照 M2 翻译：Time Profiler 还能用（看 body 耗时），新增的是 SwiftUI 模板看 **body 重算次数**——这个我听过没用过。定位到具体视图后按身份稳定化/粒度细化/惰性化动刀，改完同口径复测。
什么不变：**先分层定位再动刀、拿数据判决、改后复测**——方法论一步没变。什么变了：指标对象（重算次数、diff 规模替代了 cell 复用率、离屏渲染）。
仿真底线我主动说：Instruments 跑不了的地方，可复现的计数/计时打点当硬证据（Q1/Q3 就是这个路数），真机帧率类结论老老实实记「待真机验证」，不冒充。
**自评：有把握**（主场 + 仿真底线是 T3/T4 一路守过来的纪律）。

### C2 SwiftUI 渲染：一帧的预算花在哪？

LazyVStack 懒在哪一步——我第一反应是「懒在创建」，但照 M2 三段式推：body 是值，值很便宜；VStack 的问题是一次性把所有行都**布局渲染**出来，LazyVStack 按需实例化可视区——所以省的是**渲染与布局**那两段，不是 body 重算？这个推理我半信半疑：可视区内的行状态失效时还不是照样重算。
List 复用 vs UITableView 复用：直觉说「一回事」，但 T2 学过视图是值——行视图本身是值、不需要复用，复用应该发生在更底层的承载层？我猜是类似 cell 的什么东西在复用，具体是什么说不出。
equatable 省哪步：猜 diff——输入相等就不往下比了，body 也省得重算？位置我押「diff 阶段」，不稳。
「body 便宜」什么时候骗我：body 里塞了格式化/排序/正则这种重活的时候——这个我用工程常识能推。
**自评：半懂半猜**（三段式现学现卖，「懒在哪步」和「List 复用承载层」两个点全在押）。

### C3 取消与检查点：停不下来的 Task

「cancel 了就立刻停吗」——T3 Q2 的教训还热着：取消不杀正在跑的代码。我的理解：cancel 是往任务上打了个标志，挂起中的等待（sleep、continuation）会被叫醒抛取消，但**正在执行的循环体感知不到**，除非自己查 `Task.isCancelled`。
检查点密度——老实说我一直凭手感：重要的任务每圈查一下，不重要的随缘。原则我给不出可操作的版本，「越密越好还是越密越亏」我甚至没想过检查点本身有开销。
`.task` vs 手动 `Task`：T2 埋的钩子——`.task` 跟视图寿命绑定，视图消失自动取消；手动 Task 得自己答「什么时候取消」（T4 C1 的寿命问题同款）。这个我有方向，没亲手验过。
`for await` 中取消：消费侧迭代器应该抛取消错误退出循环；生产侧……AsyncStream 的 onTermination？这个词我在 T4 Q3 见过，取消时会走到吗？猜。
**自评：半懂半猜**（标志位模型有 T3 存量，密度原则与桥两头全悬，等 Q3 数据）。

### C4 内存与 OOM：泄漏换脸

值语义+ARC 后内存问题变多变少：我的判断是**总量变少、形态变刁**。值语义把「共享可变 + 忘了释放」这类堆压力收走了大半（T1 COW 我亲手写过），但泄漏的根——循环引用——ARC 一天不退休它就一天不下岗。
三场景我能给：
①闭包捕获环：老账，`[weak self]`，手段是 deinit 打点 + Leaks（旧世界肌肉记忆直接迁移）；
②订阅凭证长寿：T4 C1 翻面——「不存即取消」反过来是「存进一个永不 deinit 的持有者 = 订阅永生」，比如 store(in:) 存进单例。查的手段：deinit 打点看持有者是不是真不死 + Allocations 看增长斜率。这条是我自己从 T4 推出来的；
③Task 泄漏：Task 闭包强引 self、self 强引 Task——形状和 UIViewController 持 block 一模一样，deinit 打点老手艺能复用。这个我方向有、现场没见过。
「struct 一定省内存」的迷信：T1 Q2 嵌套引用成员拷贝不深，加上 M5 点破，我主动破除——struct 数组里装 class，拷贝的还是一堆指针。
**自评：有把握**（主场 + 两条新形态都从存量推出，Task 泄漏现场感是唯一欠账）。

### C5 actor hop 与优先级反转

一次 actor 调用等于什么：我类比串行队列——一次 hop ≈ 一次「入队+出队」，比锁的加解锁多了一次**调度**（锁是原地等，hop 是换执行上下文）。方向我有，量级完全没数：微秒？十微秒？
什么形态放大 hop：循环里逐条 `await actor.method()`——每次都付一趟调度费。收敛我现推：攒一批一次过桥（批量化），或者把热路径整个挪进 actor 里。nonisolated 这个词 T3 见过，「只读豁免」我能挂上。
优先级反转：GCD 时代靠优先级继承（高优等低优时把低优临时提权）。actor 世界的新形态我现推：一个低优 Task 占着 actor 跑长活，高优 Task 在门口排队——反转发生在**排队**上而不是锁持有上？缓解：把 actor 里的活拆短、关键路径显式给高优（Task(priority:)）。这个推理我自己标个「半信半疑」。
**自评：半懂半猜**（类比推理一路走通，但没有一个数字，全等 Q2）。

### C6 Combine 调试栈：管道深了怎么排障

T4 Q1 的打点手法我条件反射就能答：每站 print()/debug() 打事件流、边界打时间戳和计数——Q1 要是没埋这些点，retry 是重新订阅这件事我到现在还停在猜。
栈深成本我承认真实：操作符内部断点打不进去，崩溃栈全是框架帧（T4 撞 setFailureType 那两次，报错定位就不轻松）。但另一面我也要说：管道行为是确定的——给定输入序列输出确定，「打点 + 复现」比满世界找回调现场可操作得多。
选型账本：该进。T4 三轴判定算的是能力账（一次性/流算子/消费侧），调试成本是维护账——两栏都记才是完整的账本。
**自评：有把握**（T4 手感直接迁移，两栏账本的结论是我自己合上的）。

## 三、代码任务作答

四道题落在 `代码/T5/`，思路与疑点：

- **Q1 视图身份与 diff 模拟器**：把 M2 翻译成纯 Swift——diff 按 id 配对，统计四类计数。三场景的设计我一眼看出意图：场景②用下标当 id 就是身份漂移对照组。疑点：「重建代价」怎么量化才诚实——我只能打计数，真帧率是 Instruments 的事，按纪律记待真机。
- **Q2 Actor vs 锁基准**：三实现 + 细粒度 vs 批量对照。我的旧世界经验是基准测试**必须多轮**（第一轮永远被预热污染），这个习惯我带进来。疑点：actor 和 NSLock 的对比会不会方差很大——10 任务 ×2000 次够不够热。
- **Q3 取消延迟与检查点密度**：三组密度对照。疑点：③组不检查的话任务根本不停，怎么收场——我打算给它一个「硬上限」兜底，同时把「停不下来」本身当证据打印。取消延迟的测量点（cancel 发出 → 任务退出）我按 C3 的理解设计。
- **Q4 收账四连**：段一自定义 Subscriber 报 .max(2) 有限需求——T4 遗留 1，Demand 协议从「sink 默认无界」走到协议层，我按 T4 C2 复攻的理解写。段二 values 桥——T4 Q3 走的 continuation 路线，values 这回真写。段三 @Observable 对比我最没底：Observation 的观察 API 在 CLI 里能不能用，我打算先试 withObservationTracking，不行就退到次级证据并如实说明。

**自评：Q1 有把握，Q2 半懂半猜（没数字底气），Q3 半懂半猜（③组设计悬），Q4 段一段二半懂半猜、段三纯悬**。
