## 二、复攻记录

**C1 复攻**（学员重读「GCD到async工程深入」后补答）：

> 补答：第三层差异补齐——Task {} 从创建点**继承上下文**：优先级跟着走，更重要的是 actor 隔离继承：在 @MainActor 上下文里开的 Task {} 回 main 线程跑，不用手动 hop；detached 砍掉这些——不继承优先级、不继承隔离、不继承 task-local 值，真正「白手起家」。所以选型规则：**默认 Task {}，只有明确要摆脱当前上下文（避免在 main actor 排队、纯后台基准测试）才 detached**。场景例：拉完数据回主线程刷 UI——Task {} 天然回得来，detached 得自己再 hop 一次，多写代码还容易漏。

判定：三层齐 + 继承/砍掉讲清 + 选型场景落地 → **C1 复攻过关**。

**C2 复攻**（Q3 代码结论回填概念通道）：

> 补答：拿 Q3 的输出说话——fetchCount = 2 就是答案本身：第一个请求查缓存（空）→ await fetch（**松手**）→ 第二个请求进来查缓存（还是空，第一个还没写回）→ 又 fetch 一次。串行队列堵门为什么没这个病：旧世界里「等 IO」只能堵在门口排队（block 里同步等会死锁，GCD 代码被迫把等待移出队列）；actor 敢让位，是因为 await 挂起**不占执行资源**——不松手才是灾难：方法里 await 一个 3 秒的网络请求，整个 actor 堵死 3 秒，连读缓存的调用都排队。可重入是解药，代价是 **check-then-act 跨挂起点失效**，修法是把「挂起期间的承诺」也存进状态（in-flight 去重）：不仅记「有什么」，还记「我正在去拿什么」。

判定：活体标本引用准确、松手动机（避免堵死）讲透、堵门 vs 让位对照成立、修法原理到位 → **C2 复攻过关**。人设卡预告的核心病灶（actor=串行队列）经撞墙清除。

**C3 复攻**（学员重读「Sendable与隔离域工程对照」后补答）：

> 补答：closure 为什么默认不放心——闭包是「代码+捕获环境」的一等值（T1 M5），编译器要验证它跨域安全，得证明捕获的每个东西跨域后都不会被并发可变访问；但捕获列表里可能藏着共享可变引用，闭包体内部怎么用它更不可静态穷尽——验证不了就只能默认不信。@unchecked Sendable 的性质：「人肉担保 + 关掉保险丝」，使用前提是能证明跨域后不存在并发可变访问（全 let、或内部锁协议自洽且自己遵守）；出了事编译器不救你，TSan 见。工程自我约束：先问能不能值化，再问能不能 actor 化，最后才轮到 @unchecked，且必须留注释写担保理由。

判定：closure 不可验证的因果讲清、@unchecked 风险性质与使用纪律到位 → **C3 复攻过关**。

**C4 复攻**（Q2 代码结论回填 + 教练追问 detached）：

> 补答：group 的命运：cancelAll 给所有子任务插旗，但**父任务不会立刻返回**——它照旧等所有子任务了结（协作的在检查点抛错了结，不协作的跑完），Q2 两轮都在 cancel 后才打印结果就是这个语义；结构化保证「父返回时子必了结」，没有野任务。detached 在结构之外：没人给它传旗（要自己拿句柄 cancel）、没人等它了结（漏了就是后台幽灵——T2 说过的 onAppear+Task{} 同款病）。.task 的账算清：视图消失 → 框架 cancel 根任务 → 旗子下传 → 子任务协作了结 → 整棵树干净收掉。

判定：等待语义、传播语义、幽灵任务勾连三点齐 → **C4 复攻过关**。T2 遗留观察项 1（.task 取消无实感）清偿。

**C6 复攻**（教练追问「.task 句柄到底存哪」后补答）：

> 补答：句柄不是给视图代码拿的——.task 修饰符创建的 Task 由框架按**视图身份**保管，代码里根本没有变量可写，也就没有「我忘了 cancel」的机会；视图身份消失，框架替你 cancel。这跟 T1 的教训正好对上：unowned 那次我赌「对方一定比我活得久」，栽了；这回如果我赌「变量还在 = 任务还在跑/变量没了 = 任务也停了」，会栽同款——**寿命相关的事一律显式管理（cancel/await/身份绑定），不靠引用关系猜**。T2 说「取消从手动义务变成框架赠品」，现在我能说清赠品是怎么发的了。

判定：保管归属讲清、两次寿命教训勾连成方法论 → **C6 复攻过关**。T1 遗留观察项 3（寿命直觉）二次回收并沉淀为规则。

**代码通道复攻确认**：Q2 的 sleep 检查点认知墙、Q3 的 fetchCount 断言炸裂、Q4 的 Sendable diagnostic 抄录均已写入 `代码/T3/` 对应文件头注释，复攻版全部实跑通过（输出见上表，教练独立复跑核对一致）→ **Q2/Q3/Q4 复攻过关**。
