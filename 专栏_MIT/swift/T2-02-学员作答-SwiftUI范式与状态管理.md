# T2 学员作答：SwiftUI 声明式范式与状态管理

> 学员背景自述：10 年 OC + UIKit，脑子里的 UI 心智还是「视图是对象、命令式改属性」。SwiftUI 一行生产代码没写过，只在 demo 里看过。本轮先读了七篇原料（标了 OC 锚点），再闭卷作答。错的地方如实错——这主题正是我的范式盲区。

## 一、共识复述：M1–M5 用自己的话

**M1 视图是值，body 是函数**：这个对我冲击最大。UIKit 里 `self.titleLabel` 是个活对象，我 set 它一辈子有效；SwiftUI 的视图是个 struct 值，body 每次被框架重新调用、描述重新生成——我没有任何「实例」可以攥在手里。最顺的锚点是 tableView 的 dataSource：我不指挥 tableView 怎么变，我只描述「有哪些行」，框架自己去刷。
**自评：半懂半猜**（锚点挂上了，但十年「拿实例」的手瘾还在，C1 见真章）。

**M2 状态是唯一真理源，UI = f(state)**：类比 KVO/通知驱动 reloadData——数据变了，UI 跟着刷。差异是 SwiftUI 把「谁依赖谁」的观察注册全自动化了，我不用手写 addObserver。方向我熟，机制细节陌生。
**自评：有把握**（方向性判断，reloadData 十年的肌肉记忆）。

**M3 状态包装器三件套**：表我背下来了——@State 框架代管视图私有、@Binding 借来的读写、@StateObject 自己创建只建一次、@ObservedObject 外部拥有传入、@Environment 祖先注入。但「为什么这么分」我心里没底：所有权这个词我在 ARC 里懂（谁 strong 谁负责），可它跟「body 重算」怎么勾起来，我推不顺。
**自评：半懂半猜**（背了表，没长进骨头里，C2 要现原形）。

**M4 重算有范围，Identity 决定 diff**：重算不是全屏重画——这个我信（性能直觉），但框架靠什么对齐新旧节点、「结构身份」到底是个什么东西，我只有 T1 遗留下来的模糊印象。
**自评：半懂半猜**（印象分，C6 就是来收这笔账的）。

**M5 生命周期是事件修饰符**：没有 viewDidLoad，onAppear/task 挂在视图上。`.task` 随视图消失自动取消——这句我读到了但没实感，GCD 时代取消全靠手动，我本能不信「自动」这两个字。
**自评：半懂半猜**。

## 二、概念拷问题作答

### C1 「拿到实例改属性」的瘾怎么戒？

第一反应（如实记录）：脑子里先蹦出来的是「得有个 label 的引用吧？」——这就是病。按 M1/M2 翻译：SwiftUI 里 body 重算一次，描述就重新生成一次，我上次就算攥住了什么，这次也不是它了，改它等于改上一帧的尸体。「隐藏」这个意图不能挂在视图上，只能编码成状态：

```swift
@State private var isHidden = false
// body 里：
if !isHidden { Text("标题") }
Button("隐藏") { isHidden = true }
```

按钮的动作不是「去改谁」，而是「改状态」；显不显示由 body 重算时读状态决定。和 UIKit 的差异：那边是「改对象属性 → 屏幕跟着变」，这边是「改状态源 → 描述重生成 → 框架落最小变更」。
**自评：有把握**（翻译写得出来，dataSource 锚点真的管用；手瘾靠这道题戒第一口）。

### C2 状态包装器选型

我先按直觉答，知道可能会栽：筛选条件（枚举）→ @State，值类型小状态嘛；UserStore（class）→ @ObservedObject，引用类型用 Observed，这是我在 demo 里见过的写法。放在哪：都放列表页。

反诘①「为什么不能全用 @ObservedObject」——我卡住了。我猜：值类型它包不了？但 @State 和 @ObservedObject 好像都能触发刷新，我真说不出非用 @State 不可的理由。
反诘②「StateObject 与 ObservedObject 一句话区别」——创建时机？我记得文档说过 StateObject 保证只初始化一次，ObservedObject 不保证。但「为什么 body 重算会跟创建扯上关系」这一步我推不动：视图 init 的时候初始化表达式执行一次，不就完了吗？重算又不是重新 init……吧？这里我心虚。
**自评：半懂半猜**（直觉选型暴露了「引用类型全用 Observed」的误区，反诘两问都没答到要害）。

### C3 body 重算

性能直觉先答：重算肯定不便宜，框架应该有裁剪——「少重算」是对的，这个我在 UIKit 里对应「别轻易 reloadData，能 reloadRows 就 reloadRows」。
但机制我推不顺：某个 @State 变了，是只重算读它的那个视图，还是从根往下全算一遍？我猜是后者（树形全量），因为「状态在根上变，孩子怎么知道」。重算和重画是不是一回事——我猜重画比重算贵，但两层中间有没有第三个步骤（什么 diff），我说不出来。为什么框架敢频繁重算：猜是 struct 便宜？T1 讲过 struct 赋值是拷贝、没引用计数开销，大概靠这个。
**自评：半懂半猜**（直觉方向对，三层机制说不出，重算范围猜错了）。

### C4 if/else 凭什么能写进 body？

**如实报告：这是我知识盲区**。T1 人设卡就预告了 result builder 我没见过。我知道 @ViewBuilder 这个词（demo 里见过），但它背后干了什么，我零存量。
硬推：body 里写了三行视图，没 return 没数组，编译器居然不报错——那一定是谁替我把三行「收集」起来了。收集成什么？T1 说过 some View 要求类型恒定，三行异构视图（Text、Image、Button）类型各不相同，装不进一个数组……我就推到这儿了，再往后是黑的。
if/else 两分支变成什么类型，完全没有概念。
**卡点标注：我请求提示**。（提示使用记录见文末）

**用了弱提示**（「body 内容本质上传给了什么结构的参数」）：想到 T1 的 M5——body 本质是个闭包？`var body: some View` 不对，body 是属性不是函数参数……但 ViewBuilder 的作用对象应该是个闭包，就像 T1 Q3 里 `(@MiniBuilder content: () -> T)` 那种形状。方向有了，但「翻译成哪些调用」还是不知道。

**用了中提示**（「buildBlock/buildOptional/buildEither 静态方法，编译器把语句翻译成调用」）：这下能接上了——三行视图 = `buildBlock(Text, Image, Button)` 这样被打包；if/else 走 buildEither，if 无 else 走 buildOptional。但「打包成什么类型」「两分支怎么统一」我还是只能猜：大概是某种嵌套元组或枚举？_ConditionalContent 这个名字我在提示里第一次见。
**自评：纯猜 → 半懂半猜**（弱+中提示后搭出了骨架，类型层面的形状要靠代码题 Q3 去撞）。

### C5 生命周期平移

OC 里「页面加载完拉一次数据」写在 viewDidLoad。我第一反应：SwiftUI 对应 onAppear。
差异让我想想：viewDidLoad 是对象生命周期——控制器 init 后调一次，对象不死不再调。onAppear 是……视图出现的时候调？视图值不是每次重算都在造吗，那 onAppear 会不会每次重算都触发？我推不动，先猜「不会，按出现事件触发」。
`.task` 和 onAppear：我猜 task 能直接写 async 代码，onAppear 里起异步得自己包 Task {}。关键差异是什么——我想不起来，「自动取消」这个词在原料里见过，但 GCD 十年的经验告诉我取消都是手动活，我不信自动的，也说不出它怎么做到。
**自评：半懂半猜**（viewDidLoad→onAppear 这个平移我答了但三个差异点只碰到一个半，.task 的取消语义基本没接住）。

### C6 View Identity

T1 遗留的印象分来还债了。两种身份来源：我猜一种是「视图在树里的位置」，另一种是显式指定的什么 key（ForEach 里那个 id 参数我见过）。
AnyView 伤 diff：我只有「AnyView 性能差」的印象，差在哪一步说不清——猜是类型信息没了？跟 T1 的 any 装箱联系起来：装箱擦掉了具体类型，diff 的时候认不出「你是你」？方向我敢猜，论证我给不出。
.id() 改身份的后果：完全空白。id 不是给 ForEach 定位用的吗，改了能有什么后果？
**自评：半懂半猜**（结构和显式两种身份方向摸到了，AnyView 的伤害点只到「猜」，.id() 后果交白卷）。

## 三、代码任务作答

四道题落在 `代码/T2/`，思路与疑点：

- **Q1 视图是值现形记**：init 打点 + 手动调两次 body。我写的时候故意问了自己一句：父视图的 body 被调，子视图是「复用旧的」还是「重造」？跑之前我押复用（UIKit 惯性），跑完看输出认栽。
- **Q2 所有权模拟**：用「外部存储盒只在 nil 时创建」模拟 StateObject，「每次重算都新建」模拟 ObservedObject 误用。附加的 objectWillChange 实验——**撞墙了**：我按 KVO 习惯断言它在变更后发射，实跑 assert 失败，sink 里读到的还是旧值。will 这个前缀我十年没认真看过（KVO 是 did 语义的天下）。
- **Q3 迷你 ViewBuilder**：盲区题，代码化硬撞。第一版想用 `buildBlock<T>(_ components: T...) -> [T]` 一锅端，编译不过（异构塞不进同型数组）；改成按个数重载后又栽在「少了单参 buildBlock」上，实跑报 missing argument。两次撞墙都记在文件里了。
- **Q4 设置页改写**：**疑点如实报**——我初稿的选型是 OC 习惯：所有状态都塞进 model（visitCount 也放 @Published），理由是「控制器什么都拿」的肌肉记忆。对照 M3 三件套复盘后才改：visitCount 是页面私有的临时值，没人共享它，放 @State 才对；开关未来要接主题服务，才配得上引用型真理源。这个改的过程我认为是本题真正的考点。渲染部分 CLI 跑不了，我按规矩标「待真机验证」。

**自评：Q1 有把握，Q2 半懂半猜（wall 已撞），Q3 纯撞墙学习，Q4 半懂半猜（选型反复过一次）**。
