# T3 费曼草稿：我用自己的话讲一遍 Concurrency

> 全过后费曼写回（流程第四节）。视角：学员第一人称，讲给一个跟我一样的 GCD 老手听。
> 判定背书见 [[T3-03-批改与判定-Concurrency.md|T3 批改]]；代码证据在 `代码/T3/`（Swift 6.3.3 实跑）。

## 一、一句话版本

**GCD 的世界观是「dispatch 完就撒手」，Concurrency 的世界观是「任务从生到死都有人管」：等的时候不占线程（挂起）、任务挂在父子树上（结构化）、共享状态有门禁（actor）、跨门禁传东西要过安检（Sendable）、取消是插旗子不是拔电源（协作式）。**

## 二、五个骨架，逐个讲

### 1. await 是挂起不是阻塞：回调的里子，同步的面子

这个我有十年锚点——OC 的网络请求本来就不占线程干等，回调来了再干活。await 干的事是把「回调里才干的事」拉平成顺序代码：**心智上是同步写法，成本上还是异步的**。Q1 的时间线是肉眼证据：0.00s 发起请求，await 挂起期间 0.15/0.31/0.47s 心跳照常打印，0.52s 拿到结果——「等」没有冻住任何东西，只是把当前线程还回了池子。
给 GCD 同行的翻译：你写过的那种「completion 回调里接着干」的代码，现在写出来长得跟同步代码一样，但一根多余的线程都没烧。

### 2. 结构化并发：任务不再是孤儿

GCD 里 dispatch 出去的任务跟调用方从此两清——没结果、没错误、没取消、没人等。「发出去的任务还有人管」是我这轮最反直觉的一点。
结构化的账要算两头：
- **等待语义**：`withTaskGroup` 里 `cancelAll()` 之后，父任务**不会立刻返回**——它照旧等所有子任务了结（协作的在检查点抛错了结，不协作的跑完）。Q2 两轮都是 cancel 之后才打印结果，就是这个语义。「父返回时子必了结」，没有野任务。
- **detached 在结构之外**：没人给它传旗子（要自己拿句柄 cancel）、没人等它了结——漏管就是后台幽灵，跟 T2 说的 onAppear + Task{} 是同款病。
选型规则（C1 复攻后长出来的）：**默认 Task {}**，它从创建点继承优先级和 actor 隔离——在 @MainActor 里开的 Task {} 天然回 main 线程；只有明确要摆脱当前上下文（避免在 main actor 排队、纯后台基准测试）才 detached。

### 3. actor 是可重入的隔离域：我栽得最狠的一堵墙

「actor 就是串行队列换了语法」——人设卡预告的核心病灶，Q3 用一次断言炸裂给我清除了。
过程值得记：我赌 fetchCount == 1（堵门直觉：第二个请求在门口排队呢），实跑 **fetchCount = 2**。真相是：第一个请求查缓存（空）→ await fetch **松手** → 第二个请求进来查缓存（还是空）→ 又 fetch 一次。check-then-act 被重入打穿，活体标本。
为什么敢这么设计：**await 挂起不占执行资源**，松手是安全的；不松手才是灾难——方法里 await 一个 3 秒的网络请求，不松手就把整个 actor 堵死 3 秒，连读缓存的调用都得排队。可重入是解药，代价是 **check-then-act 跨挂起点失效**。
修法是把「挂起期间的承诺」也存进状态：in-flight 去重——不仅记「缓存里有什么」，还记「我正在去拿什么」，重入者复用同一个 Task。GCD 对照一句话：串行队列是**堵门**（旧世界里等 IO 只能堵在门口，block 里同步等会死锁），actor 是**让位**。

### 4. Sendable：把数据竞争的安检从事故现场搬到编译期

OC 里数据竞争靠 TSan 事后抓、靠人脑事前想；Sendable 把它提前成编译期类型属性——「隔离域」从口头约定变成账本。
保护的不变量一句话：**同一时刻只有一个隔离域能碰这块可变状态**。所以可变 class 跨域 = 把事故种子传递出去，编译器拦的就是这个；全 let 的 struct 拷贝出去是独立一份，天然容易 Sendable（T1 值语义的直接回收）。
closure 为什么默认不放心：闭包是「代码 + 捕获环境」的一等值，编译器要验证它跨域安全，得证明捕获的每个东西都不会被并发可变访问——但捕获列表里可能藏着共享可变引用，闭包体怎么用更不可静态穷尽，**验证不了就只能默认不信**。
@unchecked Sendable 的性质：「人肉担保 + 关掉保险丝」，前提是你能证明跨域后不存在并发可变访问；出了事编译器不救你，TSan 见。工程纪律三连：**先问能不能值化 → 再问能不能 actor 化 → 最后才 @unchecked，且必须留注释写担保理由**（Q4 我选了值化，@unchecked 只有概念无实操，台账挂着）。

### 5. 取消与寿命：插旗子、遥控器、身份保管

取消链条 T2 建的，这轮有了手感：**cancel 只是沿任务树插旗子，代码自己查（checkCancellation/检查点 await）才会停**。Q2 的认知墙很值钱：第一版两轮都写 `try await Task.sleep`，结果「不协作」那轮也被取消干净——**sleep 本身就是检查点**，被取消直接抛错。要演示不协作得 `try?` 吞信号。教训：检查点无处不在，取消不住不是没旗子，是不睁眼。补充观察：不协作版被取消后 sleep 立即抛错返回、但活照样干完——「取消不掉」指不了结果，不是不提速。
寿命这块我把 T1 的 unowned 教训用上了：句柄置 nil 不停任务——**句柄是遥控器，任务本体由运行时持有**，要停得显式 cancel。`.task` 的句柄根本不在视图代码手里：框架按**视图身份**保管，身份消失框架替你 cancel，代码里没有变量可写，也就没有「忘了 cancel」的机会。
沉淀成规则：**寿命相关的事一律显式管理（cancel/await/身份绑定），不靠引用关系猜**——unowned 那次赌「对方比我活得久」栽了，赌「变量没了 = 任务停了」会栽同款。
Continuation 是这轮我主场最稳的一题：欠条只能兑现一次且必须兑现——resume 两次运行时崩（同一笔债还两次），不 resume 调用方永远挂在 await 上（就是 OC 时代「completion 忘回调导致页面永远转圈」的同款病，换了语法而已）。checked 版替你盯着这两条义务。

## 三、争议题我的立场（讲给同行听）

- **D1 Combine 还有没有未来**：本轮只站分界线——**单值/序列走 async，复杂流算子（多路合并、防抖节流、背压）才考虑 Combine**。这是 T4 的主战场，不提前下结论。
- **D2 全 actor 化是不是正解**：不站。优先级是**无共享可变**（值类型/Sendable）→ 真需要共享才 actor → actor 也不是没代价（hop 开销、优先级反转，T5 的基准测试见）。actor 消灭的是一整类数据竞争，但把代码切碎成异步拼图也是真的。
- **D3 Sendable 严格化**：机制必须懂，策略按仓库现状定——百万行存量一夜全红不现实，`@preconcurrency`/渐进迁移是能落地的路；但新代码从第一天就按 Swift 6 严格写，不欠新债。OC 混编老手做这个决策有天然手感：跟当年 ARC 迁移一个味道。

## 四、迁移对比小节（GCD ↔ Concurrency，固定骨架）

| 维度 | OC + GCD（旧世界） | Concurrency（新世界） | 迁移要点 |
|------|-------------------|---------------------|---------|
| 等待成本 | 同步等 = 占线程；异步等 = 回调金字塔 | await 挂起释放线程，回来接着跑，代码拉平 | 回调→async 是机械迁移（continuation 桥），心智反而变简单 |
| 任务归属 | dispatch 完即失联，结果靠出参回调 | 结构化父子树，父返回子必了结 | 「发出去没人管」的直觉要重写；detached 是逃生口不是默认 |
| 结果与错误 | block 出参、NSError**、code 约定 | 进类型系统：`async throws` 可 await 可捕获 | 错误路径不再靠约定，编译器盯着 |
| 共享状态保护 | 串行队列堵门 / 锁 + 人肉遵守 | actor 让位式隔离：挂起即松手 | check-then-act 跨挂起点失效——in-flight 去重是新必修课 |
| 数据竞争防线 | TSan 事后抓 + review 事前想 | Sendable 编译期安检，跨域传递进类型系统 | 值化 > actor 化 > @unchecked（人肉担保要留注释） |
| 取消 | 无对应物（DispatchWorkItem 半成品） | 插旗-检查-协作了结，沿任务树自动传播 | sleep/await 自带检查点；不睁眼（try? 吞）才取消不掉 |
| 任务寿命 | block 执行完自然消失，无句柄概念 | 句柄≠本体；置 nil 不停，cancel 才停 | 寿命一律显式管理或绑身份（.task），不靠引用关系猜 |
| 回调桥接 | completion block 传参 | withCheckedContinuation：一次性欠条 | 兑现恰好一次——忘回调/双回调的老病在桥这里都有后果 |
