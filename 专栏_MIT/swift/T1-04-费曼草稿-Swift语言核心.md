# 费曼草稿：T1 Swift 语言核心（过关后用自己的话重写）

> 设定：讲给一个和我一样的 OC 老手听。他若追问到我答不上来，说明我没懂——本稿经教练 agent 以初学者身份连环追问一轮后定稿。
> 依据：[[T1-03-批改与判定-Swift语言核心.md|T1 判定]] 双通道全过；代码证据在 `代码/T1/`。

## 一、一句话总纲

OC 十年的世界里一切都是「共享的指针」；Swift 把「拷贝还是共享」变成了类型系统的头等决策——**值语义是默认承诺，引用语义要付共享的代价，而类型系统（泛型/协议/some/any）就是编译器替你把这笔账记清楚的那本账本**。

## 二、五个模型，讲给 OC 老手听

### 1. struct/class 不是「新/旧语法」，是「拷贝/共享」两种世界

OC 里 `A *b = a` 永远是共享，十年没见过第二种赋值。Swift 的 `var b = a`（struct）是真的复制：改 b 不动 a。但承诺来自**内容**不来自关键字——struct 里塞一个裸 class 成员，赋值拷的只是那个引用字段，等于把 OC 的共享世界偷渡进来（我跑过实验：改 b 连坐 a，`===` 为 true）。
两个修法：数据就值化（交给标准库自带 CoW 的容器）；必须共享存储就手写 CoW——写之前查 `isKnownUniquelyReferenced`，不独占先拷贝再改。判定必须放在修改**之前**。Substring 是同构案例：切片共享大字符串存储，出边界要 `String(...)` 切断。

### 2. Optional 不是空指针，是「缺席」这个类型事实

OC 的 nil 是地址 0，`[nil foo]` 运行时兜底返回零——安静，但 nil 能穿透十层调用在莫名位置炸，这种事故我查过太多次。Swift 把「可能没有」做成枚举 `Optional<T>`（.some/.none），`nil` 是 case 不是对象，「给它发消息」在类型层面就不成立，编译器逼你先拆包。可选链 `a?.b?.c` 脱糖就是逐层 if-let，任一层 .none 短路。
交易明码标价：用满屏 if let 换掉一整类静默崩溃。

### 3. 协议是积木，泛型是编译期钉死的分发

OC 协议是约定，遵守与否运行时见分晓，靠消息转发找实现。Swift 的协议 + extension 默认实现横向叠能力，不靠继承树。泛型调用点编译器知道具体类型：特化生成专用代码，或经 Protocol Witness Table 找实现——大部分分发在编译期就钉死，不像 OC 每次都查表。
带 associatedtype 的协议（PAT）不能直接当类型用，编译器愁两件事：元素的内存格子尺寸定不下来；方法签名里关联类型未知、调用点没法做类型检查。出路两条：`protocol P<T>` 提升主要关联类型后 `any P<String>` 钉死；或手写擦除盒子（AnyHashable/AnyView 的路数）。

### 4. some 是账本条目，any 是运行时箱子

`some P`：编译器知道具体型、调用方只见协议，同一位置类型恒定，可静态派发——SwiftUI 的 `body` 靠它维持稳定的类型身份做 diff，装箱擦掉类型（AnyView）就伤了 Identity。`any P`：三指针 buffer + VWT + PWT 的存在容器，装箱换动态，异构集合才用它。OC 的 `id<P>` 最像 any；Swift 没有与 some 对应的旧物——这是迁移时唯一没有锚点、必须新建的心智。

### 5. 闭包逃逸 = 把「活得比栈长」写进类型契约

闭包捕获的东西要活得比栈帧长，就搬进堆。`@escaping` 就是让编译器承认这个事实的声明：不标就按不逃逸优化，一带出去就编译报错。逃逸闭包强捕获 self + self 持有闭包属性 = 环——我在 unowned 上栽过一次（实跑崩溃：对象先释放、迟到回调读 unowned 即 Fatal error），教训是**寿命不确定就 weak**，unowned 只给「闭包必然不晚于对象死」的场景。和 OC 比：block 时代 weakSelf 靠团队约定，Swift 把「逃不逃逸」升级成类型契约，但捕获列表仍要人自己写——义务没消失，只是换了落点。

### 附：mutating 与 let 的一层窗户纸

mutating = self 变 inout（copy-in copy-out），改的是写回；class 方法改的是引用指向的共享内存，天然没有写回问题。let 的 struct 不许调 mutating（写回违反只读承诺），let 的 class 却可以改内部（let 锁的是引用指向，不是内容）——差异根源就是值/引用有没有那层间接。

## 三、迁移对比小节（OC ↔ Swift 双实现视角）

| 议题 | OC 旧世界 | Swift 新世界 | 迁移动作 |
|------|----------|-------------|---------|
| 赋值语义 | 一切指针共享 | struct 真拷贝（CoW 延迟） | 数据模型默认 struct；共享需求显式选 class/actor |
| 集合成员共变 | 两个属性指同一 NSMutableArray 是常态，靠纪律 | 值语义下这是 bug（泄漏） | 值化存储或手写 CoW |
| nil 处理 | nil-messaging 运行时兜底 | Optional 枚举，编译期强制拆包 | 接受 if let 噪音，换掉静默穿透类崩溃 |
| 分发 | 运行时消息转发，可热替换 | 静态分发为主，PWT 动态兜底 | 放弃「运行时换实现」的依赖；动态性用 any/闭包显式表达 |
| 协议用法 | 约定 + delegate | 积木式组合 + 泛型约束 | 新逻辑层走 POP；UIKit 壳保留继承 |
| block/闭包 | __weak typeof(self) 靠约定 | @escaping 类型契约 + [weak self] 仍靠人 | 凡是存进属性/异步回调的闭包，先问寿命再选捕获列表 |
| 空值字段 | `id` 可为 nil 无人管 | `id<Proto>` ↔ `any P`；some 无旧物 | 异构集合才 any，API 出口默认 some |

## 四、这轮学习教会我的三件事（学法层）

1. **OC 直觉是好挂靠，但会押错注**——unowned 那一栽，就是拿「回调肯定先执行」的旧直觉赌新世界的寿命模型。凡是涉及寿命/并发的判断，跑代码验证，别信直觉。
2. **编译器是第二个教练**——Q2/Q3 三次撞墙的报错信息，比任何讲解都精确地指出了知识缺口。以后学新特性先故意写错，收集「编译器在骂我什么」。
3. **半懂要用判分点拆出来**——C2 首轮「半懂半猜」自评是对的，但只有拆成三层判分点，才知道补哪一层、补没补齐。
