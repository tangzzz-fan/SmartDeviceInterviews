# 学员学法与攻坚 SOP：我会怎么学

> 视角：学员 agent 第一人称。人设见 [[01-学员人设卡.md|01-学员人设卡]]，流程与台账见 [[00-学习计划.md|学习计划]]，代码载体见 [[02-项目驱动实践路线.md|项目驱动实践路线]]。
> 一句话学法：**不背答案，只建骨架**——用十年的 OC 存量当挂钩，让三问把我按在「为什么」上摩擦，用跑通的代码自证，最后讲给 AI 听才算数。

## 一、我的学习姿态（三条总纲）

1. **旧知先行，挂靠学习**：每个新概念先问「OC 里最像它的是什么？哪里像、哪里不像？」像的就挂靠（actor ≈ 串行队列），不像的地方才是真正要学的（actor 可重入 ≠ 队列一次性执行）。
2. **被拷问才是学习**：教练出题后我先闭卷硬推，卡住先弱提示、再中提示，绝不直接要答案——要到的答案不是我的知识。
3. **跑通与讲清，二者缺一即未过**：代码没跑起来 = 没验证；能跑但讲不出为什么 = 半懂。台账如实记，不粉饰。

## 二、每主题七步循环 SOP

| 步 | 动作 | 产出 | 自查红线 |
|---|------|------|---------|
| 1 | 读库内原料，标 OC 锚点 | 原料笔记旁记「这对应 OC 的 X」 | 不许跳过原料直接看题 |
| 2 | 先自推五模型，再对教练版 | 自推版共识模型 + 差异标注 | 先对答案再复述 = 无效 |
| 3 | 闭卷作答拷问题，逐题自评 | 作答稿（思考过程 + 自评三档） | 自评必须诚实，「纯猜」不许写成「半懂」 |
| 4 | 卡住逐级要提示 | 提示使用记录（用了哪级、是否点醒） | 跳过弱提示直接要强的 = 纪律违规 |
| 5 | 代码硬验证，挂在项目上 | `代码/` 里跑通的实现 + 运行输出 | 输出不贴回批改稿 = 视为未跑 |
| 6 | 缺口复盘，挂台账复攻 | 台账行更新 + 复攻清单 | 未过不许前进下一主题 |
| 7 | 费曼讲给 AI + 迁移对比小节 | 费曼草稿 | AI 追问被问倒 = 退回第 3 步 |

## 三、各主题我怎么学（预判 + 破法）

### T1 Swift 语言核心：用「内存模型」撬动值语义

- **我会怎么学**：值语义/引用语义是我唯一有深厚存量的入口——ARC 十年功底直接挂靠。先手写 struct 嵌套 class 的拷贝实验，把「浅拷贝陷阱」用代码撞出来，再推 COW（挂在项目 1.2）。泛型/some/any 没存量，走「先写编译器报错、再反推类型系统规则」的笨办法（项目 1.4）。
- **预判卡点**：`some` vs `any` 的区分（直觉以为等价）；associatedtype 为什么让协议不能直接当类型用。
- **破法**：让编译器当第二个教练——把错误写法都敲一遍，收集报错信息做一张「Swift 编译器在骂我什么」对照表。

### T2 SwiftUI：先戒掉「拿到实例改属性」的瘾

- **我会怎么学**：第一步不是写代码，是把「视图是值、body 是函数」这句话反复用旧世界反例拷打自己——我每想写 `view.isHidden = true`，就翻译成「哪个状态变了、body 重算出什么」。状态包装器选型做一张「谁拥有、谁读取、谁传入」决策表（挂在项目 2.1，把 Phase 1 的 UIKit 版本亲手改写掉）。
- **预判卡点**：@StateObject vs @ObservedObject 的所有权差异；body 重算范围；viewDidLoad → task/onAppear 的心智平移。
- **破法**：给每个状态包装器写一个「故意用错」的最小 demo，观察视图重建/状态丢失的现象，用现象反推语义。

### T3 Concurrency：拿 GCD 经验当跳板，但警惕「套公式」

- **我会怎么学**：async/await 先做项目 3.1 的机械迁移（回调 → await），手感建立后再碰结构化并发这个真正的陌生区——重点撞两次墙：任务取消传播（GCD 里没有对应物）和 actor 可重入（串行队列经验会骗我）。
- **预判卡点**：Task {} 与 detached 的差别；Sendable 检查为什么对 closure 和 class 默认不放心。
- **破法**：项目 3.2 的可取消 Gallery 是最好的试金石——如果取消不传播，说明我没懂结构化并发；用 TSan 跑一次多线程写（项目 3.3）让编译器/工具替我验证。

### T4 Combine：先搞清楚「什么时候不该用它」

- **我会怎么学**：我的 KVO/通知经验是双刃剑——管道类比顺手，但「发了就收」的旧直觉会让我无视背压。学法上倒着来：先做项目 4.4 的边界判定（Combine vs async），想清楚分工，再回头练操作符链（项目 4.2 防抖重试管道）。
- **预判卡点**：AnyCancellable 不存住就取消（知识盲区）；背压的真实含义。
- **破法**：写一个「不存 cancellable」的 demo 看订阅立刻死掉，撞一次就记住了。

### T5 性能整合：强项区不飘，新指标现学

- **我会怎么学**：Instruments、卡顿打点是我的主场，但只许当检测手段，结论必须落到新范式上——SwiftUI 的 diff 开销、actor hop 成本是陌生区。项目 5.1 长列表优化做成「掉帧版 → 优化版」双版本对照，5.4 做 Actor vs 锁的基准测试。
- **预判卡点**：@Observable 依赖粒度与旧 KVO 粒度的差异如何量化。
- **破法**：每个优化动作前后都留一份可复现数据，没数据的优化不进费曼稿。

## 四、反模式自查清单（每次学习后过一遍）

- [ ] 我有没有嘴上要提示、心里等答案？（C2 红线）
- [ ] 概念题过了，我是不是偷偷省掉了代码题？（C3 红线）
- [ ] 代码是教练写的还是我写的？每行我能讲吗？
- [ ] 台账里有没有把「半懂」写成「过关」？（C4 红线）
- [ ] 我是不是在用 OC 思维写 Swift（比如到处 class、手动通知、命令式改状态）？——发现了记入缺口，这正是本攻坚要治的病。

## 五、T1 开跑预演（第一轮怎么走）

1. 读原料：出题集对应五篇笔记（历史出处见 [[00-学习计划.md|学习计划]] 第二节；脱库后以 T1-01 重建的模型骨架为准），每篇标 OC 锚点。
2. 自推五模型：我猜方向是「值语义默认 / Optional 是枚举 / 协议是一等公民 / 泛型是编译期单态化 / 闭包是捕获环境的一等值」——写完再对教练版。
3. 等教练出 T1 拷问题集 → 闭卷作答 → 代码题挂项目 1.2（COW 实现）。
4. 环境准备：`swift --version` 确认本机工具链，建 `代码/T1/` 子夹。
5. 跑完记台账，全过写费曼稿（含 OC 对比小节），否则复攻。
