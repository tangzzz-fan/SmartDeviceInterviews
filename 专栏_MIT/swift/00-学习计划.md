## 一、原料策略

教材原为外部知识库的 iOS 笔记集（见第二节「原料出处」列）；本仓库脱库自包含后，**原料不再是运行时依赖**——五轮出题集的模型骨架与考点已由教练按既有知识重建并自洽（各 `T{n}-01` 文件头有注明），出题/判定只读本目录文件即可完成。OC 对照资产作为学员的「存量骨架」保留：他已有 UIKit/GCD/RunLoop/内存管理功底，三问的共识模型主动挂靠这些旧知做迁移锚点（如 GCD → async、delegate → 状态注入、手动 retain/release → ARC + 值语义）。

## 三、每主题执行流程（教练 + 学员双 agent 仿真）

沿用双 agent 仿真格式（四件套规范见 [[04-方法论基座-MIT三问与测试协议.md|方法论基座]]，格式范例即本目录 T1–T5 既有产出），每主题产出四件套：

1. **教练出题**：读上表对应原料 → 出「共识五模型 + 争议三焦点」→ 出拷问题（概念口述题 + 代码任务题，各配弱/中/强三级提示与评分要点）。落 `T{n}-01-教练出题-<主题>.md`。
2. **学员作答**：严格按 [[01-学员人设卡.md|人设卡]] 作答——该对的凭 OC 功底对，该错的地方如实错，禁止全知全能。落 `T{n}-02-学员作答-<主题>.md`。
3. **批改判定**：逐题判 过关 / 半过（拆判分点）/ 未过；概念题看「能否讲出为什么并迁移新场景」，代码题看本机是否跑通。落 `T{n}-03-批改与判定-<主题>.md`。
4. **费曼写回**：全过的主题用自己的话重写一篇草稿落本目录（`T{n}-04-费曼草稿-<主题>.md`）；未过的缺口记台账复攻，不写草稿。

**代码通道环境**：代码题的最小可跑实现放本目录 `代码/` 子夹（每个 `.swift` 文件顶部注释标注对应题号），用本机 `swift` CLI 运行，输出贴回批改文件作为硬验证证据。「AI 说我懂了」不算数，跑通才算数。完整工程骨架不孤立写片段，挂靠 [[02-项目驱动实践路线.md|项目驱动实践路线]] 的对应 Phase 迭代项目（绑定关系见第七节）；Instruments 类交付物在仿真阶段记为「待真机验证」，不冒充硬验证。

### 定向评估：「UIKit+Combine → SwiftUI+Concurrency」迁移框架（2026-08-15 补）

若把迁移框定精确到 **源栈 = Swift + UIKit + Combine、目标栈 = SwiftUI + Swift Concurrency**（不依赖外部知识库，只凭本目录自包含内容），结论：**知识内容不缺反而有余，但存在两处结构性偏差需校正。**

**逐轴映射检查**：

| 迁移轴 | 覆盖情况 | 依据 |
|--------|---------|------|
| UIKit → SwiftUI 范式与状态 | ✅ 覆盖 | T2 全题 + T2 Q4 设置页改写实操；互混桥接在 Phase 2.4 |
| Swift 语言核心 | ✅ 覆盖 | T1 |
| Concurrency 作为目标栈 | ✅ 覆盖 | T3 |
| Combine → Concurrency 分工边界 | ✅ 覆盖 | T4 三轴判定 + T5 Q4 段二 values 桥实操 |
| 凭证生命周期 → 结构化并发寿命 | ✅ 覆盖 | T4 C1（不存即取消）+ T5 M5（凭证长寿翻面） |
| 操作符链 → AsyncSequence/AsyncAlgorithms 替换 | ⚠️ 偏薄 | T4 Q1 是「用 Combine 建管道」，没有「存量 debounce/throttle/retry 管道迁往 AsyncAlgorithms」的迁移演练 |
| @Published/ObservableObject ViewModel → @Observable | ⚠️ 偏薄 | T5 Q4 段三只量了爆炸半径（6:3），没有存量 @Published 链路的重构实操 |
| UIKit 增量迁移切分（逐屏迁、UIHostingController 混合托管） | ⚠️ 偏薄 | Phase 2.4 存在但拷问线只在 T2 Q4 顺带 | 

**结构性偏差一：视角倒置（已按真实画像校准）**。本计划把 Combine 当**目标侧新知**教（仿真人设是「Combine 零基础的 OC 老手」）；而真实学员的起点是「会一点 Swift、纯 Swift 完整项目经验、用过 Combine 但不多」（学员本人澄清，见 [[01-学员人设卡.md|人设卡]] 校准注记）——Combine 对他是**半存量**，「从 swift+combine 向 swiftui+concurrency」的框定同样准确。知识不浪费——T4 的背压/凭证/三轴判定恰是「留什么、换什么、桥什么」决策的前提，且对「用得不多」的画像 T4 暴露点基本仍成立，T1–T5 结果不回改。后续增量轮（T6）出题按校准后画像执行：拷问重心打迁移决策而非 Combine 入门。

**结构性偏差二：「替换迁移工程」缺独立轮次**——**已于 T6 闭环清偿**（2026-08-15）：操作符管道→AsyncSequence（Q1）、@Published→@Observable 重构（Q2）、寿命移交（Q3）、混合共存（Q4）三支柱全落地，判定见 [[T6-03-批改与判定-Combine到async迁移实操.md|T6 批改]]。另注：本框架下源栈已是 Swift，原缺口「OC–Swift 混编」从必修降为可选（仅项目含 OC 遗留时才需），被「UIKit–SwiftUI 混合托管」替代。

**候选增量 T6（Combine → async 迁移实操）**：①存量操作符管道 → AsyncSequence/Swift Async Algorithms；②@Published ViewModel → @Observable/@Bindable 重构；③增量迁移切分与混合托管。~~判定规则：项目线 Phase 4.1/4.4/2.1 真实碰到存量 Combine 管道或 ViewModel 重构时开轮，不为开而开~~ **已开轮并闭环（2026-08-15）**：由学员明确指令触发（触发条件调整如实记于 T6-03 第四节），产出见 `T6-01`～`T6-04` 与 `代码/T6/`。
