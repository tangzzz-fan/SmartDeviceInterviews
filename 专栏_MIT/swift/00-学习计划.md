# MIT 三问攻坚：OC 老手迁移现代 iOS 栈 —— 学习计划

## 一、原料策略（改造 3：不重新喂资料，用库内笔记）

教材 = `20_领域/01-iOS开发/` 现有笔记。OC 对照资产同时作为学员的「存量骨架」：他已有 UIKit/GCD/RunLoop/内存管理功底，三问的共识模型应主动挂靠这些旧知做迁移锚点（如 GCD → async、delegate → 状态注入、手动 retain/release → ARC + 值语义）。

## 三、每主题执行流程（教练 + 学员双 agent 仿真）

沿用 L2 仿真格式（见 `_skilltest/MIT三问skill测试/`），每主题产出四件套：

1. **教练出题**：读上表对应原料 → 出「共识五模型 + 争议三焦点」→ 出拷问题（概念口述题 + 代码任务题，各配弱/中/强三级提示与评分要点）。落 `T{n}-01-教练出题-<主题>.md`。
2. **学员作答**：严格按 [[01-学员人设卡.md|人设卡]] 作答——该对的凭 OC 功底对，该错的地方如实错，禁止全知全能。落 `T{n}-02-学员作答-<主题>.md`。
3. **批改判定**：逐题判 过关 / 半过（拆判分点）/ 未过；概念题看「能否讲出为什么并迁移新场景」，代码题看本机是否跑通。落 `T{n}-03-批改与判定-<主题>.md`。
4. **费曼写回**：全过的主题用自己的话重写一篇草稿落本目录（`T{n}-04-费曼草稿-<主题>.md`）；未过的缺口记台账复攻，不写草稿。

**代码通道环境**：代码题的最小可跑实现放本目录 `代码/` 子夹（每个 `.swift` 文件顶部注释标注对应题号），用本机 `swift` CLI 运行，输出贴回批改文件作为硬验证证据。「AI 说我懂了」不算数，跑通才算数。完整工程骨架不孤立写片段，挂靠 [[02-项目驱动实践路线.md|项目驱动实践路线]] 的对应 Phase 迭代项目（绑定关系见第七节）；Instruments 类交付物在仿真阶段记为「待真机验证」，不冒充硬验证。

## 四、执行纪律（照搬测试协议 C1–C5）

| # | 纪律 | 在本攻坚中的含义 |
|---|------|----------------|
| C1 | 先弱提示 | 学员卡住时先只定位概念不给方向；学员立刻想到答案说明提示太强，降级重出 |
| C2 | 拒答代学 | 学员直接要答案 → 拒给，反问已排除了什么 |
| C3 | 双通道强制 | 概念口述过关后必须追加代码任务，只有口述不算过关 |
| C4 | 台账如实 | 未过不得写「过关」，半过必须拆判分点注明缺口 |
| C5 | 产出落 inbox | 全部产出落本目录，审查吸附是后话，不直写 `20_领域/` |

失败标准（出现即说明仿真失真，需重跑）：学员 agent 全题全对（人设失效）、或代码题全靠教练代写也能判过（C3 失守）。

## 六、执行节奏

- 每主题一轮闭环（出题 → 作答 → 批改 → 费曼），跑完记台账再开下一主题；未过缺口先复攻再前进。
- 拷问与项目双线并行：拷问题暴露的缺口优先复攻，项目迭代提供硬验证实体；两边互相出题（项目里踩的坑可转为拷问题）。
- 进度：T1、T2、T3、T4 均已闭环（四件套齐，见 `T1-01`～`T1-04`、`T2-01`～`T2-04`、`T3-01`～`T3-04`、`T4-01`～`T4-04`；代码落 `代码/T1/`～`代码/T4/`），**下一站 T5 性能优化整合（前四主题收束），等库主指令**。

规则：

1. 拷问的代码题若主题命中上表，优先直接长在该迭代项目上，避免孤立片段；未命中才退回最小 `.swift` 片段。
2. 项目交付物（如 Instruments 报告、编译时间分析）在仿真阶段无法真机执行时，按 C4 如实记「半过/待真机验证」，不记过关。
3. 原路线的「关键对比任务」（OC 与 Swift 双实现）作为每主题费曼草稿的固定骨架：费曼稿必须含一段迁移对比小节。
