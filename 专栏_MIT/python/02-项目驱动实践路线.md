# 项目驱动实践路线（代码通道载体）

> 定位：本文件是 [[00-学习计划.md|学习计划]] 代码通道的**工程载体**——MIT 三问负责拷问与判定纪律，本路线的迭代项目负责提供「可运行的完整骨架」。各 Phase 与 T1–T5 的绑定见 [[00-学习计划.md#七、代码通道载体绑定|学习计划第七节]]。
> 格式参照：Swift 线 [[../MIT-Swift-migration/02-项目驱动实践路线.md|同名文件]]；五条原则与其一致，仅迁移对比透镜改为 Swift ↔ Python。

## Agent 角色定义

**身份**: 从 iOS/Swift 转向 Python 与 LLM 方向的开发者 Agent
**背景**: 十年 iOS 工程经验，Swift 迁移已收官；Python 有刷题与脚本存量但无完整工程实践；大学数学公式残存、直觉清零；PyTorch 仅跑过教程 notebook。
**目标**: 以 MIT 学习方式（项目驱动、快速迭代、从实践中学习）复习 Python 工程级基础、重建线代与概率论直觉、掌握 PyTorch 训练闭环、用 Python 标准库武器重写算法存量，并掌握 async/await 并发编程与 LLM 企业落地工程化实操。
**约束**: 所有学习必须通过可运行的代码项目验证，禁止纯理论阅读；每个阶段必须有明确的可交付物（Deliverable）；数学类交付物必须附「直觉解释」，只有数值结果不算交付完成。

---

## MIT 学习方式核心原则

1. **项目驱动 (Project-Based)**: 每个知识模块都绑定一个可运行的项目，而非孤立练习。
2. **快速迭代 (Rapid Iteration)**: 每个项目从 MVP 到优化版控制在 3-5 个迭代周期内，每个周期有明确的功能增量。
3. **从错误中学习 (Learning by Debugging)**: 主动制造边界场景（可变默认参数、浅拷贝矩阵、in-place 张量操作、梯度累加），通过运行报错与断言失败反向推导底层机制。
4. **第一性原理 (First Principles)**: 不满足于"怎么做"，必须追问"为什么这样设计"——从动态类型、引用语义、解释执行的底层约束推导 Pythonic 实践；数学部分必须落到几何/概率直觉，公式不算终点。
5. **迁移对比 (Migration Lens)**: 始终对比 Swift 中的等效实现与心智模型，明确范式差异（值语义 vs 引用语义、编译器兜底 vs 测试兜底、静态分发 vs duck typing），避免用 Swift 思维写 Python。

## 学习路线图

### Phase 1: Python 工程基础重塑 (Week 1)
**核心目标**: 从"会写 Python 语法"到"用 Python 心智写代码"，戒掉 Swift 值语义依赖，建立引用语义 + 协议（魔术方法）的新心智。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 1.1 | 生成器分页加载器 | 大文件/大数据源的分页读取器，支持 for 消费与手动 next | 迭代器协议、yield、生成器惰性、StopIteration |
| 1.2 | 上下文管理器资源守卫 | with 语法的文件/锁/计时守卫，含 `contextlib` 版 | `__enter__`/`__exit__`、@contextmanager、异常传播 |
| 1.3 | 装饰器工具箱 | 带参重试、LRU 缓存、耗时打点装饰器 | 闭包、带参装饰器、functools.wraps |
| 1.4 | 引用语义翻车合集 | 可变默认参数、浅拷贝矩阵、函数副作用的最小复现集 + 修复 | 可变对象、copy/deepcopy、is vs == |
| 1.5 | GIL 与并发边界实验 | CPU 密集 vs IO 密集在多线程/多进程/asyncio 下的耗时对比报告 | GIL、multiprocessing、asyncio 适用边界 |

**关键对比任务**: 1.4 与 1.5 各写一份 Swift 对照说明（Swift 值语义如何天然免疫 1.4 的坑；actor/GCD 与 GIL 模型的差异）。

---

### Phase 2: 线性代数直觉重建 (Week 2)
**核心目标**: 把残存的公式记忆重建成几何直觉，用 numpy 落地，最终能解释「为什么神经网络的前向传播就是矩阵乘法链」。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 2.1 | 手写矩阵运算库 | 纯 Python 实现 matmul/transpose/求解，与 numpy 对拍 | 矩阵乘法定义、形状规则、复杂度 |
| 2.2 | 线性变换可视化 | 二维平面上旋转/剪切/投影的变换前后对照（matplotlib 或字符画） | 矩阵即变换、基变换、秩与降维 |
| 2.3 | SVD 图像压缩 | 取前 k 个奇异值压缩图像，输出不同 k 的重建质量对比 | SVD 分解、奇异值含义、低秩近似 |
| 2.4 | PCA 手写实现 | 协方差矩阵 → 特征分解 → 降维投影，解释最大方差方向 | 特征值/特征向量、协方差、PCA |

**关键对比任务**: 每个项目附一段「给 iOS 同事讲懂」的直觉说明（用图形渲染/SIMD 的类比入口）。

---

### Phase 3: 概率论直觉重建 (Week 3)
**核心目标**: 从「会套公式」到「会用概率语言描述 ML 问题」，打通 MLE → 交叉熵 → softmax 这条 LLM 损失函数的主链路。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 3.1 | 蒙特卡洛实验台 | 大数定律与中心极限定理的数值验证 + 收敛曲线 | 期望、方差、LLN、CLT 适用条件 |
| 3.2 | 手写朴素贝叶斯分类器 | 垃圾邮件/文本二分类，先验后验数值全程打印 | 贝叶斯公式、先验/似然/后验、拉普拉斯平滑 |
| 3.3 | softmax 数值稳定性实验 | 大数值输入下 naive softmax 溢出复现 + max 减除修复 | 指数化动机、数值稳定性、log-sum-exp |
| 3.4 | MLE → 交叉熵推导稿 | 从二项分布 MLE 推到负对数似然再到交叉熵的可跑验证 | MLE、对数似然、交叉熵 |

**关键对比任务**: 3.2 用 Swift 写一份对照实现，体验动态类型下概率计算的调试差异。

---

### Phase 4: PyTorch 训练闭环 (Week 4)
**核心目标**: 拆掉「教程肌肉记忆」，把训练循环五步的每一步都讲到机制；先手推反向传播再上 autograd，理解计算图。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 4.1 | 纯 Python 手推反向传播 | 两层 MLP 前向 + 手写梯度更新，不用 torch | 链式法则、梯度累加、矩阵求导形状 |
| 4.2 | torch 训练循环迁移 | 把 4.1 迁到 nn.Module + autograd，与 4.1 梯度数值对拍 | 计算图、backward、zero_grad、optimizer.step |
| 4.3 | 梯度诊断工具箱 | 梯度爆炸/消失、不 zero_grad 的累加爆炸、in-place 翻车的最小复现集 | requires_grad、detach、no_grad、in-place 陷阱 |
| 4.4 | Dataset/DataLoader 管道 | 自定义 Dataset + collate_fn + 批训练完整管道 | Dataset、DataLoader、shuffle、num_workers |

**前置约束**: Phase 4 开跑前必须先在项目 venv 装 torch（`uv pip install --python .venv/bin/python torch`，见 [[00-学习计划.md|学习计划]] 第三节代码通道环境）并实测；环境未就绪的代码题按 C4 记「待环境验证」。

### Phase 5: 算法存量 Python 化 (Week 5)
**核心目标**: 把 Swift 刷题存量翻译成 Python 标准库武器，补上解释型语言的复杂度常数直觉。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 5.1 | LRU 缓存 | OrderedDict 版 + 手写双链版，与 Swift 实现对照 | 哈希 + 双链、OrderedDict、O(1) 操作 |
| 5.2 | 流式 Top-K | heapq 维护 K 大元素，对比排序法的耗时曲线 | 堆、bisect、复杂度权衡 |
| 5.3 | DP 专题 | 背包/打家劫舍/最长子序列，含 `[[0]*n]*m` 陷阱复现与修复 | DP 状态设计、浅拷贝陷阱复发验证 |
| 5.4 | Python 耗时常数报告 | 同一算法 Swift vs Python 实测耗时 + 解释型开销分析 | 解释执行、常数因子、何时该换实现 |

**关键对比任务**: 每个项目保留 Swift 版实现做双实现对照，费曼稿以对比小节为骨架。

### Phase 6: async 与企业落地 (Week 6，T6 显式增量轮载体)
**核心目标**: 把 Swift Concurrency 收官经验平移成 asyncio 心智，再用「并发调 LLM API」这个企业落地主场景把 async、限流重试、流式消费、pytest 与依赖管理串成工程闭环。

| 迭代 | 项目 | 交付物 | 核心知识点 |
|------|------|--------|-----------|
| 6.1 | asyncio 基础实验 | 协程调度、gather/TaskGroup、取消传播的最小实验集 | 事件循环、协程对象 vs 执行、取消语义 |
| 6.2 | 并发 LLM API 网关（mock） | Semaphore 限流 + 重试 + 超时 + 结构化取消的并发调用器 | Semaphore、asyncio.timeout、TaskGroup、阻塞调用危害 |
| 6.3 | 流式响应消费管道 | 异步迭代器消费 mock 流式输出（逐 token），含背压式缓冲 | async for、异步生成器、aiter 协议 |
| 6.4 | 工程化基础 | pytest 覆盖 6.2/6.3 + uv 依赖清单 + logging 结构化日志 | pytest、uv、日志与配置 |

**关键对比任务**: asyncio.TaskGroup 与 Swift 结构化并发（withTaskGroup/取消传播）逐项对照表；阻塞调用杀 loop 的实测数据（并发度崩塌前后）。
