# 方法论基座：MIT 三问学习法与测试协议（自包含版）

> 用途：本目录全部拷问轮的方法论出处。本文件与 Swift 线（[`../MIT-Swift-migration/04-方法论基座-MIT三问与测试协议.md`](../MIT-Swift-migration/04-方法论基座-MIT三问与测试协议.md)）同源——按仓库约定（C5：产出落本目录、脱库自包含），每个迁移目录各自持有一份，Python 线以本文件为准，不依赖外部知识库。
> 关系说明：[[02-项目驱动实践路线.md|项目驱动实践路线]] 的五条原则是「学法约束」，本文件的三问拷问法是「验收判定」，两者互补不冲突。

## 一、MIT 三问学习法（方法本源）

一句话：**不教答案，用拷问逼出共识模型，用代码硬验证，用费曼讲回。**

### 三问结构

1. **共识模型**：一个主题先收敛成少数几个「骨架模型」（本项目每轮 5 个）。模型不是知识点清单，是能解释大量现象的最小结构——学员必须能用自己的话重推出来。
2. **争议焦点**：挑出该主题下社区真实存在分歧的问题（本项目每轮 3 个）。争议题考的不是标准答案，而是「能否给出有边界的立场」——什么条件下站哪边、证据是什么。
3. **拷问题**：概念口述题 + 代码任务题双通道，每道题配弱/中/强三级提示。先闭卷硬推，卡住逐级要提示，绝不直接要答案。

### 四点改造（本项目落地版）

1. **双 agent 仿真**：教练 agent 出题批改，学员 agent 按人设卡作答——人设决定哪里该对、哪里该错，禁止全知全能。
2. **旧知挂靠**：学员已有的存量知识（本线为 iOS/Swift 工程功底 + 大学数学残存记忆 + 刷题存量）作为迁移锚点，共识模型主动挂靠旧知，不像的地方才是真正的学习区。
3. **硬验证优先**：代码必须本机跑通、输出贴回批改稿；「AI 说我懂了」不算数。仿真阶段无法本机执行的交付物（如 torch 环境未就绪）如实记「待环境验证」，不冒充。
4. **费曼写回**：主题全过后用自己的话重写一遍草稿（含 Swift/iOS 对照小节）；被追问问倒就退回复攻。

### 复习线补充条款（Python 线特有）

复习线与迁移线的区别：学员对主题有**残存记忆**，失真的主要形态不是「不会」而是「以为会」。补充判定：

- **数学题**：会算但讲不出几何/概率直觉 = 半过，直觉重建后复攻销账；
- **语言题**：能写出能跑但带 Swift 味（用错习惯、绕开 Pythonic 设施）= 半过，标注「习惯债」；
- **假过关检测**：教练对「答得太顺」的复习题追加一道变式题，变式卡住即原判降档。

## 二、测试协议 C1–C5（执行纪律，照抄有效）

| # | 纪律 | 含义 |
|---|------|------|
| C1 | 先弱提示 | 学员卡住先只定位概念不给方向；学员立刻想到答案说明提示太强，降级重出 |
| C2 | 拒答代学 | 学员直接要答案 → 拒给，反问已排除了什么 |
| C3 | 双通道强制 | 概念口述过关后必须追加代码任务，只有口述不算过关 |
| C4 | 台账如实 | 未过不得写「过关」，半过必须拆判分点注明缺口 |
| C5 | 产出落本目录 | 全部产出落迁移目录内，不直写外部知识库 |

## 三、人设三档与失真标准

- **人设档位**：低档（零基础）、中档（有相邻领域存量，本项目采用）、高档（半专家）。档位决定提示分级的区分度怎么考。
- **失真标准**（出现即说明仿真失效，需重跑）：
  1. 学员全题全对 → 人设失效；
  2. 代码题全靠教练代写也能判过 → C3 失守；
  3. 台账把半懂写成过关 → C4 失守；
  4. （复习线附加）数学题靠套公式算对即判过关、无直觉解释 → 复习失真；
  5. （双分支协议）学员分支混入提示、评分要点或参考答案（含误合并教练分支）→ 泄漏，该轮作废重跑。

## 四、判定三档

- **过关**：能讲出为什么、能迁移到新场景；代码通道要求本机跑通且逐行能讲。
- **半过**：方向对但机制讲不出 / 代码跑通但有撞墙未复盘 / 会算但无直觉——必须拆判分点（√/△/✗）。
- **未过**：方向错或纯猜。半过/未过挂台账复攻，复攻通过才销账。
