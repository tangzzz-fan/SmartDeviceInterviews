## 〇、五模型自推（先写再对本）

自推版本：① LRU = 哈希表加双向链表，get/put 都 O(1)；② Top-K 用堆，维护大小为 K 的堆；③ DP 三件套：状态、转移、初始化，Python 初始化有个乘号陷阱；④ Python 比 Swift 慢，要用内置函数；⑤ 标准库有 bisect/heapq/deque/Counter，刷题常用。

对教练版差异：M1 我漏了「OrderedDict 就是标准库化身」这层（move_to_end/popitem 我会用但没把它和 LRU 结构画上等号）；M2 我说「维护大小为 K 的堆」时没过脑「哪种堆、堆顶语义是什么」——最小堆维护 K 大、堆顶是门槛，这层是写 Q2 时才逼自己说清的；M4 我只有口号「Python 慢要用内置」，「复杂度定增长、常数定起点」这层——被 Q1 的墙当场教做人（见下）。

## 一、概念口述通道

**C1（LRU 三连）**：① 单哈希表缺「顺序」能力——哈希给你 O(1) 定位，但「谁最久没用」是顺序信息，哈希表本身不记访问序，得外挂一个可 O(1) 挪动位置的结构（双链）。② get 命中：哈希定位节点→从链上摘下→接到头部→返回值；未命中：返回 -1。put 命中：更新值→挪头部；未命中且满：摘尾节点→哈希删键→新节点接头部+入哈希。③ OrderedDict 内部是哈希表 + 双向链表的合体（dict + 链），move_to_end 就是「摘下接尾/头」，popitem(last=False) 就是「摘头+删哈希」——它就是 LRU 的标准库实现。自评：**有把握**（刷题存量，但③的「内部维护了什么」是背过的结论，没拆过源码）。

**C2（堆三连）**：① 维护「K 个最大」用**最小堆**：堆顶是这 K 个里最弱的（门槛），新来的比门槛大才替换——淘汰判断只看堆顶 O(1)；用最大堆的话最弱者藏在叶子层，找它要 O(k)。② insort 维护有序列表：bisect 定位 O(log k)，但 list.insert 要把后面的元素整体搬移，**O(k)**——二分只解决「找位置」，不解决「挪数据」。③ 第 K 大：排序 O(n log n)；堆 O(n log k)；快速选择平均 O(n)（最坏 O(n²)，随机化保平均）。自评：**有把握**（②的 O(k) 搬移写 Q2 前嘴上会说，心里其实还押着「二分所以快」，见 Q2 墙1）。

**C3（打家劫舍现场推）**：① dp[i] = 偷到第 i 家为止的最大金额；② dp[i] = max(dp[i-1], dp[i-2] + nums[i])（不偷 i / 偷 i 则 i-1 必不偷）；③ 两个变量 prev2/prev1 滚动，每步算 cur 后整体前移，O(1) 空间；④ 环形：首尾不能同时偷——拆成两个线性问题：偷 [0, n-2] 与偷 [1, n-1]，取 max；边界 n=1/n=2 单独处理。自评：**有把握**。

**C4（别名三连）**：① `[[0]*n]*m`：外层 `*m` 复制的是**同一个列表对象的引用** m 份——m 行指向同一行，改任何一行全体变（Q3 陷阱复现区打了 id 证据）。② Swift 的 `Array(repeating: Array(repeating:...), count:)`：Array 是值语义，初始化时内层数组被**逐份拷贝**，每份独立存储（CoW 只延迟写时复制，不共享可变状态）——T1 学的，这次接上了。③ 两种正确写法：列表推导 `[[0]*n for _ in range(m)]`（每次迭代求值一次，生成 m 个独立列表）；numpy `np.zeros((m,n), dtype=int)`（C 层连续内存，压根没有「行对象」共享问题）。推导式安全的原因：for 每轮都重新执行 `[0]*n` 这个表达式，产生新对象。自评：**有把握**（T1 病灶知识在线）——**但 Q3 里手还是滑了，复发记录见第四节**。

**C5（内置快过手写）**：`sorted()` 是 C 实现的 Timsort：循环在 C 层跑，直接操作对象指针数组；手写快排的每一步比较、交换、递归都是字节码逐条解释执行，每条指令都要走解释器分发——同样 O(n log n)，常数差一到两个数量级（Q4 实测手写归并慢 12×）。同类例子：`sum()` 快过 for 累加（实测 4×）、`Counter` 快过手写 dict 计数、`str.join` 快过 `+=` 拼串。自评：**有把握**。

**C6（滑窗最大值）**：① 单调递减 deque：新元素从尾部入队前，把比它小的全弹掉（维护单调性）；每个元素最多进队一次、出队一次，弹人操作看着 O(n) 其实**摊销 O(1)**——总弹次数不超过总入队次数 n。整体 O(n)。② 堆解法：窗口滑走时堆里的过期元素没法立刻删（堆不支持按值 O(1) 删），只能「懒删除」——取堆顶时发现过期就弹掉再看下一个；复杂度 O(n log n)（每次插入 log n），退化点在堆里积压的过期元素让堆远大于窗口 k，最坏堆大小 O(n)。③ 取舍：要 O(n) 最优、窗口大→单调队列；代码短优先、n 不大→堆+懒删除也能过，且「懒删除」模式在需要取最值又要删任意元素的场景（如 Dijkstra 的懒删除版）是通用武器。自评：**有把握**（摊销分析是现场推的，推完自己验了一遍「总弹≤总入」才敢说）。

## 二、争议焦点

**F1（手写双链 vs OrderedDict）**：面试场景手写——考的就是「LRU = 哈希+双链」的结构认知，直接用 OrderedDict 等于跳过考点（多数面试官会追问内部实现）；生产场景直接 OrderedDict（或 functools.lru_cache）——标准库经过千万人踩坑，自己手写双链的断链、环、并发问题都是负债。判据一句话：**答题场合写机制，工程场合用标准库**。自评：**有把握**。

**F2（排序 vs 堆取 Top-K）**：复杂度只比增长：排序 O(n log n) 对 k 无感，堆 O(n log k)。但实际胜负看常数与 k/n：n=1000 时排序的 C 层 sorted() 大概率快过 Python 层 heapq 逐元素入堆（解释器开销吊打算法差异）；n=1 亿、k=100 时堆法优势碾压（log k≈7 vs log n≈27，且流式不用全量驻留内存）。判据：k/n 大（比如 >0.1）或 n 小 → 排序；k 远小于 n 且 n 大/流式 → 堆。Q2 实测全对上了：n=1e4 三法贴一起，n=1e6、k=10 时堆法 0.028s vs 排序 0.226s。自评：**有把握**（这题是 Q2 数据喂出来的，不是背的）。

**F3（Python 慢到什么程度换实现）**：触发线我给三条可量化的：① 该热点占总耗时 >30%（profile 出来的，不是猜的）且纯 Python 循环占该热点 >90%；② 同等数据量下 numpy 向量化能把该段压到 1/10 以下（Q4 实测 sum 压到 1/126）——能向量化就先向量化，别急着上 C 扩展；③ 多进程只在 CPU bound 且绕过 GIL 收益明确时用，触发线是单核跑满且任务可切块。顺序纪律：先内置函数 → 再 numpy 向量化 → 再考虑 C 扩展/换语言——每一级都是「复杂度升、维护成本升」，没有 profile 数据不动手。自评：**有把握**（量化线是现场把 Q4 数字倒推出来的）。
