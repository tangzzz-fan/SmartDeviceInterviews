## 一、共识模型（教练版五个骨架）

学员先自推五模型再对本版，标注差异。

| # | 模型 | 一句话骨架 |
|---|------|-----------|
| M1 | LRU = 哈希表 + 双链：两个 O(1) 的乘积 | 哈希 O(1) 定位节点，双链 O(1) 挪到头部/摘尾；OrderedDict 是标准库化身（move_to_end + popitem） |
| M2 | 堆是「流式 Top-K」的答案，但要选对堆 | heapq 是**最小堆**：维护 K 大用大小 K 的最小堆（堆顶是门槛，来了比它大才换）；总复杂度 O(n log k) |
| M3 | DP 三件套：状态定义 → 转移方程 → 初始化边界 | Python 初始化有引用语义专属陷阱（`[[0]*n]*m` 是 m 个同一行的别名）；空间可滚动压缩 |
| M4 | 解释型语言的复杂度常数：类同数不同 | Python 纯循环比 Swift 慢一到两个数量级；C 实现的内置武器（sorted/sum/Counter）把常数拉回来——复杂度定增长，常数定起点 |
| M5 | 标准库武器表：bisect/heapq/deque/Counter/切片 | 手写二分、手写计数、手写滑窗都是「武器旧」的信号；每个武器背一句适用边界 |

## 二、争议焦点（三题，考有边界的立场）

- **F1**：手写双链 LRU vs 直接用 OrderedDict——面试场景与生产场景的答案不一样，分别给立场和理由。
- **F2**：Top-K 用排序（O(n log n)）还是堆（O(n log k)）？n=1000 和 n=1 亿时答案可能相反——复杂度类比的是增长，常数与 k/n 比值决定实际胜负，给判据。
- **F3**：Python 慢到什么程度该换实现（numpy/C 扩展/多进程）？「先 profile 再动手」之外，给出可量化的触发线。

## 三、拷问题——概念口述通道（C1–C6）

**C1（M1）**：LRU 机制三连——① 为什么单靠哈希表做不到 LRU（缺了什么能力）？② get/put 命中与未命中各自的指针操作序列讲一遍；③ OrderedDict 的 `move_to_end`/`popitem(last=False)` 为什么就是 LRU——它内部维护了什么？

**C2（M2）**：① heapq 是最小堆，维护「K 个最大」为什么用最小堆而不是最大堆？堆顶的语义是什么？② 流式场景为什么 `bisect.insort` 维护有序列表不行——插入的复杂度是多少，为什么？③ n 个数取第 K 大的三种做法（排序/堆/快选）平均复杂度各是多少？

**C3（M3）**：打家劫舍现场推：① 状态怎么定义；② 转移方程；③ 滚动变量压缩空间（两个变量版）；④ 如果房子围成环（打家劫舍 II）状态设计要动哪里？

**C4（M3）**：`[[0]*n]*m` 三连——① 它到底创建了什么（引用图讲清楚）；② Swift 里 `Array(repeating: Array(repeating: 0, count: n), count: m)` 为什么没有这个问题（值语义做了什么）；③ Python 正确写法给两种，并说出列表推导式版为什么安全。

**C5（M4）**：同一个 O(n log n)：Python 内置 `sorted()` 常常快过「Python 手写快排」——为什么？讲出「C 层循环 vs 字节码层循环」的差别，再举两个同类例子（内置武器吊打手写循环的）。

**C6（M5/M2）**：滑动窗口最大值（LeetCode 239）：① 单调队列（deque）解法的复杂度与「单调」维护的摊销分析；② 为什么堆解法要「懒删除」，复杂度退化在哪；③ 两解法的取舍判据。
