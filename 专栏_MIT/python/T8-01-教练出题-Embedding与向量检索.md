# T8-01 教练出题：Embedding 与向量检索（RAG 基座）（独立增量轮）

> 本轮补「LLM 企业落地的检索面」：embedding 语义化、文档切分、向量检索、RAG 管道与召回评估。全部用本地可跑实现（numpy + mock embedding），不依赖外部向量库即可闭环；faiss 作为可选升级对照。
> 复习线条款：① 性质断言兜底、测量方法学沿用；② 费曼稿必须含「精确 top-k vs ANN」取舍表；③ 代码一律 `.venv/bin/python` 实跑。
> 使用纪律：卡住按弱→中→强逐级要提示（密卷在教练分支），直接要答案 → 反问「你的测试集和指标是什么」。

## 一、共识模型（教练版五个骨架）

| # | 模型 | 一句话骨架 |
|---|------|-----------|
| M1 | Embedding 把文本变成「语义坐标」 | 语义相近的文本在向量空间距离近；相似度用余弦 |
| M2 | 检索质量取决于切分 | chunking 策略（语义/固定+重叠）决定召回边界与上下文完整性 |
| M3 | 向量检索是近似最近邻问题 | 精确 top-k（numpy 全量）→ ANN（faiss）的取舍：规模与召回率 |
| M4 | RAG 管道 = 切分 → 向量化 → 存储 → 召回 → 组装上下文 | 每一环都有失败模式，评估是工程不是感觉 |
| M5 | 召回评估要量化 | 小测试集 + hit@k / MRR，比较不同策略 |

## 二、争议焦点（三题，考有边界的立场）

- **F1**：固定大小切分 vs 语义切分，企业默认该用哪个？
- **F2**：精确检索 vs ANN（faiss），什么时候升级？
- **F3**：RAG 是终局方案还是过渡（RAG vs 微调 vs 超长上下文）？

## 三、拷问题——概念口述通道（C1–C6）

**C1（M1）**：为什么用余弦相似度而不是欧氏距离？embedding 向量「语义坐标」的直觉怎么建立？给一个「字面不同但语义相近」的例子。

**C2（M2）**：固定大小 + 重叠切分 vs 按段落切分，各自的边界效应是什么？一个事实被拦腰截断时，召回会发生什么？

**C3（M3）**：精确 top-k 在什么规模下撑不住？ANN（faiss）牺牲什么换什么？「近似」对业务的影响什么时候可接受？

**C4（M4）**：RAG 管道每一环的失败模式各是什么（切分切断事实 / 向量化噪声 / 召回漏检 / 上下文超长 / 组装无序）？怎么定位问题出在哪一环？

**C5（M5）**：hit@k 和 MRR 分别怎么算、各自回答什么问题？为什么「凭感觉看结果」不算评估？

**C6（M1/M4）**：embedding 用 API 还是本地模型？维度（768/1536/3072）与成本/质量怎么权衡？对「企业内部文档检索」的场景给出选择与理由。

## 四、拷问题——代码任务通道（Q1–Q4）

**Q1（挂项目 8.1，M1）**：**numpy 余弦相似度 + 精确 top-k**。mock 一个小语料（10 段文本 + 确定性 mock embedding：可基于字符特征生成向量，保证同类文本相似度高），实现余弦矩阵 + 给定 query 返回 top-k。实跑证明相似度排序符合直觉。

**Q2（挂项目 8.2，M2）**：**文档切分器**。实现两版：固定大小 + 重叠（word 级窗口）vs 按段落。对同一段长文档切分，打印各 chunk 的边界，指出「一个事实被切断」的具体例子。

**Q3（挂项目 8.3，M4）**：**迷你 RAG**。管道：切分 → mock embedding → 精确 top-k → 组装上下文（拼接 + 顺序 + token 预算截断）→ 打印组装结果。用 Q2 的两种切分策略各跑一遍，比较召回上下文质量。

**Q4（挂项目 8.4，M5）**：**召回评估**。建 10 个查询的小测试集（每个标注应命中的 chunk id），实现 hit@1 / hit@5 / MRR，比较「固定+重叠」与「按段落」两种策略的指标差异，给出结论。
