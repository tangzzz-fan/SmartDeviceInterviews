# T7-04 费曼草稿：LLM API 客户端与提示工程实践（示例）

> **示例文件**：演示「脱稿重推 + 对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 API 客户端是协议翻译层**：httpx 直连 + 薄封装，保留控制权（响应头、Retry-After、多 provider）。
- **M2 错误是类型化的**：超时/429/5xx 可重试（暂时性）；上下文长度/校验失败不可重试（确定性失败）。
- **M3 重试要退避、抖动、有预算**：Retry-After 优先；预算 = 最大次数 + 最大总时长，超了转降级。
- **M4 并发与限流是网关职责**：Semaphore 管在飞数、连接池管连接、配额管上游吞吐、有界队列产生背压。
- **M5 提示词是数据**：system 管行为、user/assistant 管事实；token 预算 = 窗口 - 输出预留；结构化输出 = schema + 校验 + 有限重试。

## 二、对照表（httpx 直连 vs SDK）

| 维度 | httpx 直连 | 官方 SDK |
|------|-----------|---------|
| 控制权 | 高（头/重试/打点） | 低（黑盒） |
| 样板 | 自己写协议层 | 零 |
| 多 provider | 统一适配 | 各自为政 |
| 适用 | 企业网关/降级 | 标准小场景 |

## 三、一个例子讲到底

企业网关：httpx 直连 + 错误分类 + 指数退避重试（429 读 Retry-After）+ 熔断（连续 5 次失败短路 10s，半开试探）+ Semaphore 限流。mock 服务器先 429 两次再 200，重试序列打印出来——「重试是工程不是感觉」。

## 四、60 秒讲稿

「调 LLM API 的第一课：错误是类型化的。超时、限流、5xx 可以重试，上下文长度和校验失败重试一万次也没用。重试要有退避、有抖动、有预算，429 要听服务器的 Retry-After。并发不是开一堆协程就完事——Semaphore 管在飞数，连接池管连接，队列有界才有背压。结构化输出别靠提示词碰运气，schema + 校验 + 有限重试四件套。这一轮学完，网关里的每个决定都能说出为什么。」

## 五、自检三问

1. 被问「重试预算是什么」能答（次数 + 总时长）。
2. 能讲给同事听：用了网关例子。
3. 诚实自查：C4 限流/连接池混淆是复攻补上的，属于盲区。
