## 三、复攻记录（提示分级使用台账）

**C1 复攻**（弱提示：「赋值语句里到底复制了什么？」）：学员反应——「什么都没复制，复制的时机只在显式 copy……等等，那 copy 复制的也只是外层容器」。当场改判第 2 段：`a` 变成 `[[1,2,99],[3,4]]`，并主动要求跑 Q1 现场二的 id 输出复核（三行→两组 id）。**提示强度评估**：弱提示即点醒，说明缺口是「没把 M2 套进 copy 场景」而非模型缺失。→ **销账**。

**C2 复攻**（中提示：「函数也是对象，`print(tag.__defaults__)` 验证」）：学员实跑打印出 `(['x', 'y'],)`，补齐链条：def 定义时 `[]` 求值一次 → 挂进函数对象 `__defaults__` → 调用不传参时复用同一对象。能迁移：「所以默认值是不可变对象时没坑，但社区仍建议 None 哨兵，因为签名自文档化且防未来改成可变」。→ **销账**。

**C3 复攻**（弱提示：「`*` 对 list 做的是拷贝还是重复引用？」）：学员第一反应仍是「复制」，降档处理；（中提示：「打印每行 id」）：实跑后三行 id 相同，结论重塑：`[x]*n` 是 n 个指向同一对象的引用，推导式每次循环重新求值才是独立对象；追加自问「那 `[0]*3` 为什么没坑」答出「int 不可变，共享无害」。**未过根因**：Swift「赋值即复制」的肌肉记忆反向干扰，记入观察项（T5 的 DP 初始化是复发高危区，点名复查）。→ **销账，挂观察项**。

**C4 复攻**（弱提示：「list 和生成器对象，谁是工厂谁是消费者？」）：学员借 Q2 撞墙经验直接补全：list 每次 `iter()` 返回新迭代器（工厂），生成器对象 `iter()` 返回自己（自产自销），所以一次性。**提示强度评估**：弱提示即通，且学员自证「Q2 墙2 其实就是这个机制」——代码通道经验反哺概念通道，记为正面案例。→ **销账**。

**C5 复攻**（中提示：「线程在 IO 阻塞时的 GIL 状态是关键差异点」）：学员推出「等 IO 时释放、算字节码时持有」；（追加强提示半级：「GIL 保护解释器的什么东西」）：补到「引用计数等解释器内部状态，多线程并发改引用计数会弄坏内存管理」。能迁移：「所以 numpy 在 C 层算矩阵时主动放锁，Q4 的实验换成 numpy 就测不出 GIL 了」。→ **销账**。

**C6 复攻**（弱提示：「`retry(times=3)` 这行先执行的是什么？」）：学员补全：先执行工厂拿到装饰器，再 `deco(fn)`——「参数得在装饰发生前固化成闭包，所以多一层工厂」；wraps 影响面补齐：`__name__`/`__doc__` 丢失伤调试、文档生成、以及按函数名注册的框架（类比 Swift 里的路由/测试收集）。→ **销账**。

**F3 复攻**（不给提示，直接追问变式）：学员补出「复用中间结果」与「排序等需要物化的操作」，清单收敛为四条：多次遍历、随机访问/长度、复用中间结果、需要物化的下游操作。→ **销账**。

**Q1 复攻**（无新代码要求，口述打通）：学员用复攻后的 C1 认知逐行重讲 Q1 三个现场的 id 证据，概念与代码对齐。→ **销账**。
