# T8-04 费曼草稿：Embedding 与向量检索（示例）

> **示例文件**：演示「脱稿重推 + 对照 + 60 秒讲稿」长什么样，用于格式参考，**不是真实产物**。

## 一、五模型脱稿重推

- **M1 embedding 是语义坐标**：语义近 = 向量近；相似度用余弦（归一化后与欧氏排序一致）。
- **M2 检索质量取决于切分**：固定+重叠保粒度、按段落保语义；事实被切断 = 召回上下文缺主语。
- **M3 向量检索是近似最近邻**：万级 numpy 全量可跑；百万级上 ANN（faiss），牺牲召回率换延迟。
- **M4 RAG 管道五环**：切分 → 向量化 → 存储 → 召回 → 组装；每环都有失败模式，先测召回再谈答案。
- **M5 评估是工程不是感觉**：测试集 + hit@k / MRR + 对照策略。

## 二、对照表（精确 top-k vs ANN）

| 维度 | 精确（numpy 全量） | ANN（faiss） |
|------|-------------------|-------------|
| 召回率 | 100% | 有损（可评估） |
| 延迟 | 万级可接受 | 百万级才需要 |
| 复杂度 | 零依赖 | 索引构建/内存 |

## 三、一个例子讲到底

企业内部文档检索：文档按「固定 200 词 + 30 词重叠」切分 → mock embedding → numpy 精确 top-k → 组装上下文。10 个查询测试集算出 hit@1=0.8、MRR=0.85；换成按段落切分 hit@1=0.6——数字说话，切分策略换了。

## 四、60 秒讲稿

「RAG 的第一块地基是检索，检索的第一件事是评估。embedding 把文本变成语义坐标，余弦算相似；切分决定召回边界，事实被切断答案就会编；万级数据 numpy 精确检索就够，百万级才上 faiss，而且上了 faiss 就要用 hit@k 量化召回损失。管道五环——切分、向量化、存储、召回、组装——每一环都可能坏，先测召回再谈答案。评估不是感觉，是测试集加指标加对照策略。」

## 五、自检三问

1. 被问「什么时候上 faiss」能答（万级精确可跑，百万级 + 召回损失可接受时）。
2. 能讲给同事听：用了企业文档检索例子。
3. 诚实自查：C3 的规模门槛是复攻后推通的，不是天生会。
