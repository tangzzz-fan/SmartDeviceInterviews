## 一、共识模型（教练版五个骨架）

学员先自推五模型再对本版，标注差异。

| # | 模型 | 一句话骨架 |
|---|------|-----------|
| M1 | 一切皆对象，名字只是标签 | 赋值不是「把值装进变量」，而是「把名字贴到对象上」；对象有身份（id）、类型和值，名字本身无类型 |
| M2 | 可变性是默认，隔离要显式 | list/dict/set 是可变共享的；想要隔离必须显式拷贝，且拷贝分深浅两层 |
| M3 | 协议靠魔术方法，duck typing 替代声明 | 行为由 `__xxx__` 定义，调用方不查类型只查行为；「看起来像鸭子就当鸭子用」 |
| M4 | 迭代器是统一的消费接口 | for 循环 = `iter()` + 反复 `next()` + `StopIteration` 收场；生成器是一次性的惰性迭代器 |
| M5 | 字节码 + GIL 决定并发天花板 | 同一时刻只有一个线程执行 Python 字节码；IO 等待时让出锁，CPU 密集靠多进程绕开，海量 IO 靠 asyncio |

## 三、拷问题——概念口述通道（C1–C6）

**C1（M1/M2）**：依次说出下面三段的执行结果与原因：
```python
a = [1, 2]; b = a; b.append(3)          # 第1段：此时 a 是什么？
a = [[1, 2], [3, 4]]; b = a.copy(); b[0].append(99)   # 第2段：此时 a 是什么？
def tag(word, items=[]): items.append(word); return items
print(tag("x")); print(tag("y"))         # 第3段：两次打印分别是什么？
```
追问：同样的第 1 段语义换成 Swift 的 `var a = [1,2]; var b = a; b.append(3)`，结果有何不同？根本原因是什么？

**C2（M1）**：为什么第 3 段的默认列表会「记住」上一次调用？请从「函数定义何时执行、默认值存在哪里」讲到机制层，不许只说「这是个坑」。

**C3（M2）**：`is` 与 `==` 分别比较什么？为什么 `[[0]*3]*3` 建出来的「矩阵」改一个元素会整列跟着变？给出两种不踩坑的建法。

**C4（M3/M4）**：`for x in obj` 背后 Python 依次调用了哪些协议方法？「可迭代对象」与「迭代器」的区别是什么？为什么生成器表达式 `(x*x for x in range(10))` 不能被遍历两次？

**C5（M5）**：GIL 三层拷问——① GIL 锁的到底是什么（不许只说「锁线程」）？② 为什么多线程对 CPU 密集任务没有并行收益、对 IO 密集任务却有？③ multiprocessing 凭什么能绕开？

**C6（M3）**：装饰器三连——① 装饰器的本质是什么语法糖？② 带参数的装饰器 `@retry(times=3)` 相比无参的多了哪一层、为什么？③ 不加 `functools.wraps` 会丢失什么、为什么重要？

## 四、拷问题——代码任务通道（Q1–Q4）

代码要求：本机 `python3` 跑通，输出贴回作答稿；文件落 `代码/T1/`，文件头注释标对应题号与撞墙记录。挂靠项目见 [[02-项目驱动实践路线.md|项目路线]] Phase 1。

**Q1（挂项目 1.4，M1/M2）**：**引用语义翻车合集**。写一个脚本，主动复现三个翻车现场并各给出修复版（修复前后都要打印证据）：
① 可变默认参数累积；② 浅拷贝矩阵的整列联动；③ 函数内修改传入的 dict 影响调用方。最后用一个断言汇总「修复版全部隔离成功」。

**Q2（挂项目 1.1，M4）**：**生成器分页加载器**。实现 `paged_loader(source, page_size)`，用 `yield` 逐页产出（每页是 list）；要求：source 用一个生成器模拟百万级数据源（不许先物化成 list），并演示「同一个生成器第二次消费为空」的现象且用注释解释为什么。

**Q3（挂项目 1.3，M3）**：**带参重试装饰器**。实现 `retry(times, delay=0)`：被装饰函数抛指定异常时重试，超过次数再抛；用 `functools.wraps` 保留元信息；写一个「前两次失败第三次成功」的演示函数验证，并打印被装饰函数的 `__name__` 证明 wraps 生效。

**Q4（挂项目 1.5，M5）**：**并发边界实测**。同一个 CPU 密集函数（纯 Python 计算）与同一个 IO 密集函数（sleep 模拟），分别用单线程 / 多线程(threading) / 多进程(multiprocessing) 各跑一遍，打印三种方式的耗时。工作量控制到总时长 15 秒以内。预测先写在作答稿里，再对拍实测。
