# T9-01 教练出题：Tokenizer 与 Transformer 最小实现（模型面）（独立增量轮）

> 本轮补「LLM 模型面」：从 token 到 attention 到最小因果模型前向，最后落到 HuggingFace 生态实操。全部用 numpy 从零实现可跑；HuggingFace 实操允许离线/文档模拟，但必须如实记录「待真机验证」。
> 复习线条款：① 性质断言兜底；② 费曼稿必须含「从零实现 vs 直接用库」取舍表；③ 代码一律 `.venv/bin/python` 实跑。
> 使用纪律：卡住按弱→中→强逐级要提示（密卷在教练分支），直接要答案 → 反问「这一步的矩阵形状是什么」。

## 一、共识模型（教练版五个骨架）

| # | 模型 | 一句话骨架 |
|---|------|-----------|
| M1 | tokenizer 是文本 ↔ id 的桥 | BPE 合并高频子词；token 数 = API 成本与上下文窗口的度量单位 |
| M2 | Transformer = 注意力 + 前馈 + 残差 | 自注意力让每个位置看到全部位置；QKV 是三种线性投影 |
| M3 | 注意力是「按相关性加权求和」 | softmax 归一化权重；因果 mask 防未来泄漏，填充 mask 忽略 padding |
| M4 | 残差与层归一化是工程件 | 不是理论必需，是训练稳定与深层网络的实践必需 |
| M5 | 理解原理 + 会用生态 | 从零实现小模型建立心智，HuggingFace 负责规模与工程 |

## 三、拷问题——概念口述通道（C1–C6）

**C1（M1）**：BPE 训练的两步（统计相邻对 → 合并最高频）直觉是什么？为什么「low」被拆成 `lo` + `w` 是合理的？token 数对 API 成本的意义？

**C2（M3）**：自注意力的 QKV 各是什么投影？为什么用「点积」衡量相关性？softmax 的温度/缩放（sqrt(d_k)）是为什么？

**C3（M3）**：因果 mask 与填充 mask 分别防什么？在实现里它们加在哪里（softmax 前还是后）？为什么 mask 的位置很关键？

**C4（M4）**：残差连接解决什么问题（梯度消失/深层退化）？层归一化在哪个维度归一、为什么按特征维而不是样本维？

**C5（M1）**：怎么估算一段文本的 token 数（英文/中文差异）？上下文窗口满了怎么办（截断/摘要/分块）？为什么「token 预算」是 prompt 工程的第一约束？

**C6（M5）**：HuggingFace 生态的最小工作流（tokenizer + model + generate）是什么？从零实现的小模型与库里的模型在「可学到的东西」上有什么互补？

## 四、拷问题——代码任务通道（Q1–Q4）

**Q1（挂项目 9.1，M1）**：**BPE 最小实现**。小语料（几行英文）训练 BPE：统计相邻 token 对、按频率合并直到 vocab 大小达标；实现 encode/decode 往返。实跑证明：往返一致、高频子词被合并、vocab 与合并序列可打印。

**Q2（挂项目 9.2，M2/M3）**：**自注意力最小实现（numpy）**。实现单头 + 多头（2 头）：QKV 投影、缩放点积、softmax、加权求和；分别跑无 mask / 因果 mask / 填充 mask 三个版本，打印注意力矩阵，证明 mask 生效（被 mask 位置权重为 0）。

**Q3（挂项目 9.3，M2–M4）**：**单层因果 Transformer 前向（玩具）**。embedding + 位置编码 + 单层自注意力 + 前馈 + 残差 + 层归一化 + 输出投影，给定输入 id 序列预测下一个 token 的 logits。实跑证明形状正确、因果性成立（位置 i 的 logits 不受 i+1 影响，可验证）。

**Q4（挂项目 9.4，M5）**：**HuggingFace 实操**。用 `transformers`/`tokenizers` 加载一个小模型（如 `gpt2` 或 `distilbert`，网络不可用则用本地缓存；实在不行用文档模拟并如实标注「待验证」）：编码一段文本、跑一次前向/生成、记录「加载 → 编码 → 推理 → 解码」的 API 用法对照表（含参数含义）。全部命令与输出留档。
