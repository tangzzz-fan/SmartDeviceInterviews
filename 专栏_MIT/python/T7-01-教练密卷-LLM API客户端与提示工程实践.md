# T7-01 教练密卷：LLM API 客户端与提示工程实践（仅教练分支，学员禁阅）

> 本文件含弱/中/强三级提示、评分要点与参考答案。使用纪律：先弱提示；直接要答案 → 反问「这个错误该重试吗」。

## 一、概念题：提示梯与评分要点

### C1 SDK vs httpx 直连
- 弱提示：SDK 替你做了什么？直连替你保留了什么（控制权）？
- 中提示：什么时候 SDK 的「便利」变成「黑盒」——需要看原始响应头、自定义重试、打点、降级时？
- 强提示：判断标准：需要原始控制（头/重试/打点/多 provider 统一）→ httpx 直连 + 薄封装；纯标准场景 → SDK。企业网关通常是直连 + 自己的协议层。
- 评分要点：死记硬背典型：「官方 SDK 最稳。」（无控制权维度）真懂特征：给出切换信号与判断标准。
- 参考答案：SDK 省样板、随官方演进；直连保留控制权（响应头、Retry-After、多 provider 适配）。网关/降级/自定义重试场景直连。

### C2 错误类型与重试映射
- 弱提示：四类错误先分类：超时、429、5xx、上下文长度/校验。哪些是「暂时」哪些是「永远」？
- 中提示：重试的前提是「重试可能有不同结果」。上下文长度重试会有不同结果吗？
- 强提示：超时/429/5xx 可重试（暂时性）；上下文长度/认证失败/校验失败不可重试（确定性失败），要降级或改请求。
- 评分要点：真懂特征：每类给「能否重试 + 为什么」；死记硬背典型：「出错就重试。」
- 参考答案：超时（可，幂等）、429（可，尊重 Retry-After）、5xx（可，限次数）、上下文长度/校验（否，改请求或降级）。

### C3 退避、抖动与重试边界
- 弱提示：没有抖动的退避会发生什么（多客户端同步重试 = 惊群）？
- 中提示：429 的 Retry-After 是服务器给的精确值，本地退避是估算——谁优先？
- 强提示：抖动打破同步；Retry-After 优先于本地估算；边界 = 最大次数 + 最大总时长（预算），超预算转降级/告警。
- 评分要点：真懂特征：抖动原因、Retry-After 优先级、预算概念。
- 参考答案：指数退避 + 抖动防惊群；429 读 Retry-After；重试预算（次数 + 总时长）防「重试到死」。

### C4 限流与背压
- 弱提示：Semaphore 限的是「同时在飞的数量」；连接池限的是「底层连接数」。两个限的是同一件事吗？
- 中提示：上游配额（每分钟请求数）决定了你的吞吐上限；队列深度决定「来不及处理时怎么办」。
- 强提示：三层：上游配额（外部）、Semaphore（并发）、队列（缓冲 + 背压）。背压 = 队列满时新请求被拒/阻塞，而不是无限积压。
- 评分要点：真懂特征：三层各管什么、背压表现。
- 参考答案：Semaphore 管并发在飞数，连接池管连接复用，配额管上游吞吐；队列有界即背压，满了拒绝或阻塞。

### C5 消息结构与上下文管理
- 弱提示：system 是「行为设定」，user/assistant 是「对话事实」——职责混了会怎样？
- 中提示：长对话的 token 会涨——先算预算（max_tokens + 历史），超了怎么办？
- 强提示：system 固定且短；历史按「从新到旧」裁剪，重要事实可摘要压缩；预算 = 模型上限 - 输出预留。
- 评分要点：真懂特征：职责边界 + 预算公式 + 截断/压缩策略。
- 参考答案：system 管行为、user/assistant 管事实；预算 = 上限 - 输出预留；超预算用截断（新优先）或摘要压缩。

### C6 结构化输出
- 弱提示：让模型输出 JSON 有几种办法？「提示词约定」和「JSON mode」谁更可靠？
- 中提示：模型可能输出非法 JSON——谁负责兜底？
- 强提示：方法谱系：提示词约定（最弱）→ JSON mode（格式保证）→ 函数调用（schema 驱动）→ 校验 + 重试（业务兜底）。校验失败重试几乎必须，因为模型不保证业务合法性。
- 评分要点：真懂特征：方法谱系 + 可靠性边界 + 校验重试的必要性。
- 参考答案：提示词约定最弱；JSON mode 保证格式不保证 schema；函数调用是 schema 驱动；最终靠「校验 + 有限重试 + 放弃降级」。

## 二、争议焦点参考立场

- F1：默认直连 + 薄协议层（企业网关要控制权）；纯标准小场景用 SDK；站死一方 = 半过。
- F2：只重试可重试错误 + 预算；无条件重试 = 放大故障。
- F3：结构化输出是工程——schema + 校验 + 重试 + 降级四件套；「碰运气」= 未过。

## 三、代码题：评分要点与提示

### Q1 httpx 最小客户端
- 评分要点：mock 服务器真实存在；鉴权头/base_url/timeout 生效；错误分类函数把超时与 5xx 分开；实跑输出贴回。
- 参考答案要点：`httpx.AsyncClient(base_url=..., timeout=...)`；分类函数 `classify(exc/status) -> ErrorKind`。

### Q2 重试器
- 评分要点：指数退避 + 抖动实现；只重试 `should_retry` 允许的错误；429 读 Retry-After；实跑证明「前两次 429、第三次成功」。
- 参考答案要点：`backoff = min(cap, base * 2**attempt) * (1 + jitter)`；`Retry-After` 覆盖本地估算。

### Q3 并发网关 + 熔断
- 评分要点：Semaphore 限流生效；连续失败熔断（窗口/短路时长）实测生效；恢复期半开重试；降级路径可跑。
- 参考答案要点：熔断三态 closed/open/half-open；失败计数窗口；open 期间直接降级。

### Q4 结构化输出管道
- 评分要点：mock 可配置非法 JSON；解析 + schema 校验；失败重试次数固定；实跑证明非法被消费。
- 参考答案要点：`try: data = json.loads(...) except: retry`；校验必填字段；重试上限后放弃并告警。

## 四、使用纪律

- 判分只认证据：实跑输出、重试时序、熔断状态机都要留档；mock 服务器不得省略。
- 失真自查：没跑就说通了、重试无条件、熔断没有半开恢复 = 该题作废重跑。
