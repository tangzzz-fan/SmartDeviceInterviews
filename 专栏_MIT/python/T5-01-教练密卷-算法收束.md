## 一、概念题判分点与提示梯

### C1 LRU 机制
- **判分点**：① 哈希缺「顺序」能力——LRU 需要 O(1) 找到最旧者，哈希无序；② get 命中：定位节点→摘出→插头部；put 已存在：改值+挪头；put 新增：插头部，超容量摘尾+删哈希；③ OrderedDict 内部是哈希+双链（CPython 实现），move_to_end 是双链挪节点，popitem(last=False) 摘头/尾——就是 LRU 原语。刷题存量应全对，有卡壳 = 武器生疏信号。
- **弱提示**：淘汰时要「找到最旧的」，哈希表能 O(1) 做到吗？
- **中提示**：什么结构支持 O(1) 头插尾删？两者怎么接起来？
- **强提示**：哈希存 key→节点指针，双链存使用顺序，节点同时活在两个结构里。
- **复习线变式**（答太顺追加）：LFU 与 LRU 的数据结构差在哪？（频率维度→双哈希+分桶双链或堆。）

### C2 堆与 Top-K
- **判分点**：① 最小堆堆顶 = 当前 K 大的「门槛/最弱者」，新元素比门槛大才替换——堆里始终是 Top-K，堆顶最小正是我们要监视的那个；用最大堆则堆顶是最大值，无法判断新元素够不够格；② bisect.insort 查找 O(log n) 但**插入是 O(n)**（列表挪位），流式 n 个插入总 O(n²)——「二分只帮你找位置，搬数据还是线性的」是判分关键；③ 排序 O(n log n)、堆 O(n log k)、quickselect 平均 O(n)（最坏 O(n²)，随机化保底）。
- **弱提示**：最小堆的堆顶是这 K 个数里的谁？
- **中提示**：list 中间插一个元素，后面的元素要干什么？
- **强提示**：insort = bisect 定位 + list.insert，后者 O(n)。
- **复习线变式**：k 接近 n 时堆法还划算吗？（k≈n 时 O(n log k)≈排序，直接排序或「取 n−k 小」反转。）

### C3 打家劫舍链
- **判分点**：① dp[i] = 前 i 间能偷的最大金额；② dp[i] = max(dp[i−1], dp[i−2]+nums[i])；③ 滚动：prev2, prev1 两变量；④ 环形 = 首尾互斥，拆「偷 [0..n−2]」与「偷 [1..n−1]」两次线性版取 max。强项区预期全链顺，**答太顺按条款追加变式**（环形/树形打家劫舍说出状态差异即过）。
- **弱提示**：第 i 间的决策只依赖哪两个历史状态？
- **中提示**：环形唯一的冲突在哪两间房？
- **强提示**：枚举 0 号偷不偷，拆成两个线性问题。
- **复习线变式**：树形打家劫舍的状态要加什么维度？（节点+「偷/不偷」二元状态，后序遍历。）

### C4 `[[0]*n]*m` 三连
- **判分点**：① 外层 `*m` 复制的是**同一个行列表的引用** m 次——改 grid[0][0] 所有行一起变，id() 全同；② Swift 值语义：repeating 时按值拷贝（元素是 Array 值类型，CoW 各自持有），改一份不牵连；③ 正确写法：`[[0]*n for _ in range(m)]`（每次推导式重新求值）或 `[[0]*n] * m` 换成 `copy.deepcopy`/乘法改逐行建。推导式安全的原因：循环体每轮**重新执行** `*n` 表达式，产出 m 个独立对象。人设卡预期此题复发于 Q3 代码——概念层答对+代码层复发 = 如实，判定概念过、代码按条款记复发。
- **弱提示**：`*` 对列表做的是拷贝还是复制引用？
- **中提示**：print 一下 grid[0] is grid[1]。
- **强提示**：外层乘法只复制一个对象的引用 m 次；列表推导式每轮重新求值。
- **复习线变式**：`[{}]*3` 和 `[{0}]*3` 呢？（同病；字典/集合同理，乘法复制引用。）

### C5 C 层 vs 字节码层
- **判分点**：sorted() 是 C 实现的 Timsort，元素比较虽回调 Python 但**循环本体在 C 里跑**（每步几纳秒）；纯 Python 手写快排每步循环走字节码分发（每步几十~百纳秒，REPL 逐条解释）。同类例子：sum() vs for 累加、str.join vs 循环 +=、Counter vs 手写 dict 累计数、列表推导 vs append 循环（推导有专门字节码优化）。能讲「每步操作的固定开销差一到两个量级、总量 = 步数 × 每步开销」= 过；只说「内置快」= 半过。
- **弱提示**：手写快排的 while/for 每一步 Python 要做哪些事？
- **中提示**：sorted 的循环体在哪个语言里执行？
- **强提示**：复杂度数步数，常数看每步——字节码分发 vs C 直循环差 10~100 倍。
- **复习线变式**：为什么 `map(str, nums)` 常快于 `[str(x) for x in nums]`？又为什么有时反过来？（map 省了逐帧调用开销但取属性/复杂表达式时推导更优。）

### C6 滑动窗口最大值
- **判分点**：① deque 存下标、队首是当前窗口最大，入队时弹掉所有 ≤ 新元素者（它们永无出头之日）——每个元素最多进出队一次，摊销 O(1)，总 O(n)；② 堆解法：窗口滑走后堆顶可能已出窗，只能「懒删除」（堆顶下标 < 窗口左界就弹），总 O(n log k)，退化发生在重复大量出窗检查时；③ 判据：严格 O(n) 选单调队列；k 小或需要同时维护更多分位信息时堆更灵活——单调队列只能答「窗口最值」这一类问题。
- **弱提示**：窗口里一个较小元素，什么时候可能变成最大值？
- **中提示**：堆顶滑出窗口了你怎么知道？
- **强提示**：单调队列摊销 O(1)：每元素最多进一次出一次；堆懒删除多一层 log。
- **复习线变式**：单调队列还能答什么？（窗口最小、最近更大元素——「单调栈是它的静态版」。）

## 二、争议焦点判分点

- **F1 手写 vs OrderedDict**：面试手写（考数据结构功底、面试官明说可用标准库时再换）；生产直接 OrderedDict 或 functools.lru_cache（可读性/维护成本/已被千万人验证）。边界：面试里「用 OrderedDict 一行解」要先征得同意——立场两面 + 场景切分 = 过。
- **F2 排序 vs 堆**：k 相对 n 很小 → 堆（O(n log k) 的 log k 小）；k 与 n 同阶 → 排序（Timsort 的 C 层常数吊打 Python 层堆操作，且 sorted 有快路径）；n=1000 量级差异淹没在常数里，实测说了算。有「复杂度定增长、常数定起点、实测终裁」三层 = 过。
- **F3 何时换实现**：触发线三档——纯 Python 循环步数 > 1e7 且热点集中（先 profile 定位）→ 优先 C 层武器（numpy/内置）换写法而非换语言；向量化可行（数值数组运算）→ numpy 通常 10~100 倍；CPU 密集且不可向量化 → 多进程绕 GIL 或 C 扩展/其他语言。有「先 profile、换写法优先于换语言、GIL 边界」三层 = 过。

## 三、代码题判分点

- **Q1**：双实现对拍序列必须含淘汰顺序断言（不只是值一致）；10 万操作耗时比值应有数量级差（dict+list 的 O(n) 淘汰会显形）；ARC 对照注释要点：Python 引用计数下节点 prev/next 互指会成环——要么手动断链要么接受环由 GC 回收（与 Swift weak 破环对照）。
- **Q2**：结论必须落到曲线斜率——k=10 时堆法近线性、bisect 法在 n=1e6 显形 O(n²) 级陡升；排序法对 k 不敏感。三法对拍一致。bisect 法若被学员预测「二分所以快」然后被实测打脸 = 本轮最高质量墙。
- **Q3**：陷阱复现要有 `grid[0] is grid[1] == True` 级证据 + 修改牵连演示；LIS 用 bisect_left（严格递增）不是 bisect；DP 与暴力/滚动版对拍断言。第一版是否复发如实记录是判分点。
- **Q4**：三档耗时表齐全；三条纪律必须从数据长出（如「纯循环贵、C 内置便宜、numpy 向量化再降一阶」）；Swift 对照缺失时如实降级不编数据——**诚实条款重于数据完整**。
