# T7-01 教练出题：LLM API 客户端与提示工程实践（独立增量轮）

> 本轮是 T6 之后新增的独立轮：T6 用 mock 打通了并发/重试/流式/工程化骨架，本轮专攻「真实 LLM API 客户端与提示工程」——鉴权、错误分类、重试/熔断、并发限流、消息结构与结构化输出。
> 复习线条款：① 沿用全线纪律——性质断言兜底、耗时断言扫容量、perf_counter + 重复取 min；② 费曼稿必须含「httpx 直连 vs SDK」的取舍表；③ 代码一律 `.venv/bin/python` 实跑，mock 服务器用本地实现，不许假装调了真实 API。
> 使用纪律：卡住按弱→中→强逐级要提示（密卷在教练分支），直接要答案 → 拒答并反问「这个错误该重试吗」。

## 一、共识模型（教练版五个骨架）

| # | 模型 | 一句话骨架 |
|---|------|-----------|
| M1 | API 客户端是「协议翻译层」 | SDK/httpx 封装 HTTP + 鉴权 + 错误映射；企业落地要能脱离 SDK 用 httpx 直连（调试、自定义、降级） |
| M2 | 错误是类型化的 | 超时 / 限流 429 / 上下文长度 / 认证失败——各自决定不同的重试策略 |
| M3 | 重试要幂等、退避、只重试可重试错误 | 指数退避 + 抖动；429 尊重 Retry-After；5xx 可重试；上下文长度重试是浪费 |
| M4 | 并发与限流是网关职责 | asyncio.Semaphore 限流 + 连接复用 + 背压；同时保护上游与自身 |
| M5 | 提示词是数据不是咒语 | 消息结构（system/user/assistant）、结构化输出（JSON schema）、上下文与 token 预算管理 |

## 二、争议焦点（三题，考有边界的立场）

- **F1**：企业 LLM 调用该用官方 SDK 还是 httpx 直连？
- **F2**：重试该「无条件重试」还是「只重试特定错误」？
- **F3**：结构化输出是工程（schema + 校验 + 重试）还是玄学（碰运气）？

## 三、拷问题——概念口述通道（C1–C6）

**C1（M1）**：SDK 与 httpx 直连各解决什么、各自代价是什么？什么信号出现时你应该从 SDK 切到 httpx 直连？给出判断标准。

**C2（M2）**：把 LLM API 的典型错误分成至少四类（超时、429、5xx、上下文长度/校验失败），每类说清：能否重试、重试是否幂等、重试了有没有意义。

**C3（M3）**：指数退避为什么必须加抖动？429 响应里的 `Retry-After` 与本地退避算法怎么配合？「重试到死」与「一次不重试」之间怎么定边界（最大重试次数/总时长）？

**C4（M4）**：并发网关里 Semaphore 限流与「连接池复用」是什么关系？限流阈值该由谁决定（上游配额 / 自身预算 / 队列深度）？背压表现在哪？

**C5（M5）**：消息结构（system/user/assistant）里 system 和 user 的职责边界是什么？长对话的上下文管理（token 预算、截断策略、摘要压缩）怎么做？

**C6（M5）**：让模型稳定输出 JSON 有哪几种方式（提示词约定 / JSON mode / 函数调用 / schema 校验重试）？各自的可靠性边界是什么？为什么「校验失败自动重试」几乎是必须的？

## 四、拷问题——代码任务通道（Q1–Q4）

**Q1（挂项目 7.1，M1/M2）**：**httpx 异步最小客户端 + mock 服务器**。本地起一个 mock LLM 服务器（`http.server`/`aiohttp` 均可，返回固定 JSON 或流式 chunk），用 `httpx.AsyncClient` 实现：base_url 配置、Bearer 鉴权头、timeout 设置、错误分类函数（把异常/状态码映射成类型）。实跑证明：成功路径返回解析结果、超时路径走超时分类。

**Q2（挂项目 7.2，M2/M3）**：**重试器**。实现 `retry_async(coro_factory, *, max_attempts, base_delay, jitter, should_retry)`：指数退避 + 抖动；只重试 `should_retry` 允许的错误；429 时读取 `Retry-After`。mock 服务器按「前两次 429、第三次成功」脚本运行，实跑证明重试序列与耗时符合预期。

**Q3（挂项目 7.3，M4）**：**并发网关 + 熔断**。在 T6 Q2 的并发调用器上加：Semaphore 限流、连续失败熔断（窗口内失败 N 次后短路 N 秒）、熔断期间走降级（返回缓存/默认值）。实跑证明：正常并发跑通、注入连续失败后熔断生效、恢复期后自动半开重试。

**Q4（挂项目 7.4，M5）**：**结构化输出管道**。请求模型输出 JSON（mock 服务器可配置「偶发非法 JSON」），实现：请求 → 解析 → schema 校验（必填字段）→ 失败重试（固定次数）→ 返回结构化结果或放弃。实跑证明：非法输出被重试消费、校验规则可配置。
