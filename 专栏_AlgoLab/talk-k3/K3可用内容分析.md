---

## 总判

K3 这批材料**比现有备战包更「面试可演练」**：题集有答题骨架、两张图可默画、算法工程化有可动手的 5 天计划。  
与现有包关系是 **互补而非重复**——现有包偏知识广度和落地纠偏；K3 偏「怎么讲、怎么练、怎么画」。

**优先级：算法工程化练习（填你 Core ML/算法实现缺口）> 两张默画架构图 > 三级题集刷题 > 方法论框架。**

## 一、立刻高价值可用（建议本周主用）

### 1. 算法工程化最小流水线（TalkWithK3 + lab 说明书）

| 可用点 | 为何对你特别关键 | 怎么用 |
| :--- | :--- | :--- |
| `algo-engineering-lab` repo 结构 | 精确命中 JD「算法实现 / 读 Python / 调 C++ / CoreML」 | 按说明书先写规范再写代码；面试说「验证性原型」勿说生产 |
| 案例 1 HRV 时域 float64→32 | 补「没做过健康算法」话术 | 练完产出数字 + 面试卡片 |
| 案例 2 FIR + vDSP + 系数精度陷阱 | 直接对应 Swift↔C 加分项 | 「系数有效位不够阻带掉 20dB」是强钩子 |
| 案例 3 频域 HRV + **中间快照法** | 与 BLE 分层归因同构，叙事极强 | 必练；对齐口径文档可当作品 |
| 案例 4 CoreML FP16 top-1 一致率 | 补强你刚加强的模块 03 | 与现有黄金集/契约叙述合并 |
| 案例 5 流式滑窗 + FIR overlap | 把 BLE 主场缝进算法故事 | 与现有 RingBuffer/背压合并讲 |
| 5 天时间盒 | 可执行 | Day1–5 按表验收 |
| lab 文档 DoD（规范先行） | 被问「怎么工程化」可直接甩规范文件 | 先写 01/03/05 规范再实现 |

**与现有模块 03 关系：** 03 讲「该怎么做」；K3 给「练什么、几天练完、口述卡片怎么写」。**两套一起用，不要二选一。**

### 2. 两张默画架构图（核心架构图 + PNG）

| 可用点 | 相对现有包的增量 | 怎么用 |
| :--- | :--- | :--- |
| OTA：Paused 独立态、双端 offset **取小**、Aborted≠Failed、分片校验重传、BootloaderRecovery | 现有 02 有 FSM，但「取小 / Aborted 分流 / 失败边优先讲」更锋利 | 替换/增强默画版本；面试先画失败边 |
| 流式管道：**显示可丢 / 存储零丢 / 算法滑窗** 三链路 + FW 循环缓存回填 + 对账二次回填 | 现有 01/08 有 RingBuffer/LTTB，缺「缺口回填 + QoS 分流」完整图 | **强烈建议并入面试主图**；与眼镜 Jitter Buffer 同构叙事可用 |
| 设计决策清单 + 话术锚点 | 现有包偏知识点 | 直接当白板讲稿 |

### 3. 三级面试题集

| 层级 | 建议用法 |
| :--- | :--- |
| 基础 Q1.1–1.8 | 90 秒口述过关；与现有 01/02 对照，缺的补数字 |
| 进阶 Q2.1–2.8 | **主战场**；每题必须换成你自己的项目数字 |
| 专家 Q3.1–3.6 | 重点练 **Q3.1 神经调节安全**、**Q3.3 算法一致性**、**Q3.6 岗位最难点=三方治理** |
| 自检清单 | 面试前一天打勾 |

注意：骨架里的项目映射（CarKey/扫地机/眼镜）要换成**你真实履历**，不要照念 K3 假设。

### 4. 三个答题框架（TalkWithK3 第四节）

- **分层归因**：物理→链路→GATT→协议→会话→应用（定责 App/BLE/FW）
- **状态机优先**：先状态、再迁移、再失败边（OTA/重连/刺激会话）
- **度量驱动**：优化前→瓶颈→手段→优化后→防退化

这三个框架应写进 STAR 开场习惯；现有 06/07 有定责，但不如 K3 凝练成可复用模板。

## 四、慎用 / 需改写后再用

| 内容 | 原因 |
| :--- | :--- |
| 「contractor / 现金流 / 五险」等个人处境推断 | 可内化成反问「合同主体与付款周期」，不要写进对外材料 |
