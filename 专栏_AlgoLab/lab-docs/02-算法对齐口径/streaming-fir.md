# 对齐口径：流式 FIR + RingBuffer（BLE 分片）

版本：0.1.0 · 日期：2026-07-28 · 作者：lab · 状态：生效

> Case5。把 Case2 的 FIR 改成流式：模拟 BLE 分片到达 → RingBuffer → 滑窗触发。  
> **跨窗口必须保留 FIR 延迟线**，否则边界出现「每秒一跳变」。

---

## 1. 环节分解表

| 环节 | 参数 | 取值 | Python | Swift / C |
| :--- | :--- | :--- | :--- | :--- |
| 采样率 | fs | **25 Hz**（与 Case2 PPG 一致） | 合成 | 同左 |
| 分包 | — | 每包 **2~3** 个采样；带 `seq` | 生成器 | `BLEPacket` |
| 缓冲 | — | RingBuffer 容量 ≥ **2 秒**（50 点） | — | `SampleRingBuffer` |
| 触发窗 | — | 凑满 **25** 点（1 秒）触发一次滤波 | — | `StreamingFIR` |
| FIR | 系数 | 与 Case2 同源 `ALGO_FIR_BANDPASS_COEFFS` | — | C 延迟线 |
| 状态 | — | 延迟线长度 = **M**（抽头数）；跨窗连续，**禁止**每窗重置 | — | `algo_fir_stream_*` |
| 因果定义 | — | \(y[n]=\sum_{k=0}^{M-1} b[k]\,x[n-k]\)，\(x<0\) 视为 0 | 同公式 | 同左 |
| 丢包 | 比率 | 注入约 **5%** 丢包（按包） | 生成器 | 同策略回放 |
| 缺口策略 | — | 默认 **`zero_fill`**：缺失采样填 0 并推进时间；可选 `skip`（不填，时间轴收缩，仅演示） | — | `GapPolicy` |

> 与 Case2 `mode='same'`（非因果居中）**不同**：流式产品路径用**因果** FIR，避免未来样本。Case2 仍保留 same 对齐 scipy；本 case 对齐「连续因果流」。

## 2. 中间快照 / 验收

| 检查 | 方法 | 阈值 |
| :--- | :--- | :--- |
| 无状态断裂 | 整段一次性因果滤波 vs 按 1s 窗流式（状态连续） | abs ≤ 1e-12 |
| 有状态断裂（负例） | 每窗重置延迟线 | 边界处误差 ≫ 1e-6（用于演示 bug） |
| 丢包 zero_fill | 与「预先插 0 再整段滤波」一致 | abs ≤ 1e-12 |

## 4. 面试金句

> 流式 DSP 的坑在窗口边界——滤波器状态必须跨窗口连续。这和 BLE 收包同构：数据分片到达，算法假设流连续，中间这层状态管理就是 iOS 工程师的价值。
