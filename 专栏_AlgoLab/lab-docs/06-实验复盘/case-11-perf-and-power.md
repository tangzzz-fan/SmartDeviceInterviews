# Case11 实验复盘：端上性能与能耗画像

版本：0.1.0 · 日期：2026-07-28 · 作者：lab · 状态：草稿

## 1. 假设
- 性能结论若缺统一入口，会出现“各 case 数字不可比”。
- 在验证性原型阶段，先建立统一基准框架比追求绝对最优更重要。

## 2. 做法
- 新增 `UnifiedPerfPowerBenchmarkTests`，同一测试输出 FIR / CoreML / Sleep 后处理三类路径。
- 保持“精度与性能分离”：Benchmark 不进 CI gate，Parity 仍是 CI 必过。
- 记录能耗补充模板（电源模式、电量区间、热状态、监控工具）。

## 3. 数字
- 本机 Debug 快照（Apple M2）：
  - FIR naive p50/p95: 0.0340 / 0.0380 ms
  - FIR vDSP p50/p95: 1.4430 / 1.5470 ms
  - CoreML FP32 infer p50/p95: 42.5091 / 46.9099 ms
  - Sleep postprocess p50/p95: 0.1850 / 0.2040 ms
- 已追加 `docs/bench-log.md`。

## 4. 坑
- CoreML 测试路径若每次 compile model，会引入额外开销；数字需标注测试语义。
- Debug 构建不适合作为对外承诺数字，仅用于回归趋势观察。

## 5. 结论
- 性能治理先统一度量语义，再讨论优化，否则数字没有可比性。

## 6. 面试卡片（≤5）
- 我把多条热路径放进同一 benchmark 入口，保证口径统一。
- 性能与精度测试分离，避免“为了提速改行为”混入 CI。
- 数字必须绑定环境与能耗状态，才具备沟通价值。
