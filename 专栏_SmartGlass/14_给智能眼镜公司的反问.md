# 14 给智能眼镜公司的反问

对方是做眼镜的公司，不是普通 App 厂。反问要证明：你交过眼镜配套、知道难在交界处，并且在挑能干活的团队——不是在背「有什么问题想问我们」。

**上场只带 2 条必问 + 1 条按面试官气质选。** 多了像问卷。先用自己做过的切法垫一句，再问他们怎么做。

---

## 一、怎么问（固定句式）

> 我在商汤眼镜配套 App 里是「BLE 控制面 + WiFi 数据面、会话状态机在 App、ASR/TTS 走云 SDK」。想对一下你们这边……

不要一上来问「你们用哪个 ASR」。对方没说之前，问分工和坑，比问品牌名更像做过的人。

---

## 二、必问（从这里定 2 条，明早默一遍）

### Q1 · 语音链路现在怎么切

**问：** 现在语音是云端流式为主，还是已经有端侧唤醒 / 离线降级？眼镜、手机 App、固件、云，各自的边界在哪？一次对话里谁拥有状态机？

**为什么问：** 这是眼镜公司的生死题。答得清，说明团队知道自己在做产品而不是「接个大模型」。你也能判断入职后是补编排、补固件联调，还是被扔去改 UI。

**听什么：**
- 好：控制/数据面切开；状态机有主人；弱网有降级；承认端侧唤醒和云端识别不是同一层。
- 差：一句「都在云上」或「都在眼镜上」，说不清打断、停播、断连谁负责。

### Q2 · App 和固件怎么联调

**问：** 日常联调眼镜是真机为主，还是 App 侧有 Mock？EVT 阶段协议变了，是固件先冻接口，还是 App 跟着每晚的固件包改？

**为什么问：** 你 0 到 1 过，知道没 Mock 的 EVT 会把客户端拖死。问这个等于在问「我能不能把货交出去」。

**听什么：**
- 好：有设备影子 / Mock；协议有版本；发完 OTA ≠ 成功，要设备校验。
- 差：只有真机、没有接口冻结、客户端当试验田。

### Q3 · 双端还是单端，契约在哪

**问：** Android / iOS / Flutter 的边界怎么划？设备能力是统一插件契约，还是两端各写一套？新功能是先冻 Dart/原生 API，再两边实现吗？

**为什么问：** 岗位兼备 Android，你的真实牌是「契约 + 翻译交付」。问清楚才知道能不能把阿兹尔那套直接用上。

**听什么：**
- 好：有 platform interface；BLE/音频在原生，会话 UI 在 Flutter 或原生，但状态不跟 Widget 走。
- 差：页面里直接 new BluetoothGatt；iOS 和 Android 行为对不齐没人收口。

## 三、按面试官气质加 1 条

### 对方偏硬件 / 固件 / 系统

**Q4 · 控制面和数据面**  
眼镜到手机，控制信令和大流量音频是一条通道还是两条？打断、停播能不能在数据面堵车时仍然到达？

（你自己的锚点：BLE 控制 + WiFi PCM。他们若走 BLE 音频或 A2DP，听完再对，不要当场推销口径 A。）

**Q5 · 功耗谁拍板**  
整机电流曲线是固件实验室出，还是 App 也要背场景功耗？扫描、WiFi 拉起、音频通路空转，这三件有没有明确的「谁允许打开」。

**Q6 · OTA**  
升级会话谁编排？App 管到哪一步——下载、分片、设备校验、激活确认？防砖和双槽在哪一侧？发完包算不算成功？

### 对方偏客户端 / Flutter / Android

**Q7 · 音频在 Android 上怎么保活**  
丢 AudioFocus、来电话、厂商 ROM 杀后台时，TTS 和采音怎么切状态机？有没有前台服务类型约束？

**Q8 · GATT 和 Channel**  
BLE 操作有没有全局串行队列？Notify 是原生聚合再进 Flutter，还是逐包过 MethodChannel？

**Q9 · 会话页 rebuild**  
ASR partial 刷新时，整页会不会跟着 layout？字幕和历史列表有没有拆树？

### 对方偏产品 / 负责人 / 交叉面

**Q10 · 现在最疼的工程问题**  
当前量产或下一版，最拖交付的是连接稳定性、首包延迟、功耗，还是 OTA/产测？如果我入职，90 天最希望我先啃哪一块？

**Q11 · 量产阶段**  
现在是 EVT、DVT 还是已经 PVT？App 在产测通道里要不要隔离正式云、做版本矩阵？

**Q12 · 团队怎么定责**  
现场出「连不上 / 没声音 / 很慢」时，是按日志三段定界（端侧 / 网络 / 云 / 固件），还是按模块甩锅？有没有 sessionId 贯穿眼镜、App、云？

## 四、上场组合（明天照着选，不要全问）

| 面试官 | 带这 3 条 |
|--------|-----------|
| 偏硬件 | Q1 语音怎么切 · Q4 控制/数据面 · Q5 或 Q6 功耗/OTA |
| 偏客户端 | Q3 双端契约 · Q7 或 Q8 焦点/GATT · Q1 状态机在谁那 |
| 负责人 / 交叉 | Q1 边界 · Q10 最疼的问题 · Q2 联调/Mock |
| 说不清气质 | **Q1 + Q10**，第三问用 Q3 |

收尾可以接 Q10 的后半句：「如果我加入，希望先在哪段链路上形成产出。」这比问培训、加班、有没有导师像要干活的人。

---

## 五、不要问（除非对方先打开）

- 加班、调休、培训、导师带不带
- 「你们用哪个 ASR / 哪家大模型」（显摆；对方先说再用自己的火山/日日新经历去对）
- 「我主要是 iOS，你们 Android 多吗」——短板自己在回答里处理，反问里不要示弱
- 薪资结构放到 HR 轮；技术轮最多问「这轮之后还有业务/交叉吗」

---

## 六、3 秒备用（卡壳就念）

**语音：** 我想确认一次对话的状态机在眼镜、App 还是云。我这边是 App 编排、云做 ASR/TTS、眼镜做人机。

**联调：** EVT 时协议会不会每周变。我这边没有 Mock 就会被真机拖死，想知道你们怎么冻接口。

**契约：** 设备能力有没有统一到插件层。我做过 iOS 插件翻译 Android，关心的是 API 先冻还是两端各写。

**最疼：** 如果入职，90 天希望我先啃连接、延迟、功耗还是 OTA。
