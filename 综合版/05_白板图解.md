# 白板图解（8 张，必须不看稿画出来）

> 用法：系统设计轮和技术深挖轮，主动说「我画一下」。白板 1–4 是 P0 必画；白板 5–8 是加分项深挖时的弹药。
> 自测标准：D7 前，随便抽一张能在 2 分钟内边画边讲完。

## 白板 1：BLE 连接 / 恢复状态机（P0，画 10 遍）

```
Idle
  -> Scanning（按 UUID / manufacturer data / 已绑定 ID 过滤）
  -> Connecting
  -> Discovering（service / characteristic）
  -> Ready（notify + 握手 + 首包校验）
  -> Streaming / Commanding
  -> Disconnected

Disconnected 分类：
  用户主动 -> Idle，不自动重连
  蓝牙关闭 / 权限 -> WaitSystem，提示用户
  链路异常 -> Reconnecting（有限次数 + 指数退避）
  恢复成功 -> 不一定直接 Streaming，先 Reconciliation
```

**要点**：Ready 不等于可信。重连后必须重新发现或确认订阅，再拉关键状态，再决定是否补发命令。对应题：[03_题库与答案/02-ble与corebluetooth.md](./03_题库与答案/02-ble与corebluetooth.md) B2/B7、[03_题库与答案/05-场景设计题.md](./03_题库与答案/05-场景设计题.md) E3。

## 白板 2：OTA 链路（P0）

```
Check(型号 / 电量 / 版本 / 是否充电)
  -> Download + Verify(hash / 签名)
  -> EnterOTA
  -> Transfer(分片 + seq + ack + 窗口)
  -> Validate on device
  -> Reboot
  -> Reconnect + Version confirm + Smoke
  -> Success

失败路径：
  下载失败 -> 不进升级模式
  校验失败 -> 丢包，保留旧固件
  传输中断 -> 断点或从头，设备保持可连
  重启后连不上 -> 超时窗口 + 恢复模式（和固件约定）
  版本不匹配 -> 拒绝启动新功能，上报
```

**要点**：OTA 是高风险链路。没有失败路径和可观测性，等于没有设计。讲的时候必须提 commit 点：未提交新镜像前保持旧镜像可启动。对应题：B9、[04_加分项_硬件专题.md](./04_加分项_硬件专题.md) 专题二。

## 白板 3：联调分层归因（P0）

```
现象：点击后设备无响应

L1 App UI / ViewModel     命令有没有发出？参数对不对？
L2 连接与队列             当前是 Ready 吗？命令有没有入队？
L3 BLE 传输               write 成功？notify 回来了吗？
L4 协议                   seq / opcode / crc / 版本对吗？
L5 固件                   收到了吗？执行了吗？状态机在哪？
L6 云 / 账号（如有）      是否还依赖服务端授权？

每个 L 必须有：日志点、时间戳、版本号。
```

**要点**：先建共同证据，再谈责任。对应题：[03_题库与答案/03-联调协议与量产.md](./03_题库与答案/03-联调协议与量产.md) C2。

## 白板 4：前后台状态重建（P0）

```
WillEnterForeground
  1. 不信任内存里的 connectionState
  2. 读 CBManager.state
  3. 对已绑定外设 retrieve / connect
  4. 确认 service 与 notify
  5. Snapshot：设备模式、电量、固件版本、待同步队列
  6. Reconcile：本地预期 vs 设备实际
  7. 再恢复 UI 与待发命令
```

**要点**：后台恢复是一次小型重连，不是「把页面重新显示出来」。对应题：[03_题库与答案/01-ios核心.md](./03_题库与答案/01-ios核心.md) A7。

## 白板 5：功耗预算（加分项）

```
电池寿命 ≈ 容量 / (射频 + MCU + 传感器 + 漏电)

射频通常是大头：
  广播 interval
  连接 interval / slave latency
  notify / write 频率
  扫描窗口（主要在手机侧）

App 能直接搞砸的：
  不停 scan
  Ready 后高频无响应写
  后台无预算重连
  日志 / 定位 / 音频会话常开

SLA 先和产品冻：
  目标续航
  状态新鲜度（例如 2s / 30s / 仅打开 App 时）
  是否允许后台实时
```

**要点**：先定 SLA，再选连接参数，再决定 App 行为。不要先「实时同步所有传感器」。对应：[04_加分项_硬件专题.md](./04_加分项_硬件专题.md) 专题一。

## 白板 6：离线同步管线（加分项）

```
Device flash ring buffer
  -> BLE pull / push（seq + window + ack）
  -> Phone pending store（requestId 持久化）
  -> Cloud（可选）
  -> 冲突：device truth / field merge / 版本号

时钟：
  设备常见是单调 tick，不是墙钟
  手机侧转墙钟时记录 offset，断连后 offset 失效要重标定

失败：
  只重传缺失 seq
  成功必须幂等
  旧包不得覆盖新版本状态
```

对应题：[03_题库与答案/05-场景设计题.md](./03_题库与答案/05-场景设计题.md) E2。

## 白板 7：传感器 / 音频数据面（加分项）

```
采样 -> 设备缓冲 -> 分包（seq/ts/codec）-> BLE/经典蓝牙
     -> App 重组 -> 会话/文件 -> 本地处理或上行

两条通道不要混：
  控制面：短命令 + 可靠 ack
  数据面：吞吐优先 + 校验 + 可丢或可补

AI 可穿戴常见坑：
  时钟域不同导致对齐失败
  MTU 小导致音频/IMU 打满通知
  后台录音 / 音频中断把会话打掉
  隐私：麦克风、健康明细默认不进日志和模型
```

对应：[04_加分项_硬件专题.md](./04_加分项_硬件专题.md) 专题四、五。

## 白板 8：EVT 到量产，客户端在冻什么（加分项）

```
EVT  接口还在变     App：多 firmware profile，日志拉满，功能克制
DVT  协议应冻结     App：恢复 / 功耗 / 回归集，开始谈 SLA
PVT  接近出货形态   App：兼容矩阵、灰度、工厂固件差异
试产 缺陷回流       App：按 SN / 固件版本切片，能停能回
量产 规模与版本斜   App：分阶段放量、kill switch、防砖 OTA
```

**要点**：每一阶段问自己：现在该冻接口，还是还在探路？冻错了会拖硬件；冻晚了会让试产不可回归。对应：[04_加分项_硬件专题.md](./04_加分项_硬件专题.md) 专题七。
