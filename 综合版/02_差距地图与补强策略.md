## 二、各模块补强路径与翻车点

### A. iOS 核心（P0）

**必掌握**：
- Swift 并发：必须能现场画出「async/await 线性化回调、actor 保护共享状态」的例子（用 BLE 管理器举例最加分）。
- 内存：用 Xcode Memory Graph 实操一次定位循环引用；讲清 delegate/block/Timer 三类经典场景。
- 网络：画一版分层网络层（路由/请求/响应/错误/重试/缓存/离线队列）。
- 存储：对比 Core Data vs SwiftData vs GRDB，给出可穿戴时序数据场景的选型理由。

**深挖路径**：写一个 20 行左右的 demo（如 actor 保护一个连接状态机）跑通；每讲一个机制配一个真实踩坑。

**翻车点**：只背名词不会举例；混淆 `Task.detached` 与 `Task`；说不清主线程隔离；内存只提 Leaks 不提 Memory Graph。

### B. BLE 全链路（P0）

**必掌握**：
- 画出完整流程：扫描（过滤+RSSI）→ 连接 → 服务发现 → 订阅/收发 → 断连 → 退避重连 → 恢复现场。
- 参数三件套：connection interval / slave latency / supervision timeout，能讲清调参 tradeoff。
- 吞吐公式：每包有效载荷 = MTU - 3，分块 + ack 流控；能给出实测量级（notify 数百 KB/s 级别）。
- OTA：画时序图（下载校验 → 分块传输 → 每包校验 → 完成校验 → 切换 → 失败回滚），必须提双 bank、电量约束与 commit 点。
- 五个异常场景单独准备：扫描不到、已发现连不上、服务发现失败、写成功但状态没更新、后台恢复后状态不一致。

**深挖路径**：用 nRF Connect 连真实设备/模拟器，实操扫描、读特征、开 notify；把白板 1 画 10 遍直到不看稿。

**翻车点**：说不清 MTU 默认 23；把「通知」和「回调」混为一谈；把 `didConnect` 当 Ready；OTA 只讲流程不讲中断恢复；重连策略没有退避与前后台差异。

### C. 软硬件联调（P1）

**必掌握**：
- 协议设计最小集：magic + version + opcode + length + payload + crc；seq/ack/超时重传；大小端与字段对齐。
- 排障四步：nRF Connect 直测固件 → 桩设备验证 App → BLE sniffer 抓 ATT → 双方日志时间线对齐。
- EVT/DVT/PVT：各阶段定义与软件重点。

**翻车点**：把问题全推给固件；不会用 sniffer；对字节序/长度字段等低级错误没有意识。

### D. 性能与基建（P1）

**必掌握**：
- 启动：pre-main 到首帧的链路；优化手段按「收益/风险」排序；指标埋点。
- 稳定性：收集（Crashlytics/Sentry + dSYM）→ 分析（聚类/符号化）→ 灰度 → 预防（测试+监控+开关）。
- CI/CD：fastlane 一条龙；灰度发布与回滚。
- 功耗：定位/网络/BLE 三块；Energy Log 与真机实测。

**翻车点**：只有结论没有数字；把 Crashlytics 当全部稳定性方案；CI 只提 Jenkins 不提测试策略。

### E. 行为与 AI-native（P0）

**必掌握**：准备 6+ 个 STAR 故事（见 06），每个都有量化结果；AI-native 至少 3 个案例 + 1 个「AI 出错被我拦下」的反例。

**翻车点**：故事没有结果数字；AI 案例只是「我用过 ChatGPT」而没有具体产出。

### F. 英文（P1）

**必掌握**：60-90 秒自我介绍背熟；一个技术故事用英文讲 5 分钟；daily sync 与风险同步模板。

**翻车点**：中文思维直译；术语不统一（notify/characteristic 前后不一致）；反问环节没准备问题。

## 三、冲刺优先级矩阵

- **必须补到可面试**：BLE 全流程、联调归因、iOS 深水区、工程基建、一个旗舰故事。

## 四、诚实缺口话术

> 原则：先承认边界，再给可迁移证据，再给入职后 30 天怎么补。不编造项目。

### 1. 没做过完整设备 OTA

「我没有从 0 独立交付过完整量产 OTA。我做过的是固件包校验、分片传输和失败重试这一段，以及升级后重新握手、对版本。入职后我会先把失败路径和可观测性做成清单，和固件一起把中断、回滚、防砖策略冻住。」

### 2. 没参加过 EVT / DVT / PVT

「我没有以客户端 owner 身份完整走过 EVT 到量产。我参与过试产缺陷回流：协议字段不兼容、广播名变更、连接参数在不同固件下行为不一致。这些让我理解硬件阶段的核心是冻结接口和可回归的验证集，而不是继续堆功能。」

### 3. 没有音频 / 健康传感器主经验

「音频采集和健康数据不是我的主战场。可迁移的是：传感器数据的分包、时钟对齐、丢失重传，以及后台保活和功耗之间的取舍。如果这个产品音频链路是核心，我会先补编解码边界和系统音频会话冲突。」

### 4. 没有消费电子量产交付

「我没有带过百万级出货。接近的经验是小批量真机联调和灰度发布：按固件版本分流、看连接成功率和崩溃率、有问题能停。Founding 阶段我优先保证可观测和可回滚，而不是先谈规模。」

### 5. C/C++ / 嵌入式不深

「我不是固件工程师。我能读协议文档、看 hex、和固件对齐字节序与 ack 语义，必要时读他们关键状态机代码。边界我会说清楚：App 侧保证传输、重试、兼容；固件侧保证设备状态和硬件时序。」
