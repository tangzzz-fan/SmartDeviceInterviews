# 模拟面试脚本

> 用法：找一位同事或 AI 扮演面试官，全程录音；严格按时间盒推进，不跳题、不提示。一次只答一题，空话被追问到机制、案例、指标为止。
> 评分每题 1–5 分，模拟后对照录音逐题打分，低于 3 分的题回到对应题库重练。**通过标准：两轮平均分 ≥ 4，且无单题 ≤ 2。**

## 双 Agent 对练协议

1. 对面试官 Agent 说：按 Round N 开始，一次一问。
2. 你自己答，或让资深候选人 Agent 按人设答（参考 `.qoder/agents/senior-candidate.md`）。
3. 面试官只给评价 + 一个杀伤力追问。
4. 候选人用追问再答一版。
5. 你随时打断，把人设案例换成真实项目。

不要让两个 Agent 在同一条消息里互喷完整长文，保持一次一问。

## 单题答题检查表（答完自己打勾）

- [ ] 第一句是结论
- [ ] 有机制，不只有形容词
- [ ] 有案例或明确缺口话术（指向 [02_差距地图与补强策略.md](./02_差距地图与补强策略.md)）
- [ ] 有取舍
- [ ] 有指标，或说明为什么现在没有指标
- [ ] 能承受一个追问

## 第一轮：技术深挖（60 分钟）

### 开场（3 分钟）

先简单介绍自己，重点讲和岗位最匹配的经历。

- **考察**：90 秒电梯陈述，是否主动埋入 BLE / 架构 / 0→1 三个证据点。
- **评分**：□ 90 秒内完成 □ 覆盖 3 个匹配点 □ 自然引出后续话题

### 模块 A：系统设计 —— BLE OTA 主线（25 分钟）

**主问题**：可穿戴设备需要支持固件 OTA 升级，请设计完整方案，从 App 侧讲到和固件的交互。

**追问链**（按顺序深挖，每答一层追一层）：

1. 固件包怎么传？分包大小怎么定？→ 追 MTU 协商、吞吐量估算
2. 传输中断了怎么办？→ 追断点续传的状态记录与恢复
3. 怎么保证不刷成砖？→ 追 A/B 分区、bootloader 回滚、校验机制
4. 用户量上来后怎么发布？→ 追灰度策略、失败率监控、回滚预案
5. App 版本和固件版本错位怎么办？→ 追版本协商与最低版本约束

**评分维度**：□ 五要素完整（传输/校验/恢复/回滚/发布） □ 细节到实现级（MTU、连接参数、校验算法） □ 主动提出失败场景而非被追才说 □ 先框架后细节

参考答案：[03_题库与答案/02-ble与corebluetooth.md](./03_题库与答案/02-ble与corebluetooth.md) B9 + [03_题库与答案/05-场景设计题.md](./03_题库与答案/05-场景设计题.md) + [04_加分项_硬件专题.md](./04_加分项_硬件专题.md) 专题二。

### 模块 B：Swift 并发快问快答（10 分钟，每题限时 2 分钟）

1. actor 和 class 的本质区别？actor 重入会带来什么问题？
2. `@MainActor` 标注在类型上和标注在方法上有什么区别？
3. 一段 BLE 回调代码要从 delegate 模型迁到 async/await，怎么做？
4. Task 取消在 structured concurrency 里怎么传播？BLE 长任务怎么响应取消？

**评分**：□ 概念准确 □ 能落到 BLE 实际场景 □ 卡壳时展示思路

### 模块 C：性能与后台（12 分钟）

**主问题**：用户反馈 App 很耗电，还总被系统杀掉导致数据没同步上来，怎么系统性解决？

**追问链**：① 先怎么定位耗电来源？用什么工具？② 后台同步被杀，iOS 给你哪些合法手段？各自限制？③ 手段都不够、产品又必须保证数据不丢，架构层面怎么解？（考察「设备端缓存 + 前台快速回补」思维）

**评分**：□ 先度量后优化 □ 对系统限制的准确认知 □ 架构层兜底思维

### 模块 D：项目深挖（10 分钟）

挑你做过的最复杂的一个模块（用旗舰故事 S1），讲技术挑战和决策。

**追问链**：① 当时有哪些备选方案？为什么没选其他的？② 上线后出过什么问题？③ 重来一次哪里会不同？

**评分**：□ 真实细节密度 □ 权衡表达 □ 复盘能力

## 第二轮：行为 / 文化面（45 分钟，含英文环节）

### 开场与动机（10 分钟）

1. 为什么想来早期 startup 做 founding engineer？预期前六个月是什么样？
2. 讲一个在没人告诉你该怎么做时，主动把事情做成的经历。（STAR）
3. 你的项目曾经严重偏离预期（延期/方向错）吗？当时怎么处理的？

**评分**：□ 动机真实 □ STAR 完整（尤其 Result 有量化） □ 不回避失败细节

### Ownership 深挖（15 分钟）

4. 讲一件不在你职责范围内、但你 owns 到底的事。
5. 你和硬件/固件团队对问题归属有过分歧吗？最后怎么解决的？
6. 这个岗位前期可能没人 review 你的代码、没人给你方向，怎么保证自己不跑偏？

**评分**：□ 主动性证据 □ 用证据而非立场解决冲突 □ 自我管理机制具体

### 英文环节（12 分钟，抽 2–3 题）

7. (English) Tell me about a project you built from scratch — what was the hardest technical decision?
8. (English) How would you collaborate with our Silicon Valley team across the time zone?
9. (English) 用英文简述你的 OTA 方案（3 分钟）。

**评分**：□ 流畅度优先于发音 □ 技术术语准确 □ 能应对追问不卡死。素材见 [07_英文与跨团队沟通.md](./07_英文与跨团队沟通.md)。

### 收尾（8 分钟）

10. 你最近一年学到的最重要的技术教训？
11. 你日常怎么用 AI 工具？举一个具体改变了你工作方式的例子。
12. 你对我们产品有什么了解？有什么问题想问我们？

**评分**：□ 成长型信号 □ AI 用法有细节 □ 提问质量（准备过的 vs 临场编的）

## 补充轮：按真实轮次查漏

如果某轮明显薄弱，用下面的简化轮次单加练：

- **电话筛**：60–90 秒介绍 / 为什么 founding / 英文协作举例 / 没做过的加分项怎么补。通过线：匹配度清楚、不装、有旗舰故事标题。
- **技术面加练**（抽 6 题必含 BLE）：并发与 GCD / ARC 内存 / 后台恢复状态不一致 / BLE 完整流程 / 扫描不到排查 / 断连恢复幂等 / 启动优化。通过线：能画状态机，能讲 Ready ≠ `didConnect`。
- **加分项渗透**（至少 4 题）：功耗旋钮与 SLA / OTA commit 点 / 离线不丢不乱序 / 传感器或音频带宽测算 / 协议为什么不套 C struct / EVT–PVT 各冻什么。通过线：能画 [05_白板图解.md](./05_白板图解.md) 白板 5–8，说清 iOS 边界 vs 固件边界，不会的项有缺口话术。
